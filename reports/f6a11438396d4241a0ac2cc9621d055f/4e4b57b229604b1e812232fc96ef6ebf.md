## HP3: valuable method, not yet a trustworthy reusable gate

### What it actually contains

The branch has three branch-only commits: `6746a26` adds the checker and probe (573 and 1,190 lines), `7bbb3dc` adds byte-built hex fixtures and a decoded-byte SHA-256 manifest, and `6abaf56` adds the report. Its main merge base is `136d72c5a94e1c0d1878f99c461a555a91b7c3f6`.

The approach is sound enough to preserve:

- Matrix A runs the workload twice per revision and compares canonical operation/argument/result transcripts.
- Matrix B writes nine file kinds with each revision, reads them with both, appends with both, then rereads. It compares selected bytes after masking lineage/header CRC and excludes encrypted byte equality.
- Matrix C independently constructs flagged files and directory manifests, including runtime encrypted variants, and tests explicit refusal rather than counting a process crash as a refusal.
- Each revision is extracted by exact commit with `git archive`; the shared probe is copied into that extraction and built against its own lockfile with `--locked --offline`, with a separate target directory.

Evidence: `mahpate-hp3-cross-version-check:scripts/cross_version_check.py:L154-L157,L182-L229,L303-L317,L351-L389,L397-L458`; `mahpate-hp3-cross-version-check:scripts/cross_version_probe.rs:L1130-L1152`.

The historical report records Windows-only testing against v0.6.1 (`fb46702f6c14a6a2d9de750858cf1c14503fc563`) and candidate `7bbb3dc`, not today's main: 273 versus 288 workload operations, 81 identical Matrix B checks, and 26 Matrix C inputs. It records 16 directory differences as justified and 16 output-stream mutants killed. The mutation wrapper was not committed. These are useful historical observations, but the mutation campaign exercised a transcript wrapper, not sixteen engine mutations.

Evidence: `mahpate-hp3-cross-version-check:pool-briefs/reports/hp3-cross-version-check.md:L3-L10,L21-L45,L59-L87,L108-L124`.

### Reproduced acceptance weaknesses

These are harness correctness limits, not findings about the engine:

| Limit | Evidence and actual observation | Required salvage boundary |
|---|---|---|
| Identical failure can masquerade as agreement | The in-memory checker returned no A differences for two empty transcripts and for two identical `exit 1` process-failure transcripts. `transcript` records a crash as a row, but A only compares equality/determinism. | Reject any crash before comparison; require nonempty, complete, expected operation coverage and valid row shapes. |
| B accepts equal empty or crashing dumps | `judge('empty', [[], []], False)` returned `identical`, as did two `crash` dumps. Its equality check precedes failure inspection. | Reject malformed/empty output and any process failure independently of parity. Validate expected produce, dump and append inventories. |
| Directory exception is too broad | A reference `dir.open = err:Io` versus candidate `dir.open = err:Corrupt` was classified `justified`. All paired `dir.*` differences are exempt once the reference refuses the directory. | Require candidate success and named expected outcomes for directory operations; allowlist the precise reference limitation, not the whole operation family. |
| B excuses any old-reader refusal after candidate involvement | A reference `open err:Corrupt` versus candidate `open ok` was classified `justified` when `candidate_touched=True`. | Require a documented, file-specific unsupported capability/error. Corruption or arbitrary I/O errors must not be blanket exceptions. |

Source: `mahpate-hp3-cross-version-check:scripts/cross_version_check.py:L232-L236,L255-L269,L281-L317,L329-L341,L360-L384`. All four classes were reproduced with synthetic checker inputs under ordinary Python and `python -O`; no engine was involved.

Additional static limitations:

- The default candidate is still `136d72c5...`, even though the branch report tested `7bbb3dc`. Running the proposed CI command without `--candidate` does not test the current checkout. The result JSON does record resolved SHAs, which is worth retaining. Evidence: checker `L49-L50,L488-L514,L550-L554`; report `L47-L53`.
- Matrix C parses whichever entry-point rows arrive without checking the complete expected entry-point set. Its refusal/acceptance predicates quantify over the supplied dictionary. Require exact entry-point inventories appropriate to files versus directories before judging. Evidence: checker `L422-L445`; probe `L1130-L1152`. This observation is static, not a newly executed Matrix C engine test.
- `--reference` is configurable, but expectations still encode `KNOWN_V061` and v0.6.1-specific explanations. It is not a generic arbitrary-release checker without reference-specific expectations. Evidence: checker `L49-L65,L428-L456,L551`.
- Byte differences in B are informational, not automatically findings; encrypted byte equality is excluded. Preserve that distinction and explicitly define when semantic equality is enough rather than implying universal byte equality. Evidence: checker `L344-L348`.

### What is genuinely missing on main

Main already has real compatibility infrastructure: `scripts/graph_compat_check.py:L1-L24` exercises historical graph-marker behavior with isolated revisions and optional bindings; `tests/compatibility.rs:L21-L74` covers legacy fixtures, reopen, backup/restore and format preservation. HP3 should not replace or duplicate those.

The distinct potential addition is a shared-old-API **cross-revision workload plus bidirectional write/read/append matrix**, beyond the graph-marker-specific runner and single-version golden tests examined here. This conclusion rests on those tools' implemented scope and HP3's concrete matrix code, not just its unmerged status or absent filename. The bounded inspection does not prove that no individual test elsewhere overlaps any HP3 operation.

**Effort:** a bounded tooling project, not a one-line cherry-pick: harden the comparison layer and commit its negative/self-tests, preserve fixture/probe provenance, compile the shared probe against the explicitly chosen revisions, then reproduce the matrices on Windows and Linux. The existing two-file, 1,763-line tool gives the grounded scope; there is no reliable elapsed-time estimate from this assessment. The old 61-second cold run is not a current-host estimate. No new CI wiring should precede that qualification.
