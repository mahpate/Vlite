# HA gateway MVP security and correctness review

## Verdict

**INCOMPLETE runtime validation; do not approve policy mutation safety.** Static review identified one HIGH-severity lost-update flaw that can restore revoked credentials or suspended tenants. The gateway/envelope implementation otherwise has substantial fail-closed defenses, but this review does not certify the Rust implementation or the requested end-to-end acceptance tests.

- Reviewed checkout/base: **e995c536573d11388f676f2c3724118992472753** (`e995c536`), branch supplied as `mahpate-ha-pool-base`.
- Comparison baseline: `d9c3d64da1dd54a8f2036f473b98143bd7b98690` (`origin/main` supplied by the assignment).
- Scope: opt-in gateway/trusted-backend changes, associated control state, envelopes, classifier, rate sharing, CLI wiring, tests and PRD. This is not a review of every pre-existing server subsystem.
- Evidence below is repository-relative `file:line` evidence at the reviewed base. Unless expressly marked executed, observations are **static inspection**, not passing tests.
- No live deployments, Azure endpoints or emulator endpoints were contacted. No source, configuration, lockfile, tests or other reports were changed.

### Finding 1: why CAS does not preserve the security mutation

An evidence-backed interleaving, **not an executed runtime reproduction**, is:

1. Commands P and Q load the same admin directory while credentials X and Y are active (`src/server/gateway_mode.rs:965-966`). Each command now owns its own in-memory `Store`; loading constructs that store from the file (`src/server/credentials.rs:651-687`).
2. P revokes X; Q revokes Y using its previously loaded copy. Revocation clones its local entries and changes only the requested entry (`src/server/credentials.rs:1105-1125`).
3. P successfully publishes policy containing X revoked and Y active. Q then reads that shared snapshot, but `current.reimport(...)` discards its credential and tenant policy in favor of Q's copy (`src/server/control_state.rs:172-185,204-209`).
4. Q publishes X active and Y revoked under a **higher generation**. This can happen without an ETag conflict if Q's read follows P's write; a conflict also does not help, because retry repeats the same stale reimport (`src/server/control_state.rs:340-350`).
5. Authentication uses the resulting shared credential policy (`src/server/control_state.rs:227-238`). A minimum-generation check cannot distinguish this policy rollback from a legitimate new policy because the generation increased.

Concurrent commands using **the same directory** are sufficient; different or stale admin-directory copies are not a prerequisite. Suspending one tenant concurrently with another policy/directory update has the same whole-policy replacement problem (`src/server/gateway_mode.rs:980-992`; `src/server/tenants.rs:459-485`).

Impact: an acknowledged revocation/suspension can be undone indefinitely, rather than merely remain effective after a bounded S_ctl convergence interval. Triggering the race requires an authorized administrative update; an attacker possessing the restored credential benefits after the race. This violates the safe concurrent-mutation design and bounded revocation intent in `docs/projects/feature-aca-ha/feature-aca-ha.prd.md:198-213` and RD-004 (`:483`). Severity is HIGH, not CRITICAL, because it requires concurrent/stale privileged administration rather than a standalone unauthenticated exploit.

## Items checked and found correct by static inspection

These are positive code observations, **not a blanket assertion that the runtime passed validation**.

### Authentication, authorization and principal envelopes

- **RD-009 credential restriction:** `tenant_bearer` requires the parsed bearer value to begin with `vlk_` (`src/server/gateway_mode.rs:578-580`). The shared bearer parser refuses multiple Authorization values (`src/server.rs:1140-1151`). Gateway forwarding authenticates through the snapshot, requires a tenant and applies existing scoped authorization before minting the envelope (`src/server/gateway_mode.rs:387-417`). Public login/dashboard routes are refused rather than forwarded (`:383-386`); local health/readiness are intentional probe exceptions (`:348-364`). RD-009 is at `docs/projects/feature-aca-ha/feature-aca-ha.prd.md:488`.
- **Every serialized authority field is signed:** `Claims` contains audience, issue/expiry time, policy generation and the complete principal, and rejects unknown claims (`src/server/principal_envelope.rs:35-44`). Signing covers `vle1.<kid>.<base64url(serialized Claims)>` (`:210-225`); verification checks that exact signed prefix with Ed25519 before deserializing claims (`:388-418`). There is no unsigned principal field used as an authority override.
- **Fail-closed signature/key selection:** verification selects the exact configured `kid`, refuses unknown identities, and does not fall back to another key (`src/server/principal_envelope.rs:403-415`). The bounded startup bundle permits one or two distinct key identities and validates encoding (`:257-284`); active signing material is checked when configuration loads (`src/server/gateway_mode.rs:137-156`). Old/new overlap is supported, not automatic live key reload.
- **Expiry, skew and lifetime:** future `iat`, expired `exp`, nonpositive/oversized lifetime and expired underlying credentials are rejected. Saturating additions avoid overflow in skew comparisons; subtraction follows the positive-lifetime guard (`src/server/principal_envelope.rs:419-440`). Tests explicitly cover exact skew boundaries and underlying credential expiry (`:780-825`), but were not executed here.
- **Minimum generation A:** the verifier's minimum is the maximum of its configured floor and an atomic monotonic floor; successful envelopes can raise but not lower it (`src/server/principal_envelope.rs:360-369,437-442`). Trusted-backend startup performs a confirmed read and raises the floor, then the poll callback independently raises it (`src/server/gateway_trust.rs:142-166`). This implements RD-004's stale-envelope rejection but does not cure Finding 1's higher-generation policy rollback.
- **Backend tenant/audience/lineage checks:** the backend accepts the signed tenant only when the current directory routes it to this audience and database lineage, then independently admits the tenant (`src/server/gateway_trust.rs:225-254`). The verifier checks the signed audience (`src/server/principal_envelope.rs:419-424`).
- **Missing, malformed or duplicate principal headers fail closed:** trusted authentication returns no role when the header is absent, rejects duplicate/non-text values and verifies the envelope before returning a scoped role (`src/server/gateway_trust.rs:225-254`). Backend tests assert 401 for missing/malformed/expired/wrong-signature/unknown-key/wrong-audience/stale-generation envelopes and ignore a neighboring bearer token as an elevation mechanism (`src/server/gateway_trust_tests.rs:174-254`).
- **Control-store failures do not extend stale authorization:** `Poller::poll` reads successfully before updating its cache; failed reads leave the previous age untouched, and generation regression is refused (`src/server/control_state.rs:388-411`). Missing snapshots, age beyond S_ctl and backward monotonic observations fail closed with 503 (`:414-430`). Poll errors log a bounded error code rather than the raw store request (`:538-548`). A temporary store error intentionally permits the existing confirmed snapshot only within S_ctl; this is bounded-cache behavior, not immediate denial on every read failure.
- **Replay boundary is explicit:** the implementation is a short-lived bearer principal envelope, not a single-use request signature. There is no nonce/replay cache or method/path/body binding in `Claims` or `verify_with` (`src/server/principal_envelope.rs:35-44,382-442`). A captured valid envelope is reusable for authorized operations at its audience until expiry, credential expiry or the generation floor rejects it. PRD section 3.6 specifies signed principal/expiry/A, not nonce-based replay rejection (`docs/projects/feature-aca-ha/feature-aca-ha.prd.md:215-225`), so replay within that boundary is not reported as an independent requirement violation.

### Default safety and direct backend access

- **Standalone remains opt-in-safe:** `Service` initializes with `trust: None` (`src/server.rs:347`); absence of `--serve-mode` selects standalone (`src/bin/vlite-server.rs:338`), and absence of a trust file leaves trusted mode disabled (`:531-533`). Authentication dispatches to trusted logic only when explicitly configured, otherwise preserving the existing admin/read-only/scoped-credential path (`src/server.rs:1153-1183`).
- **A principal header alone is not standalone authority:** standalone authentication does not inspect it (`src/server.rs:1153-1183`). A source-level regression test covers the default mode and principal-header irrelevance (`src/server/gateway_trust_tests.rs:152-168`). This test was inspected, not run; it is not proof of every pre-existing standalone behavior.
- **Trusted-mode configuration rejects conflicting entry paths:** `--insecure-local`, gRPC binding, reader mode, `VLITE_ADMIN_DIR` and memory-only durability are refused in combination with the trust file before opening/creating the database (`src/bin/vlite-server.rs:531-550`). Trusted data authentication dispatches before standalone bearer handling (`src/server.rs:1153-1156`).
- **Untrusted caller headers are replaced, not trusted:** requests strip Authorization, cookies, caller principal, forwarding/proxy headers, Host, framing and Connection-nominated headers (`src/server/gateway_mode.rs:634-685`). Only after stripping does the gateway insert its freshly signed principal (`:452-457`). Tests cover forged caller authority/header stripping (`:1014-1053`).
- Direct access to a **standalone** deployment retains standalone rules; direct access to an explicitly **gateway-trusted** backend intentionally requires a valid envelope. These are separate configurations, not an assertion that all direct requests should remain accepted. Local probe access is not data authority.

### Proxying and resource bounds

- **RD-010 application behavior:** the gateway makes one `.send()` attempt and contains no application retry loop (`src/server/gateway_mode.rs:458-478`). Redirect following and environment proxies are disabled (`:175-182`). A non-connect failure or response-head timeout for a write maps to `write_outcome_unknown`; the error tells callers to read before retrying (`:545-567`; `src/server/gateway.rs:509-514`). A post-header failure instead truncates the body because an HTTP status has already been sent (`src/server/gateway_mode.rs:504-532`).
- **Upstream timeouts are streaming-compatible:** connect has a configured timeout, sending/waiting for response headers is wrapped in a timeout, and each next upstream response chunk has an idle timeout (`src/server/gateway_mode.rs:173-182,458-478,504-532`). There is deliberately no whole-response timeout that would kill healthy long streams. This is not a claim that inbound body receipt or downstream backpressure has a deadline.
- **Request size is bounded:** declared oversized bodies are rejected and actual body collection uses `to_bytes` with the configured limit (`src/server/gateway_mode.rs:428-451`). Configuration requires the limit to be within `MAX_JSON_BYTES`, currently 8 MiB (`:119-123`; `src/server.rs:89`). Request buffering is bounded per request, not zero-copy.
- **Responses are streamed, not collected as a complete body:** the response path uses a four-message channel and a pump retaining the in-flight permit until stream completion (`src/server/gateway_mode.rs:480-532`). Backpressure prevents unbounded queue growth. This bounds queued chunks, not total streamed bytes or a formally fixed byte count per chunk; no aggregate response-length limit was found in that path.
- **Concurrency and rate-table capacity are bounded:** configuration limits `max_in_flight` and `max_buckets` (`src/server/gateway_mode.rs:53-55,124-131`); admission uses `try_acquire_owned` (`:365-372`); a full bucket table evicts only replenished buckets or rejects the new request (`:737-766`).
- **Hop-by-hop handling is bidirectional:** fixed and Connection-nominated headers are removed; Set-Cookie is removed from responses (`src/server/gateway_mode.rs:634-700`). Framing is regenerated rather than reusing the inbound request length.
- **Path/origin isolation:** dot segments, backslashes and encoded separators are refused; endpoint URLs cannot contain userinfo, path prefixes, query or fragment; the final path/query must survive normalization unchanged (`src/server/gateway_mode.rs:585-630`). The authenticated directory record supplies the upstream origin, not caller Host.
- **Gateway-generated error/log messages avoid raw transport internals:** upstream failures expose generic codes and operation names, not `reqwest` error strings, endpoint addresses or credentials (`src/server/gateway_mode.rs:512-531,545-575`). Responses originating from a backend otherwise pass through; no universal redaction guarantee is asserted for arbitrary backend bodies/headers.

### Rate sharing, overflow and secret handling

- **Conservative static share:** division by `max_replicas` uses exact u32-to-f64 inputs, checks the product with fused multiply-add, and steps down rather than rounding above the credential budget. Zero replicas and a share below one request/second are rejected (`src/server/gateway.rs:367-395`). Both refill and burst capacity use that share (`src/server/gateway_mode.rs:702-771`).
- **Deployment trade-off:** enforcement assumes the actual combined replica count stays within the configured maximum, including revision overlap. More replicas can exceed the aggregate edge allocation; fewer replicas under-serve it. The source documents that limitation (`src/server/gateway.rs:367-372`). It is not a globally coordinated rate limiter; ACA replica/revision settings were not verified.
- **Checked arithmetic:** generation increments and envelope-expiry addition use checked operations (`src/server/control_state.rs:340-346`; `src/server/gateway.rs:470-477`); skew calculations use saturating arithmetic (`src/server/principal_envelope.rs:425-435`).
- **Untrusted envelope parsing:** token size is checked before decoding; parts are destructured and validated; signature decoding and claim decoding return refusal errors rather than unconditional unwraps (`src/server/principal_envelope.rs:388-418`). The reviewed production gateway paths use poison recovery or propagated errors rather than unconditional lock unwraps; many `unwrap`/`expect` occurrences are test assertions, not client-controlled production panic paths. This is not a whole-repository panic audit.
- **Secret boundaries:** envelopes contain principal data rather than signing seeds (`src/server/principal_envelope.rs:35-44,210-225`). Key-loading buffers are wiped after decoding/construction (`src/server/gateway_mode.rs:143-156`); startup metadata contains identities/generations rather than key bytes (`src/server/gateway_trust.rs:167-175`). Poll/proxy logging uses codes, not credentials (`src/server/control_state.rs:538-548`; `src/server/gateway_mode.rs:512-531,570-575`). No secret in the reviewed normal logging paths was identified; runtime tracing was not exercised.

## UNVERIFIED items and recommendations

- **UNVERIFIED runtime/build:** compile and run the targeted Rust modules once dependencies are available in an isolated cache. Include `gateway`, `gateway_trust`, `principal_envelope` and `control_state` filters, then the local-emulator integration scenario with isolated fixtures. Do not equate historical PRD/rehearsal claims with checks executed in this review.
- **UNVERIFIED finding reproduction:** Finding 1 follows directly from the actual mutation/reimport/CAS code, but was not reproduced against a running binary. Add a deterministic test in the owning implementation task: two independent stores load before either mutation, publish disjoint revocations in sequence, and verify both stay revoked. Also test CAS conflict retry and a directory-only update racing revocation.
- **UNVERIFIED timing qualification:** S_ctl, polling, skew/lifetime, scale maximum and drain values require measurement. They are required configuration inputs, not measured safe defaults (`src/server/gateway_mode.rs:58-80,97-116`). OD-005/006 remain open (`docs/projects/feature-aca-ha/feature-aca-ha.prd.md:499-500`).
- **UNVERIFIED platform trust:** TLS termination, private ingress, absence of environment-level backend routes, managed-identity permissions, actual secret delivery and rotation under overlapping revisions. Section 3.6 requires more than internal network placement (`docs/projects/feature-aca-ha/feature-aca-ha.prd.md:215-225`). OD-009 explicitly leaves platform verification open (`:503`). No Azure checks were performed, as required by the assignment.
- **Replay trade-off:** retain the short-lived bearer design only with a documented capture/reuse threat model, protected backend transport and non-logging of principal headers. If single-request replay resistance is required, request binding plus backend nonce/deduplication changes are needed; a signed expiration alone does not provide it.
- **Resource-bound trade-off:** the streaming implementation has no total response-byte cap and no explicit gateway timeout around inbound body collection or downstream channel backpressure (`src/server/gateway_mode.rs:449-451,504-532`). These are observable design limits, not independently reproduced vulnerabilities here. Decide whether downstream idle deadlines, inbound upload deadlines and per-route response caps are needed without breaking legitimate long-lived streams.
- **Transport-library scope:** static review established no application retry loop, not an independent audit of every automatic retry behavior in transitive HTTP libraries. The pinned reqwest dependency is 0.12.28 (`Cargo.lock:2367-2369`). The relay integration is useful empirical coverage but was not executed in this review.
- **Error disclosure scope:** generic gateway errors are constrained, but arbitrary trusted-backend response bodies and non-hop-by-hop headers pass through (`src/server/gateway_mode.rs:480-500,689-700`). No universal backend-error redaction or deployed response capture was verified.
- **Deferred HA is not silently treated as delivered:** reader routing and epoch response fencing are explicitly not wired in this MVP (`src/server/gateway.rs:398-409,444-458`). They remain prerequisites for broader writer failover guarantees, not additional evidence-backed gateway-MVP vulnerabilities.

Recommended disposition: fix Finding 1 before relying on shared-policy revocation, then close the explicitly listed runtime and timing gaps. Standalone-default safety and the inspected envelope defenses do not compensate for an administrator update that republishes older authority as a newer generation.
