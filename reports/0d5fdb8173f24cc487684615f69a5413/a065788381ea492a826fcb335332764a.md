# VLite EPIC-002 security/correctness review

## Verdict: NOT READY; validation INCOMPLETE

The new account import correctly disables source identities and does not restore credential verifiers. However, EPIC-002 does not yet satisfy its certification, isolation, binding, and bootstrap requirements. Six adversarial assertions failed in an isolated source copy, demonstrating accepted unknown security state, accepted secret-bearing credential fields, missing cross-store validation, insufficient destination isolation, failed deferred bootstrap, and input-bearing parser errors. These are implementation/certification findings, not a claim of a currently exploitable remote restore endpoint.

The requested `tests/recovery_bundle*.rs` integration target does not exist. There is no production caller of recovery-bundle capture/import in this revision, so a complete live capture-to-rekeyed-database drill, private-bootstrap flow, and AC-003/backup-only AC-004 matrix could not be exercised. Report delivery and passing component tests do not establish those acceptance criteria.

### Why RB-01 is not fixed by two equal captures

`stable` detects a persistent change to the captured projection, as its existing test shows. It cannot detect an A-to-B-to-A transition, changes outside the projection, or a partial cross-store transition that remains in place throughout both reads. Auth references retain only configured booleans; webhook capture retains only subscription count. Equal projections are therefore not evidence of complete admin persistence or an exact policy revision at the DB checkpoint.

Tenant deletion illustrates why the design explicitly requires a barrier: existing `src/server/tenants.rs:314-365` removes accounts before committing the tenant tombstone, and errors can leave an intermediate state. The new helper neither participates in that transaction nor verifies its cross-store invariants. The fixture establishes the missing relationship check without claiming a particular concurrent production schedule was executed.

## Uncertainties, blocked checks and design trade-offs

- **Required integration validation is unavailable**, not passed: no recovery-bundle integration binary, live capture/import wrapper, policy hook/barrier contract or complete private-bootstrap/activation flow exists in the reviewed revision.
- No concurrency schedule, crash/power-loss test, Linux permission/symlink test, full suite, formatter/linter, external Blob service, cloud identity or production environment validation was executed. External cloud testing was outside the no-network permission; local unit/fixture checks needed no network. No production service was started.
- Unknown post-backup revocations cannot be inferred without current authority. This is why the rekey-only path must keep imported principals disabled and require reviewed grants; the current import's refusal to install old credential verifiers is the correct trade-off. Preserving historical tenant flags is not proof of current tenant policy.
- Preserving usernames/roles/graph grants as disabled inventory is useful, but they must never become implicit regrant authority. Credential collection IDs are omitted from the public inventory, so reviewers should not assume historical collection names prove exact resource continuity.
- Fresh TLS/provider/DB-key references need explicit supported-profile and secret-custody decisions. Do not add plaintext values or portable source paths to fill the missing inventory.
- Parent-directory alias protection and crash-atomic directory activation belong in an owning restore coordinator, not ad hoc path checks. ITEM-007 may own that orchestration, but EPIC-002 cannot independently claim AC-003/004 completion without the contract and evidence.

## Recommendation

Keep the feature unqualified/unready. Preserve the existing disabled-account/no-old-credential approach, replace the arbitrary JSON credential boundary, introduce the certified persistence/identity contract and fail-closed inventory, and require exclusive isolated staging plus a completed fresh bootstrap before activation. Run the new negative regressions and complete the missing AC-003/backup-only AC-004 drill before declaring EPIC-002 or minimum backup usability complete.
