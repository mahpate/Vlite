## Scope

Wire the existing fence into the request path and the binary's stop path so
that, when a service carries an enabled fence, no mutation is admitted,
committed or acknowledged without the OD-002 checks, and a fenced writer
stops. No new dependencies. No new REST route, CLI flag or config file.
`site/api.html` needs no rows (`tests/api_reference.py` excludes Rust under
`src/server` and `src/bin`).

The only way to enable the fence in this task is a new crate-internal
builder used by tests; the binary keeps building `WriterFence::disabled()`.
With the fence disabled (every existing deployment), behaviour, headers,
JSON fields, status codes, store reads and startup must be byte-for-byte
unchanged (AC-010). `--authority-file`, writer startup/claim/recovery,
background timers (archive scheduler, compaction, memory replay, webhooks),
gateway-side epoch checks and gRPC serving with an enabled fence are later
items.

Out of scope (do not touch): `authority.rs`, `cloud_backup*.rs`,
`cloud_recovery.rs`, `archive.rs`, `failover.rs`, `gateway.rs`,
`gateway_mode.rs`, `gateway_trust*.rs`, `reader_apply*`, `backup_policy.rs`,
`ops.rs`, `memory*`, `guard.rs`, every doc, `site/`, and everything under
`deploy/`.

## Required behaviour

1. `Service` gains `writer_fence: WriterFence`, initialised to
   `WriterFence::disabled()` in `new`, and copied (same `Arc`) by
   `successor()` so compaction generations share one fence.
2. `pub(super) fn with_writer_fence(self, fence: WriterFence) -> std::io::Result<Self>`
   (crate-internal; `cfg_attr(not(test), allow(dead_code))` if unused
   outside tests). Writer mode only: refuse a standalone or reader service
   with `writer authority needs --serve-mode writer`. Call it after
   `with_serve_mode`.
3. Admission (in `observe`, after `serve_mode::admit`, before the handler):
   - fence enabled and the request is a mutation (`!read_request(..)`):
     `admit_mutation()`; refusal is 503 `writer_authority_unavailable`
     with no handler run.
   - fence state `Fenced`, `Draining` or `Stopped`: refuse data reads too
     (503 `writer_authority_unavailable`), except `/ready`, `/health`,
     `/metrics` and `/v1/admin/serve-status`, which keep their own logic.
   - Uses only local state: no store read on admission.
4. Commit gate: every database closure run by `run` and `run_mutation`
   (group commit and direct) calls `verify_before_commit()` inside the
   blocking worker immediately before `operation(db)`. A refusal returns 503
   `writer_authority_unavailable` and the operation is not run. Validation
   errors from `operation` are preserved unchanged.
5. Ack gate: when `operation` returned `Ok`, call `verify_before_ack()` in a
   blocking context (inside the `run` worker after `operation`; after
   `group.submit(..).await` in `run_mutation` via `spawn_blocking`). A
   failure replaces the success with 502 `write_outcome_unknown`. No rollback
   is attempted. On success, record a request-scoped **receipt** (a
   `tokio::task_local!` in `writer_fence.rs`, set from the async side of
   `run`/`run_mutation`, scoped per request in `observe` the same way
   `guard::track_hidden` scopes `HIDDEN`).
6. Response barrier (in `observe`, after the handler, fence enabled,
   request is a mutation, response status is 2xx):
   - fence no longer `ready()` (latched or unavailable) → replace the
     response with 502 `write_outcome_unknown`;
   - no receipt (a route that did not go through `run`/`run_mutation`) →
     one fresh `verify_before_ack()` in `spawn_blocking`; failure → 502
     `write_outcome_unknown`;
   - a receipt from this request and a still-ready fence → no second check.
   Never send a success after the fenced latch.
7. `X-VLite-Epoch: <claim.epoch>` (decimal) on every response, success and
   error, when the fence is enabled; absent when disabled. Add
   `WriterFence::epoch() -> Option<u64>`. `serve-status` reports
   `"epoch": <claim.epoch>` when enabled and `null` when disabled.
8. `/ready`: when the fence is enabled and not `ready()`, return 503
   `writer_authority_unavailable` **before** the draining, reader, trust and
   database checks. Signal drain (`Service::begin_drain`/`draining`) keeps
   its current behaviour and cannot re-open a fenced gate.
9. Stop path: add `pub(super)`/`pub` accessors as needed so `vlite-server`'s
   `serve` selects on the fence's `stop_signal()` (a never-resolving future
   when `None`) as well as OS signals. On an authority stop, `serve` calls
   `service.begin_drain()`, transitions the fence to `Draining`, closes
   listeners via the existing `stop_tx`, and after shutdown calls
   `stopped()`; the process exits with `exit_code()` (1) instead of success.
   With the fence disabled `serve` behaves exactly as today.
10. Events come only from `writer_fence.rs` (`writer_fenced`,
    `writer_drain_timeout`, `writer_stopped`). Never log tokens, request
    bodies, keys or store bodies.
11. gRPC: `run`/`run_mutation` gates apply to gRPC callers automatically.
    Do not change `grpc.rs`. Document on `with_writer_fence` that gRPC has no
    response barrier yet and must be refused by the future authority startup.
12. In the commit message, list every direct `database.write()` outside
    `run` you find under `src/server/` (backup_policy, ops, memory, replay
    and so on) as follow-up inventory. Do not change them.

## Tests (test-first, `src/server/writer_fence_wiring_tests.rs`)

Fake `Memory`, deterministic, no sleeps. Build a writer service over
`Database::create_in_memory(1, crate::CreateOptions::default())` with
`with_serve_mode(ServeMode::Writer)` and a serving fence. Drive the router
with `oneshot`. At least:
`disabled_fence_adds_no_header_and_no_store_reads` (standalone and writer;
no `x-vlite-epoch`, `serve-status` epoch null, the fake store sees zero
operations),
`with_writer_fence_refuses_standalone_and_reader`,
`serving_fence_stamps_epoch_on_success_and_error`,
`mutation_reads_authority_before_commit_and_before_ack` (count GETs on the
fake store: exactly two per successful mutation through `run`),
`group_commit_mutation_is_gated` (same through `with_group_commit`),
`unavailable_before_commit_refuses_without_mutation` (503
`writer_authority_unavailable`; a follow-up read shows no change),
`unavailable_after_commit_answers_write_outcome_unknown` (502; skip the
first GET with `Memory::fault(.., skip = 1, ..)`),
`higher_epoch_fences_and_refuses_everything` (after `change()` bumps the
epoch: 409/503 on the next mutation, data reads 503, `/ready` 503
`writer_authority_unavailable`, `stop_signal()` fired, `exit_code() == Some(1)`),
`fenced_latch_suppresses_success_without_receipt` (a mutating route that
bypasses `run` gets 502 once the fence is latched),
`signal_drain_does_not_reopen_fenced_gate`,
`validation_errors_are_preserved` (a 4xx from a malformed mutation stays the
same code with the fence enabled),
`read_routes_do_not_read_authority_while_serving`.
