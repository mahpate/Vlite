Quickstart

Create a file. Store vectors. Search.

Start in-process with Python, Node.js or Rust, or run the API and dashboard yourself.

# Python 3.11+; run in a fresh directory
# python -m pip install vlite-embedded==0.4.1
from vlite_embedded import NativeLibrary

native = NativeLibrary()
with native.create("documents.vlite", dimensions=3) as db:
    db.put("10", [1, 0, 0])
    print(db.search([0.9, 0.1, 0], 5))
// npm install ./vlite-embedded-0.4.1-<platform>.tgz (release tarball)
import { NativeLibrary } from "@vlite/embedded";

const native = new NativeLibrary();
try {
  const db = await native.create("documents.vlite", 3);
  await db.put("10", [1, 0, 0]);
  console.log(await db.search([0.9, 0.1, 0], 5));
} finally {
  await native.close();
}
// Cargo.toml: vlite = { git = "https://github.com/mahpate/Vlite", tag = "v0.4.1" }
use vlite::Database;

fn main() -> vlite::Result<()> {
    let mut db = Database::create("vectors.vlite", 3)?;
    db.put(10, &[1.0, 0.0, 0.0], b"document A")?;
    let hits = db.search(&[0.9, 0.1, 0.0], 5)?;
    assert_eq!(hits[0].id, 10);
    db.close()
}

Know the boundaries

Data safety you can reason about

Corruption fails closed. Incomplete trailing writes require explicit repair; committed data is never silently discarded. Search indexes remain rebuildable from stored records.

VLite keeps the live dataset in memory and replays the log on open. A file supports one exclusive owner or multiple shared read-only owners. Size deployments for the full dataset. Optional indexes and maintenance can use sidecars. Filesystem and directory-entry durability have platform-specific limitations; process-crash tests are not physical power-loss qualification.
