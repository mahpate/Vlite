Peer Pool: run Copilot tasks across your machines

Hand a plan to a pool of your own Windows and Linux machines. Each one claims ready work, runs Copilot in an isolated Git checkout and returns a branch for you to review.

Open the portal ↗ See how it works

How it works

A shared to-do list for your machines

Machines pull work from the pool's VLite graph; nothing pushes work to them.

01

Plans become a graph

A plan's tasks and their dependencies are stored as graph nodes and edges. A task is ready once the tasks it depends on finish.

02

Peers claim ready tasks

A machine claims a task, sends heartbeats while it works and runs Copilot in its own checkout.

03

Code travels through Git

Results land on Git branches. The graph keeps only plans, tasks, dependencies, claims and heartbeats.

Features

Split the work. Route it. Stay in control.

Split and merge

A task can split into subtasks, or merge the results of the tasks it depends on.

The right machine

Require an operating system, a label such as gpu, a locally installed tool or a signed-in MCP server.

Code or research

Choose Change code, or Research & report: the task reads the repository and writes only its assigned report.

Private pools

Each pool is its own VLite graph. Its owner chooses who can view it and who can edit it.

Review before merge

Every task runs in an isolated Git checkout, and you review each result before anything is merged.

Credentials stay local

Each machine keeps its own Copilot and GitHub sign-ins and its own VLite key. Removing a machine revokes its key.

Get started

From sign-in to first task in three steps

Setup installs missing tools such as Git, GitHub CLI and Copilot CLI, then starts the peer at every sign-in.

Step 1

Create a pool

Sign in to the portal with your VLite username and password, then choose + New pool.

Step 2

Add a machine

Choose + Add a machine and paste the command into PowerShell. Its one-time code expires in 15 minutes and becomes the machine's own VLite key.

Step 3

Submit a plan

Create a plan in the portal or from a Copilot session, watch machines claim tasks, then review their branches.

Why VLite

A coordination store in one file

Peer Pool keeps its shared state in a VLite property graph.

Graph-shaped work

Plans, tasks, dependencies and claims map directly to nodes and typed edges.

Scoped access

Every machine signs in with its own key, and accounts can be limited to chosen graphs.

Durable by design

Pool state lives in a checksummed VLite file, so it survives restarts.
