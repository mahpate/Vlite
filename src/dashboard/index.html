    05 / PERFORMANCE
Index maintenance

    
Index readiness not checked

    
    
Builds default HNSW from committed records. Blocks the single owner; schedule outside latency-sensitive traffic. Reopen/overflow loses readiness.

    
    

    
HNSW configuration and background maintenance

      
m trades graph connectivity for memory; ef_construction trades build effort for quality. Use the same configuration for building and ready-only search. A seed makes builds reproducible for fixed data. Snapshot limits do not cap total process memory.

      
      
      
      
      
      
      
      
      
      

      
      
      
      
      
Policy is process-local and resets on restart. No automatic scheduler: a tick explicitly polls/publishes or starts a matching job. Observe does not publish. Cancellation is cooperative.

      

    

  

  

    DATA WORKFLOWS
Import, export and guided demo

    
Imports are limited to 100 records / 4 MiB, committed in atomic batches of 20. An entire import is not atomic. Existing IDs are replaced only after confirmation. No automatic retries.

    
  1. Connect to a test database.
  2. Preview a demo or import file.
  3. Confirm the writes, browse the records, then search.

    
    
    
Each record: id (string), vector (JSON array), optional payload_base64 and metadata (typed object). CSV headers: id,vector,payload_base64,metadata; quote JSON cells.

    
    

    
    
    
Page exports include full records (up to 100), fetched individually; not a point-in-time database backup. Use Operations for consistent backups.

    SERVER OPERATIONS
Health and administration

    
    
    

    

      
Connect to discover server administration features. These operations require an admin credential.

      
Credentials and audit

      
      
      
      
Change configured secret files offline first. Reload validates both before swapping. Admin token rotation requires reconnecting with the new token. Environment tokens require restart. Revocation is in-memory; empty its configured file to persist it.

      

      
      
Last 256 process-local requests only; not a durable compliance log. No credentials or record contents.

      

      
Backup and staged restore

      
      
      
      
      
      
      
Copies can block the owner and consume disk. Restore never replaces the live file. Selection takes effect only after an operator restarts the API with the same admin directory. Original data remains untouched; the selection persists. Do not remove the selected copy.
