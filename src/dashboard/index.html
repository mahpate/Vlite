Where do I get a token?

Use an existing token from the server owner. Paste only the token value, without the Bearer prefix.

  • Local Docker Compose: from the checkout that started this server, read .secrets/api-token (or the file set by VLITE_TOKEN_FILE). In PowerShell: Get-Content .secrets\api-token -Raw.
  • Windows devbox script: run .\scripts\devbox.ps1 -Token to copy that devbox's token to your clipboard.
  • Direct server: use the value configured through --token-file, VLITE_AUTH_TOKEN_FILE or VLITE_AUTH_TOKEN.
  • Shared server: ask your administrator for a scoped or read-only credential with the permissions you need.

Tokens are secrets. Do not share them in screenshots or logs. The dashboard cannot retrieve an administrator token for you.

Kept in memory only; reloading the page or signing out clears it. Use HTTPS beyond loopback.

Passwords, tokens and database contents are never stored in browser storage.

Add records in bulk (JSON)

    
Paste 1..10000 documents (up to 4 MiB). IDs must be quoted decimal u64 strings. Metadata uses VLite typed values; payload is standard base64 (payload or payload_base64). Existing IDs are replaced, including payload and metadata. TTL is cleared. Preview never writes.

    
    
    
    
    
    

    
Atomic batches of up to 20 documents; the complete write is not atomic. Earlier batches remain committed on failure. No automatic retries. Stopping a browser wait does not cancel server work.

    
Copy as code

    
Generates from the current form, not an earlier result; never executes. Set VLITE_BASE and VLITE_TOKEN locally. Review private vector / metadata content before sharing. Editor snippets are unconditional upserts, without If-Match.

    
    
    
    
    

  

  

    
Import, export and demo data

    
Imports are limited to 100 records / 4 MiB, committed in atomic batches of 20. An entire import is not atomic. Existing IDs are replaced only after confirmation. No automatic retries.

    
  1. Use a test database, not production.
  2. Preview a demo or import file.
  3. Confirm the writes, browse the records, then search.

    
    
    
Each record: id (string), vector (JSON array), optional payload_base64 and metadata (typed object). CSV headers: id,vector,payload_base64,metadata; quote JSON cells.

    
    

    
    
    
Page exports include full records (up to 100), fetched individually; not a point-in-time database backup. For consistent backups, use Administration > Backup & recovery.

  

  

    
Large file import (resumable)

    
Splits a JSON array, NDJSON/JSONL or CSV file into numbered chunks for the active collection. Each chunk commits atomically and exactly once; the whole import is not atomic. Committed chunks are kept if you stop, abort or close the page. Nothing is retried automatically: after an unknown outcome, Resume reads the durable job status first and replays only the last committed chunk to prove it is the same file.

Index maintenance

    
Index readiness not checked

    
    
Builds HNSW for the active collection from its committed records, with the metric, HNSW settings and (when supported) quantization selected in the Search playground. Blocks the single owner; schedule outside latency-sensitive traffic. Reopen/overflow loses readiness.

    
    

    
HNSW configuration and background maintenance

      
m trades graph connectivity for memory; ef_construction trades build effort for quality. Use the same configuration for building and ready-only search. A seed makes builds reproducible for fixed data. Snapshot limits do not cap total process memory.

      
      
      
      
      
      
      
      
      
      

      
      
Sign in to see which collection maintenance applies to.

      
      
      
      
Policy is process-local and resets on restart. A tick explicitly polls/publishes or starts a matching job for the active collection; the optional automatic scheduler (Administration > Server settings) is off by default. Observe does not publish. Cancellation is cooperative.

      

    

    
Index memory and measured quality (active collection)

      
Memory shows the byte counts of the listed index components only, not total process memory. Quality samples live records, compares the ready index against exact search for those queries and reports recall@k; it does not build or change the index.

Manage an existing tenant

Backups and restore

    
Sign in to check backup and restore support.

    
Recovery order: list or create a backup, select it below, verify or drill it, then stage a restored copy. Select that copy only when ready for an operator-managed restart.

    
    
    
    
    
    
    
Copies can block the owner and consume disk. Restore never replaces the live file. Selection takes effect only after an operator restarts the API with the same admin directory. Original data remains untouched; the selection persists. Do not remove the selected copy.

    
    
    
Verify checks the backup file's integrity (CRC) and records the result in its manifest. A drill restores it to a scratch file, opens and validates it, compares collections/counts with the manifest, runs a self-match query, then deletes the scratch file; the active database and restart selection are never touched.

    

  

  

    
Scheduled backups

    
Sign in to check backup scheduling support.

    
Off by default. Runtime changes are memory-only: the server's environment configuration applies again after restart. Retention is a separate opt-in: when enabled it deletes generated backups ranked beyond retain_last (and, if retain_days is set, older than it), but never the newest verified backup, restored copies, drill scratch files or the next-startup selection.

Export a replication log segment

    
Read-only export, not an automatic replica service. Requires this server's export route and database-wide read access: admin, read-only, or a scoped credential with read over all collections. Output contains database records; handle the download as sensitive data.

    
    
    
Export one segment, then download it. Successful exports advance the sequence field to the last returned sequence for the next request. Importing or applying a segment requires an external replica workflow; this dashboard never applies it to the live database.

    
    
    

  

  

    
Automatic index maintenance

    
Sign in to check automatic maintenance support.

    
Off by default and memory-only (resets to the environment configuration on restart). When enabled, each tick takes at most one action for one collection (round-robin), starts at most one background rebuild, skips and counts busy ticks, and never runs a synchronous build. Thresholds use the collection maintenance policy in Index plus the stale ratio and optional low-recall trigger here.

Reload TLS certificates

    
Sign in as a super admin. Reload requires a configured file-backed native TLS listener.

    
  1. An operator replaces the configured certificate, private key and optional client CA files on the server.
  2. Reload below validates all configured identities before swapping any of them.
  3. New TLS handshakes use the updated files; existing sessions keep their original configuration.

    
This action does not upload certificates, enable TLS on a plaintext listener, change listener settings or manage a reverse proxy. Invalid files leave the previous identities active.
