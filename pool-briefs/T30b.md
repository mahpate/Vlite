## Background

The owner approved measurements on separate temporary Azure apps that are
deleted afterwards. The harness already runs MEAS-007 in a fresh tagged
resource group (ACR, identity, Consumption environment, one Manual job per
CPU tier), collects framed gzip/base64 evidence from logs, and always
deletes the group. Add MEAS-002 (reader staleness under write load against
real Blob Storage). You make no Azure calls; everything is tested offline
with mocks. Never print or persist the subscription ID, account keys or
the identity client id in summaries.

## Required behaviour

Parameters and validation:
- `-Measurements` accepts exactly one of `MEAS-007` (unchanged default) or
  `MEAS-002`. Keep refusing `MEAS-001`, any other ID and any combination
  (e.g. `@('MEAS-007','MEAS-004')`, `@('MEAS-002','MEAS-007')`).
- New string parameters, plain decimal like `-Records`, MEAS-002 only:
  `-DurationSecs` (60..3600), `-Rate` (1..200), `-ArchiveIntervalSecs`
  (60..86400), `-StalenessBoundMs` (1000..3600000), `-ReaderPollMs`
  (100..60000 and below the effective bound), `-ObserveMs` (50..5000).
  Effective defaults are the driver's: 360, 20, 60, 300000, 1000, 100.
  Refuse them with MEAS-007, and refuse `-Records/-Delta/-Dimensions` with
  MEAS-002. Budget: `600 + duration + 2 * (2 * archive + 120)` must be at
  most 3600 (the replica timeout); refuse otherwise.
- Tiers: MEAS-002 defaults to a single 1 vCPU tier when `Tiers` was not
  passed (`$Options.ContainsKey('Tiers')`); explicit tiers keep the
  existing rules. MEAS-007 behaviour and defaults are unchanged.
- New derived name `StorageAccount = "vlitemeas$($Id)st"`, validated
  `\A[a-z0-9]{3,24}\z` and never a protected name.

Plan for MEAS-002 (MEAS-007 plan stays byte-for-byte identical): after
`GrantPull` insert, in this order,
1. `CreateStorage`: `storage account create --name <acct> --resource-group
   <rg> --location <loc> --sku Standard_LRS --kind StorageV2
   --allow-shared-key-access false --allow-blob-public-access false
   --min-tls-version TLS1_2 --https-only true`.
2. `CreateArchiveContainer` and `CreateCoordinationContainer`: ARM
   (control-plane) `storage container-rm create --storage-account <acct>
   --resource-group <rg> --name archive|coordination` (no data-plane auth).
3. `GrantBlob`: `role assignment create --assignee-object-id <principal-id>
   --assignee-principal-type ServicePrincipal --role "Storage Blob Data
   Contributor" --scope <storage account resource id with <subscription>>`.
Then `CreateEnvironment` and per tier `CreateJob, StartJob, PollExecution,
ReadLogs, QueryLogs`, then `DeleteGroup, WaitDeleted`. Every step keeps
`--subscription <subscription>`.

MEAS-002 job env (in addition to both provenance variables):
`VLITE_MEAS_KIND=MEAS-002`, `VLITE_MEAS002_TARGET_B64=<target-b64>`,
`VLITE_RESOURCE_HOST_NOTE=MEAS-002 temporary ACA job; requested CPU=..
memory=..`, and `VLITE_MEAS002_<OPTION>` (`DURATION_SECS`, `RATE`,
`ARCHIVE_INTERVAL_SECS`, `STALENESS_BOUND_MS`, `READER_POLL_MS`,
`OBSERVE_MS`) only for options the operator passed. Do not add
`VLITE_MEAS_KIND` to MEAS-007 jobs.
- Add `New-VLiteMeas002Target([hashtable]$Config, [string]$ClientId)`:
  compact JSON with exactly `account`, `container` (`archive`),
  `coordination_container` (`coordination`), `prefix` (`meas002/`),
  `auth` (`managed_identity`), `client_id`; base64 of its UTF-8 bytes
  resolves `<target-b64>` at execution. Base64 avoids quoting JSON through
  the Windows `az.cmd` wrapper.
- `CreateIdentity` must also capture `clientId` (fail if absent for
  MEAS-002). `-Plan` shows the placeholders, not values.

Results: the summary `measurement` is the selected ID; files are
`<ID>-c<tier>.json` (MEAS-007 names unchanged). Everything else (log
framing, retries, cleanup in `finally`, `-KeepOnFailure`, dirty-tree rules,
