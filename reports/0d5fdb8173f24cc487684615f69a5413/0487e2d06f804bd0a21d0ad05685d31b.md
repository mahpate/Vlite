## Construction and static inspection

The following are source-inspection conclusions, not additional emulator tests:

* `Target::validate` and `endpoint_url` constrain `EmulatorSharedKey` to loopback; the emulator URL must include `/devstoreaccount1`. `connect` delegates to `connect_with`, which validates the target, chooses the shared-key credential, disables proxies for loopback, and constructs the `Sets` data/meta stores. Separate containers share credentials, not blob namespaces. See [`cloud_backup.rs:109-244`](https://github.com/mahpate/Vlite/blob/f6a8efe3f6df983225a6f192fa10a240a893cdc2/src/server/cloud_backup.rs#L109-L244) and [`azure.rs:70-150`](https://github.com/mahpate/Vlite/blob/f6a8efe3f6df983225a6f192fa10a240a893cdc2/src/server/cloud_backup/azure.rs#L70-L150).
* `read_shared_key` accepts a nonempty decoded base64 key from a file of at most 1,024 bytes. `connect` itself takes the decoded bytes; it does **not** read `VLITE_CLOUD_BACKUP_SHARED_KEY_FILE`. The harness explicitly reads that environment variable, calls `read_shared_key`, and passes the result to `connect`. This qualifies those construction APIs, not any CLI/environment plumbing.
* Shared-key signing includes the account twice for path-style emulator requests: `/<account>/<account>/<container>/<blob>`. No signature mismatch was observed: create/get/head/range/list/delete and conditional requests reached their expected operations. Signing of encoded query parameters was exercised by prefix, block ID, and continuation-marker requests.
* Publication is staging record -> upload objects -> immutable manifest -> exact ETag CAS to published. Unknown/conflicting final writes are resolved through `observe`/`finish`; deletion moves through `delete_pending`, sweeps data manifest-first, retains the record as tombstoned, and writes the marker. Relevant code: [`cloud_backup.rs:832-968`](https://github.com/mahpate/Vlite/blob/f6a8efe3f6df983225a6f192fa10a240a893cdc2/src/server/cloud_backup.rs#L832-L968), [`1281-1418`](https://github.com/mahpate/Vlite/blob/f6a8efe3f6df983225a6f192fa10a240a893cdc2/src/server/cloud_backup.rs#L1281-L1418), [`1425-1550`](https://github.com/mahpate/Vlite/blob/f6a8efe3f6df983225a6f192fa10a240a893cdc2/src/server/cloud_backup.rs#L1425-L1550).
* The protocol harness adapts the real-database/recovery-bundle preparation and assertions from existing fake-store tests, rather than inventing a substitute protocol. A missing local upload file deliberately interrupts the actual publisher after staging and one real object upload. It then uses the real Azure stores for upload verification, manifest creation, `finish`, and `resolve_pending`. An uninterrupted public `publish` is tested separately.

## Findings and exact evidence

All source line numbers below refer to the unmodified requested base, not the four-line test-module insertion.

### F1 - High priority: every file larger than 4 MiB fails while staging its first block

**Observed:** 4,194,304 bytes succeeds; 4,194,305 bytes fails. A 17,825,804-byte file fails identically.

```text
put_file exactly 4194304 bytes PASS
put_file 4194305 bytes result=Err(Failed("the response has no ETag"))
large put_file bytes=17825804
sha256=925da6acef115ad84cc8ab5867ba11e8b64b065efa7323856291b35119ca7776
result=Err(Failed("the response has no ETag"))
direct Put Block:
  status=201
  x-ms-error-code: absent
  ETag: absent
  Content-Length: 0
  x-ms-request-id: a1d8b28c-f658-4d45-aa1a-f6abe3609baa
  Server: Azurite-Blob/3.37.0
```

**Root cause:** [`azure.rs:597-602`](https://github.com/mahpate/Vlite/blob/f6a8efe3f6df983225a6f192fa10a240a893cdc2/src/server/cloud_backup/azure.rs#L597-L602) uses `put_once` for `comp=block`. [`put_once:492-503`](https://github.com/mahpate/Vlite/blob/f6a8efe3f6df983225a6f192fa10a240a893cdc2/src/server/cloud_backup/azure.rs#L492-L503) requires `etag` on every successful response; [`etag:371-379`](https://github.com/mahpate/Vlite/blob/f6a8efe3f6df983225a6f192fa10a240a893cdc2/src/server/cloud_backup/azure.rs#L371-L379) returns `Failed` when missing. A staged block is not a committed blob revision and Put Block does not promise a blob ETag. Its successful 201 is incorrectly converted into a definite client failure, so block-list commit is never attempted.

**Impact:** production-sized database backup objects do not publish; this applies to the shared REST implementation, not just its emulator credential. The protocol safely leaves a staging set, but the operation is unusable for files above its 4 MiB branch threshold.

**Suggested fix:** use `send` plus success/failure status handling for staging blocks, returning `Result<(), StoreError>` and keeping its existing retry policy. Keep ETag mandatory for Put Blob and the final Put Block List, where it is needed for committed-object/CAS semantics. Do not invent an empty ETag or relax `etag` globally.

The candidate implementing precisely this distinction completed the 17,825,804-byte `put_file`, read all ranges back, matched the SHA-256 above and exact byte count, and rejected a second create-only commit with `Conflict`. The readback's final request used `x-ms-range: bytes=16777216-17825803`, `if-match: "0x21E3E8998A86340"`, and `x-ms-version: 2021-08-06`; Azurite normalized the requested length to 1,048,588 bytes. This is supplementary candidate validation, **not a baseline pass**.

Microsoft's [Put Block response contract](https://learn.microsoft.com/en-us/rest/api/storageservices/put-block#response) documents HTTP 201 and response headers without a blob ETag. This supports a real client bug rather than an Azurite-only ETag omission.

### F2 - Medium priority for ObjectStore: blob names are treated as URL text instead of literal names

**Observed:** space, Unicode (`unicode-\u96ea-\u00e9`), and plus names round-tripped across put/get/download/list/delete. A malformed percent sequence caused HTTP 500; a syntactically valid percent sequence silently addressed another name:

```text
input: percent%name
URL suffix: /percent%name
put: Err(Unknown("HTTP 500 "))
direct repeat: status=500, x-ms-error-code absent, ETag absent,
               Content-Length: 0, x-ms-request-id absent,
               Server: Azurite-Blob/3.37.0
Azurite log: ErrorName=URIError ErrorMessage=URI malformed

input: literal%2Bname
URL suffix: /literal%2Bname
put: HTTP success, ETag "0x2468513F36A85C0"
list returns: literal+name
expected literal name is absent
```

**Root cause:** [`azure.rs:452-461`](https://github.com/mahpate/Vlite/blob/f6a8efe3f6df983225a6f192fa10a240a893cdc2/src/server/cloud_backup/azure.rs#L452-L461) interpolates the blob name into a URL string before `Url::parse`. Existing `%HH` is treated as an escape rather than data; lone `%` is left to reach the emulator URI decoder. Literal names therefore cannot reliably be recovered from listings or distinguished from their decoded aliases.

This is **not evidence of an HMAC mismatch**: successful encoded-space/Unicode and percent-sequence requests authenticate, while the malformed-percent request fails in URI processing. The signed canonical resource uses the same inadequately escaped URL. No credentials or computed Authorization signature are needed to reproduce the fault.

**Impact boundary:** current set keys consist of validated ASCII prefixes, generated IDs, fixed filenames, and hex hashes, so this defect did not break the set-protocol scenarios. It still violates literal-name behavior of this store abstraction and the requested escaping qualification.

**Suggested fix:** parse the fixed container base first; append each blob-name segment with `Url::path_segments_mut().extend(name.split('/'))`, preserving hierarchy while encoding literal `%`. Leave query construction through `query_pairs_mut`. The tested candidate sent `/percent%25name` and `/literal%252Bname`; list returned the exact original names and all name operations passed.

Azure's [naming documentation](https://learn.microsoft.com/en-us/rest/api/storageservices/naming-and-referencing-containers--blobs--and-metadata#resource-names) explicitly requires reserved URL characters to be escaped.

## Wire semantics versus the in-memory fake

| Surface | Fake behavior | Observed Azurite behavior / risk hidden by the fake |
|---|---|---|
| ETag shape | Quoted decimal counter, e.g. `"1"` | Quoted opaque hexadecimal-looking string, e.g. `"0x20FA8146D294920"`; verbatim round-trip and CAS work. Do not parse or strip quotes. |
| Duplicate create | Direct `StoreError::Conflict` | HTTP **409**, `x-ms-error-code: BlobAlreadyExists`, request ID `1203afad-7ef6-46bb-bf0c-a2b4ee37de05`; production classification works. Do not assume every failed create is 412. |
| Stale If-Match | Direct `Conflict` | HTTP **412**, `ConditionNotMet`, request ID `1ed981ed-4592-4fb2-a8bf-3c9512ea0b55`; production classification works. |
| If-Match on missing blob | Direct `Conflict` | HTTP **412**, `ConditionNotMet`, request ID `ef46c6c9-f731-448f-a712-258dc2c38f52` in this emulator/version. Other service/version cases should remain classified by actual response, not this single observation. |
| Put file | Reads the complete local file and calls one fake `put` | Actual client changes to staged 8 MiB blocks above 4 MiB; Put Block has no ETag and exposed F1. Fake has neither uncommitted blocks nor a commit stage. |
| Download | One fake `get`, one write | HEAD for length/ETag, then multiple If-Match ranged GETs; independently passed for a 17 MiB+ blob. |
| Name identity | Literal map key | URL encoding/decoding and XML serialization intervene; F2 is invisible to the fake. |
| Listing | Complete BTreeMap prefix scan in lexical order | Observed lexical order matched for 5,001 ASCII names, but responses are paginated XML and marker is opaque. Real marker/query processing and XML parsing were exercised. Protocol also rebuilds a BTreeMap and reverses IDs for newest-first sets. |
| Missing resources | No container concept | Missing blob maps to NotFound; nonexistent container maps to Failed, as intended by special `ContainerNotFound` classification. The same 404 family cannot be treated indiscriminately. |
| Error information | Injected enum, no HTTP metadata | 409/412 error codes and request IDs are separate headers; malformed URI returned 500 with neither error-code nor request-ID. `classify` turns that into Unknown, not a conflict. |
| Unknown writes and races | Deterministic before/after faults and hooks | No live response-loss or concurrency interleaving was injected. Existing fake tests remain necessary, but do not substitute for transport fault tests. |

`classify` correctly preserves the distinction between `ContainerNotFound`, object NotFound, condition conflicts, and other permanent/transient outcomes in the exercised cases. This report does not propose changing that classification to conceal F1 or F2.

## Candidate implementation experiments (temporary copy only)

In `Container::url`, the tested replacement for interpolation/parsing was:

```rust
let mut url =
    Url::parse(&self.base).map_err(|_| StoreError::Failed("invalid object name".into()))?;
if !name.is_empty() {
    url.path_segments_mut()
        .map_err(|_| StoreError::Failed("invalid object name".into()))?
        .extend(name.split('/'));
}
```

Keep the existing `query_pairs_mut().extend_pairs(query)` and return. In the Put Block retry closure, replace the `put_once(...).map(|_| ())` expression with:

```rust
let response = self.send(Verb::PUT, url, Vec::new(), Some(chunk.clone()))?;
if response.status().is_success() {
    Ok(())
} else {
    Err(failure(&response))
}
```

This intentionally leaves final block-list commit conditional and ETag-requiring, retains retries only for block staging, and does not broaden credentials or endpoint access. The seven-test candidate result demonstrates these two changes address the reproduced failures; it is not evidence that repository source has been fixed.

## Gaps, uncertainties, and recommendations

1. **Do not approve baseline large-file backup.** Fix F1 first, commit the ignored harness through the normal development process, and rerun against the pinned emulator. Small-database protocol success does not establish large-backup usability.
2. **Baseline streaming read-back remains INCOMPLETE.** It was blocked by F1, not by missing tooling. Candidate coverage completed it, but cannot turn the unmodified implementation's failure into a pass.
3. This is not exhaustive size-limit qualification: tested exact read bounds, 4 MiB/4 MiB+1 branch boundary, 17 MiB+ range/block behavior, empty objects, and 5,001-name pagination. Did not allocate the 50,000-block ceiling (419,430,400,000 bytes), exceed the 1,000,000-name listing cap, exceed 10,000 active sets, or stress 32 MiB XML/1 MiB metadata limits. Those extreme limits were statically inspected only.
4. No live socket fault injection, throttling, server timeout, altered mid-download blob, interrupted block-list response, parallel pin/delete race, or competing janitor was induced. Those scenarios currently have fake-store coverage in varying degrees; add a bounded local response-loss proxy or instrumented store wrapper before claiming wire-level ambiguity/race qualification. Do not weaken existing fake tests.
5. Managed identity, real Azure RBAC, WORM/legal hold/immutability, soft delete/versioning, TLS/private endpoints, network proxies/redirects, Azure-specific throttling and regional consistency were not tested. No authorized real-Azure validation was attempted.
6. Loose mode can ignore unsupported emulator parameters/headers. Run a second strict-mode emulator job before expanding the qualification claim. The main README fetched during research advertised 3.38.0 while npm installed 3.37.0; this report's results are explicitly for the executable actually used.
7. Recommended CI split: retain fast fake tests for deterministic protocol interleavings; add a pinned, loopback-only ignored Azurite job with a temporary key file and explicit seven-test count; use a separately authorized real-Azure suite for identity/permissions/immutability. A report artifact or zero selected tests must not count as validation success.

No full-repository test suite, release build, Clippy, or formatter check was run: this was report-only work, with the targeted library tests covering both examined modules. All available required emulator commands ran; the baseline outcomes were failures, not permission or infrastructure skips.

```rust
use super::*;
use std::io::Write;

const INSTALL: &str = "0123456789abcdef";
const BASE: u64 = 1_700_000_000_000;
const HOUR: u64 = 3_600_000;
const ENDPOINT: &str = "http://127.0.0.1:10000/devstoreaccount1";

fn target(prefix: String, shared: bool) -> Target {
    Target {
        account: "devstoreaccount1".into(),
        container: "vlite-qual-data".into(),
        coordination_container: (!shared).then(|| "vlite-qual-coord".into()),
        prefix,
        endpoint: Some(ENDPOINT.into()),
        auth: AuthMode::EmulatorSharedKey,
        client_id: None,
    }
}

    let mut file = std::fs::File::create(&path).unwrap();
    let chunk: Vec<u8> = (0..1024 * 1024).map(|i| (i % 251) as u8).collect();
    for _ in 0..17 { file.write_all(&chunk).unwrap(); }
    file.write_all(b"tail-1234567").unwrap();
    file.sync_all().unwrap();
    drop(file);
    let (expected, length) = hash_file(&path).unwrap();
    let name = format!("{}large", sets.prefix);
    let result = sets.data.put_file(&name, &path, Cond::Create);
    println!("large put_file bytes={length} sha256={expected} result={result:?}");
    if result.is_err() {
        let c = raw("vlite-qual-data");
        let id = BASE64_STANDARD.encode("00000000");
        let response = c.send(
            Verb::PUT,
            c.url(&format!("{}block-diagnostic", sets.prefix), &[("comp", "block"), ("blockid", &id)]).unwrap(),
            Vec::new(),
            Some(b"diagnostic".to_vec()),
        ).unwrap();
        evidence("direct Put Block", &response);
    }
    result.unwrap();
    let mut writer = Hashing::new(std::io::sink());
    assert_eq!(sets.data.download(&name, &mut writer, length).unwrap(), length);
    let (_, actual, bytes) = writer.finish();
    assert_eq!((actual, bytes), (expected, length));
    assert!(matches!(sets.data.get(&name, length - 1), Err(StoreError::Failed(_))));
    assert!(matches!(sets.data.download(&name, &mut Vec::new(), length - 1), Err(StoreError::Failed(_))));
    assert_eq!(sets.data.put_file(&name, &path, Cond::Create), Err(StoreError::Conflict));
}

    let sets = setup("names", false);

    let mut failures = Vec::new();
    for tail in cases {
        let name = format!("{}{tail}", sets.prefix);
        let result = sets.data.put(&name, tail.as_bytes(), Cond::Create);
        println!("name={tail:?} url={:?} put={result:?}", c.url(&name, &[]).unwrap().as_str());
        match result {
            Ok(_) => {
                match sets.data.get(&name, 1024) {
                    Ok(blob) if blob.bytes == tail.as_bytes() => {}
                    other => failures.push(format!("get {tail:?}: {:?}", other.err())),
                }
                let mut out = Vec::new();
                if sets.data.download(&name, &mut out, 1024).is_err() || out != tail.as_bytes() {
                    failures.push(format!("download {tail:?}"));
                }
                let listed = sets.data.list(&sets.prefix).unwrap();
                println!("list after {tail:?}: {listed:?}");
                if !listed.contains(&name) { failures.push(format!("list lost literal name {tail:?}")); }
                if let Err(e) = sets.data.delete(&name) { failures.push(format!("delete {tail:?}: {e:?}")); }
            }
            Err(error) => {
                let response = c.send(
                    Verb::PUT, c.url(&name, &[]).unwrap(),
                    vec![("x-ms-blob-type", "BlockBlob".into()), ("if-none-match", "*".into())],
                    Some(tail.as_bytes().to_vec()),
                ).unwrap();
                evidence(&format!("name failure {tail:?}"), &response);
                failures.push(format!("put {tail:?}: {error:?}"));
            }
        }
    }
    assert!(failures.is_empty(), "{failures:#?}");
}

fn prepare(dir: &FilePath, now: u64) -> (Manifest, Vec<Upload>) {
    let path = dir.join("source.vlite");
    if !path.exists() {
        let mut db = Database::create(&path, 3).unwrap();
        for id in 1..=5u64 {
            db.put(id, &[id as f32, 0.5, -1.0], format!("p{id}").as_bytes()).unwrap();
        }
    }
    let verification = maintenance::verify(&path).unwrap();
    let detail = maintenance::inspect_detail(&path).unwrap();
    let config: recovery_bundle::Config = serde_json::from_value(json!({
        "tenants": [], "accounts": [], "credentials": [],
        "webhook_subscriptions": 0, "secret_references": [],
        "excluded": recovery_bundle::EXCLUDED,
    })).unwrap();
    let bundle = serde_json::to_vec(&recovery_bundle::bundle(config, INSTALL, detail.lineage, 1)).unwrap();
    let uploads = vec![Upload::file(ROLE_DATABASE, path).unwrap(), Upload::bytes(ROLE_BUNDLE, bundle)];
    let id = new_set_id(now).unwrap();
    (Manifest::new(&id, INSTALL, now, &verification, &detail, &uploads), uploads)
}

fn record(sets: &Sets, id: &str) -> Record {
    serde_json::from_slice(&sets.meta.get(&sets.record_key(id), META_MAX).unwrap().bytes).unwrap()
}

fn retention(enabled: bool) -> Retention {
    Retention { enabled, keep_sets: 0, keep_days: 0, orphan_grace_hours: 1 }
}

fn published(result: Publication) -> Record {
    match result {
        Publication::Published(record) => record,
        Publication::Pending(_) => panic!("unexpected pending"),
    }
}
```
