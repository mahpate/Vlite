## 1. Decision and minimum defensible source

Implement **a bounded, signature-verified clock qualification plus a fresh startup-session grant**, issued by a separately trusted measurement/qualification authority. Use the existing `ring`, `base64`, `getrandom`, `serde`, `serde_json`, `sha2`, `reqwest::blocking`, `std::time`, and `UniqueJson`; no new crate is necessary. Retain the projection startup refusal whenever that authority or its evidence is unavailable.

There is **no identified qualifying production source in this checkout**. Neither the managed-identity token endpoint nor ARM responses, Blob ETags, HTTP Date, local `SystemTime`, or an NTP synchronized status supplies the required pairwise bound. The smallest defensible external source is an operator-approved qualification authority that:

1. Has an independently justified reference-time uncertainty and retained measurement/provenance records.
2. Establishes an approved bound between the **control publisher's wall clock at source-read start** and the **specific backend clock during admission**, over an explicit coverage interval. If individual ACA hosts cannot be identified reliably, coverage must include every eligible host/clock domain in that deployment and re-enrollment policy; app resource ID alone is insufficient.
3. Also establishes the monotonic clock's minimum/maximum rate and suspend/resume behavior for the exact runtime profile used to expire evidence and witnesses. Rust's `Instant` is nondecreasing, not a contractual steady clock or a suspend-inclusive timer [X2].
4. Independently binds qualification to retained deployment identity, source identity, runtime profile, and covered publisher/consumer clock domains. It must not simply sign client-supplied app names, offsets, or numbers.
5. Answers a new unpredictable startup challenge with a signed, bounded-age grant and independently established reference-time interval. This permits evidence-expiry checking without bootstrapping trust from the backend's unqualified wall time.

This authority is an **external dependency to acquire**, not an existing service discovered here. A trusted, already available provider with these properties can implement the read-only port below. If none exists, local development can finish parsing, binding, refusal, and fixture tests, but deployment remains blocked. Historical measurements without a justified future coverage model, a file containing `uncertainty_ms`, or a newly generated signing key do not satisfy this requirement.

An offline qualification certificate can describe the approved measurement and coverage policy. An offline certificate alone cannot establish startup liveness/age in the presence of an untrusted local clock and replay. The first slice therefore requires the fresh signed challenge response. A future trusted anti-replay/time mechanism could substitute, but merely mounting a certificate file cannot.

### Existing sources are sufficient for control and credential content

`ObjectStore` is a blocking whole-object interface, preserves ETags and prohibits redirects (`src/server/cloud_backup.rs:157-179`). `Target` already validates account, endpoint, containers, prefix, auth mode and identity client ID (`cloud_backup.rs:183-214, 294-327`). The Azure adapter makes an authenticated primary-endpoint GET and returns the bounded body plus ETag (`src/server/cloud_backup/azure.rs:572-596, 620-636`). Microsoft documents strong consistency and ETag conditional writes for Blob Storage [X1].

Use this **direct primary authoritative GET** as the minimum production content source. Bind the exact endpoint/account/container/prefix/object. Do not renew a direct feed from a proxy cache, geo-secondary endpoint, export file, recovery inventory, or the fact that an HTTP call succeeded. A generic `ObjectStore` implementation does not automatically inherit Azure primary consistency; production eligibility must be restricted to the validated adapter/source contract. Local fake stores remain fixtures.

There is no separate credential-projection source module in the inspected Rust tree. The shared `Snapshot` contains credentials, tenants and directory in one generation (`control_state.rs:38-58`); `Snapshot::authenticate` authenticates against those credentials (`control_state.rs:713-718`). The gateway uses one fresh feed snapshot for credential authentication and routing (`src/server/gateway_mode.rs:629-647`). The tenant projection intentionally excludes all credentials, including hashes. **Keep that separation**: project tenant/admission plus upstream A and canonical snapshot digest; do not introduce a secret-bearing backend credential feed.

Revocation/suspension freshness is the direct gateway read-start S_ctl bound plus the backend projection's upstream-read-start S_ctl bound. The bounds run in parallel against the same authoritative generation; they should not be described as a new S_ctl starting when a derived object is read. A backend raising its verifier's minimum A refuses older credential envelopes after observing the new A, even if that credential is not in its projection. A fresh reread of the unchanged *authoritative snapshot* can renew a direct feed; a fresh reread of the unchanged *derived witness* cannot renew source freshness.

Credential **absolute expiration** is a distinct clock question: `principal_envelope.rs:423-446` checks envelope issue/expiry and principal expiry using `now`, while `gateway_mode.rs:600, 631, 691` samples local wall time. A projection proof must not be advertised as proving gateway credential expiration globally. In projection backend mode, expose a conservative qualified time interval to the verifier; for a gateway, an independently scoped credential-gateway grant is required before claiming qualified absolute expiry there. Preserve current legacy/full-feed behavior unless explicitly opting into the new qualified deployment profile. Do not silently change every gateway's time semantics in this report's first slice.

## 3. Proposed typed inputs and verification algorithm

These are implementation contracts, not new flags that authorize arbitrary numbers.

```rust
struct SourceBinding {
    installation_id: String,
    scope_id: String,
    account: String,
    endpoint: String,
    coordination_container: String,
    prefix: String,
    object: String,
    // Retained deployment registry identity, if the namespace can be recreated.
    namespace_incarnation: String,
}

enum ClockRole {
    ControlPublisher,
    ProjectionBackend,
    CredentialGateway,
    ArchiveReader,
}

struct RuntimeBinding {
    deployment_resource_id: String,
    environment_resource_id: String,
    deployment_created_at: String,
    revision_id: String,
    runtime_profile_digest: String, // image, OS/timer profile, clock-domain policy
    instance_id: String,
    boot_session_id: String,       // fresh randomness per process
    role: ClockRole,
    tenant_id: Option<String>,
    operation_id: Option<String>, // required for pending/readiness admission
    audience: Option<String>,
    lineage: Option<u64>,
    source_binding_digest: String,
    producer_clock_domain: Option<String>,
}

struct ClockQualification {
    schema: String,                // vlite.clock-qualification/1
    qualification_id: String,
    evidence_digest: String,       // retained measurement/provenance package
    approved_policy_digest: String,
    coverage_digest: String,       // registry-approved producer/consumer domains
    valid_from_unix_ms: u64,
    valid_until_unix_ms: u64,
    pairwise_uncertainty_ms: u64,
    monotonic_rate_min_ppb: u64,
    monotonic_rate_max_ppb: u64,
    resume_policy: ResumePolicy,   // only externally qualified policies accepted
}

struct ClockGrant {
    schema: String,                // vlite.clock-grant/1
    qualification_digest: String,
    binding: RuntimeBinding,
    nonce: String,                 // 32 random bytes, strict encoding
    issued_reference_low_ms: u64,
    issued_reference_high_ms: u64,
    expires_reference_ms: u64,
    grant_sequence: u64,
    // Present only for ControlPublisher; mandatory for that role.
    publisher_stamping_window: Option<PublisherStampingWindow>,
}

struct PublisherStampingWindow {
    from_publisher_wall_ms: u64,
    until_publisher_wall_ms: u64,
}

struct EvidenceChallenge {
    nonce: String,
    expected_binding_digest: String,
    qualification_digest: String,
}

trait ClockEvidenceSource {
    fn read_challenge(
        &self,
        challenge: &EvidenceChallenge,
    ) -> Result<SignedClockEvidence, ClockEvidenceError>;
}

struct ClockSample { wall_ms: u64, mono_ms: u64 }
struct ObservedControlRead {
    snapshot: Snapshot,             // never serialized into the tenant projection
    source: SourceBinding,
    etag: String,
    canonical_snapshot_digest: String,
    started: ClockSample,
    finished: ClockSample,
}
// ClockProof fields private. No Deserialize, public numeric constructor,
// caller-authored "verified" boolean, or production for_test equivalent.
```

`ClockQualification`, `ClockGrant`, binding types, and the signed wrapper use `deny_unknown_fields` and strict bounds. Role is serialized as an explicit enum; `ResumePolicy` is also a closed enum, not a string whose unknown values default to safe.

Implement one bounded `reqwest::blocking` adapter for the read-only issuer challenge when a qualifying issuer is supplied. Use HTTPS, fixed operator-approved origin/path, explicit connect/request timeout, no redirects, no ambient proxy forwarding of credentials, bounded response reads, and no retries of the same grant request after ambiguous completion: a retry obtains a new nonce. A signed read-only challenge may be an HTTP request with a small challenge body; it must not mutate Azure or provisioning state. Authentication/identity enrollment with the external authority must be approved separately; do not repurpose the private Blob token helper into a generic arbitrary-host bearer client. The issuer must resolve binding from its trusted registry/attested domain coverage, not trust the challenge's asserted binding.

### Exact ingestion sequence

1. Read bounded evidence policy and separately delivered issuer public-key bundle with `gateway_trust::read_bounded`; 64 KiB limits suffice for the first slice. Trusted configuration pins permitted issuer/key identities, expected installation/source/runtime identity and approved qualification/policy digests. Neither a response nor a qualification can introduce its own trusted key. Use separate clock-issuer keys, not gateway principal keys.
2. Parse the signed wrapper through `UniqueJson` before typed deserialization. Limit the wrapper and decoded payload separately; reject duplicate fields at any depth, trailing JSON, unexpected schemas/roles, zero or inverted validity windows, invalid digest lengths/encodings, invalid integer rates, and oversized arrays/text.
3. Verify Ed25519 over **exact received payload bytes with a domain-separated envelope**, for example `vlc1.<kid>.<base64url(payload)>`, matching the existing `principal_envelope` signature pattern (`principal_envelope.rs:27-29, 183-208, 396-414`). Signature verification precedes trusting claims. SHA-256 identifies retained evidence; it does not authenticate evidence.
4. Verify the qualification signature and its digest against the approved policy. Evidence must specify an externally accepted bound and coverage model, not a software-derived estimate. A finite qualification interval and runtime profile are mandatory. Use a checked rate representation and wide integer intermediates; reject nonpositive bounds on rate, arithmetic overflow and unsupported resume policy.
5. Generate nonce/session with `getrandom::fill`. Capture `(wall, mono)` immediately before issuing the challenge and immediately after its complete response. Verify the signed grant signature, nonce, boot session, expected binding and qualification digest. Reject returned grants from an older boot, different source/tenant/lineage/audience/revision, unknown qualification, or sequence regression. The issuer's boot/instance coverage must be independently substantiated.
6. Bootstrap trusted **reference time**, not clock quality, from the grant's independently bounded reference interval. Let the grant be issued in reference interval `[Tlo, Thi]`, challenge local elapsed monotonic be `d`, and the qualified minimum timer rate be `rmin` parts per billion. At receipt, a conservative reference interval is `[Tlo, Thi + ceil(d * 1e9 / rmin)]`. This includes request/response delay. Require that whole interval be inside the approved qualification/grant validity windows. All arithmetic is checked. A slow challenge can consume the entire grant budget and must refuse.
7. Anchor that interval to the receipt monotonic sample. Later elapsed `e` advances the lower endpoint by `floor(e * 1e9 / rmax)` and upper endpoint by `ceil(e * 1e9 / rmin)`. Refuse when the conservative upper endpoint reaches expiry; validity at equality is expired. A wall clock discrepancy can additionally trip the existing sticky regression check, but never establish or enlarge the approved uncertainty.
8. Construct private `ClockProof` only after these checks. It retains immutable approved coverage, role/source/runtime binding, issuer/qualification/evidence digests, reference interval anchor and conservative monotonic expiry. `valid_at` is called for **every freshness decision**, not once at startup.

Reference time and qualified timer rates above are claims requiring external substantiation. The client algorithm does not measure them. In particular, the signed challenge plus local RTT cannot by itself prove a pairwise clock bound.

### Bind the producer evidence to each witness

Current projection v1 has tenant, generation, digest, revision and timestamps, but no producer/source/evidence identity. Use an explicit **`vlite.control-projection/2`** for the new qualified deployment profile, not an optional v1 field with an unverified default. Add:

- `source_binding_digest`;
- publisher `RuntimeBinding` digest and boot session;
- qualification digest;
- a bounded signed publisher grant (or its exact digest plus a separately authenticated, digest-checked immutable grant; embedding avoids another first-slice fetch).

The backend verifies that grant with pinned issuer keys, requires a publisher-role grant for the same source/coverage domains, and checks its timestamps/coverage against the witness and backend grant. The publisher grant must explicitly delimit the allowed **publisher wall-clock stamping interval**, as justified by the external qualification; the reference-time interval is not interchangeable with publisher wall time.

Publisher chooses `deadline <= min(read_start + S_ctl, last_qualified_publisher_wall_deadline)` with checked arithmetic. The read-start and resulting deadline must be inside its approved stamping interval. Before PUT, confirm the upstream read completed and sufficient qualified budget remains. A completed read/PUT after expiry is not a successful usable witness; uncertain PUT outcome still uses existing `projection_indeterminate`, followed by a fresh read before another attempt. No successful stale publication result.

Compare-and-swap and per-reader regression checks remain. A new publisher boot can legitimately take over with a newer qualified grant and higher witness revision, but it must still perform a new authoritative read and match the expected source and deployment domains. Never reset witness revision to one on an existing object. Freeze the canonical snapshot-digest rule already used by `Publisher`; do not confuse canonical snapshot SHA-256 with raw projection byte digest.

Backend privilege remains read-only for tenant projections. Production source integrity depends on verified storage origin and appropriately restricted publishing access; a digest plus a clock certificate cannot turn an untrusted writer into a trusted publisher. External deployment evidence must confirm the binding/permissions assumption. This is not a new writer-fencing mechanism.

## 4. Runtime state machine and budgets

### Startup

`GatewayTrustConfig::read` validates source/evidence configuration without store contact. `GatewayTrust::start` in projection mode obtains/validates the grant before connecting coordination. Missing key bundle, absent provider, unknown qualification, unqualified runtime profile, unsupported suspend behavior, binding mismatch, malformed signature or expired evidence is a startup error. Prefer stable codes:

| Condition | Result |
|---|---|
| No available qualifying provider/evidence | `projection_freshness_unproven` |
| Malformed/unauthenticated evidence | `projection_clock_evidence_invalid` |
| Wrong deployment, boot, role, source, tenant, lineage or audience | `projection_clock_binding_mismatch` |
| Grant/qualification expired or exhausted during startup read | `projection_clock_evidence_expired` |
| Wall/monotonic regression after enrollment | existing `projection_clock_regressed`, sticky |
| Missing/invalid/stale witness | existing projection-specific refusal |

Only after verified evidence, a valid initial projection GET, and `reader.current()` succeeds may trust startup complete and minimum A be raised. The extra `current` check closes elapsed time between polling and startup admission. Full-view exclusivity remains: invalid projection configuration cannot select `control_state` or serve development/open auth. Unavailable evidence should fail before projection GET, not only prevent the first request.

The external publisher runtime caller is a separate integration prerequisite. The local slice can make `Publisher::new/publish` require a publisher proof, expose the bounded source-observation helper, and exercise it with fake stores. It cannot claim a production publisher is deployed merely because a backend loader exists.

### Serving and expiry

For a new witness received at wall `W`, monotonic `M`, with deadline `D`, approved pairwise uncertainty `U`:

```text
witness_remaining = D - (W + U)                // checked, strictly positive
evidence_remaining = certified expiry - conservative reference upper(now)
remaining = min(witness_remaining, evidence_remaining)
monotonic_budget = floor(remaining * rmin / 1e9)
accepted_expiry = checked_add(M, monotonic_budget)
```

Require positive monotonic budget. At every decision reject when evidence invalid, `mono >= accepted_expiry`, or checked `wall + U >= D`. Correcting for qualified slow monotonic rate is necessary: the existing 1:1 anchoring assumes a rate/resume property that `Instant` alone does not guarantee. Forward wall jumps fail earlier; backward/monotonic regression stays sticky. Overflow refuses; saturating arithmetic must not create an effectively immortal deadline.

Renewal obtains a new nonce-bound grant for the same expected source/runtime/qualification policy and strictly nonregressing issuer sequence. It can occur on the existing poll tick, before storage read, using the read-only provider; capture no `Trust` ownership cycle. **Renewing evidence does not change an accepted projection's expiry**. Only a genuinely newer witness from a new upstream read may establish a later witness budget. First-slice conservative policy: restart required after evidence expires or regression trips; no hot resurrection of an already refused runtime. Poll worker logs stable error codes; public errors/logs contain no raw evidence, credentials or signing material.

Content failures/regressions remain the existing bounded-cache policy: a failed poll does not renew or replace an accepted witness, and that witness can be served only until its original deadline while its proof remains valid. A repaired source/new valid witness can recover an ordinary source refusal. Clock regression is different and sticky. Do not accidentally equate a successful same-revision poll with freshness; it should return `projection_stale` once the accepted witness is stale.

### Direct feed and archive-following reader

Direct feed freshness measures elapsed time from the local authoritative read-start. Keep the current conservative pre-read timestamp; moving it to read completion grants extra time during slow reads. Extend the observation cache with canonical digest and compare it on same-ETag renewal. This relies on the direct-source consistency contract; an ETag from an arbitrary export does not establish current control/credential state.

For `reader_apply`, local archive confirmation is **not a ClockProof** and does not establish cross-host replication lag since the writer's last write. It establishes how long this process has gone without confirming the newest verified head of its configured source. Use:

```rust
struct Confirmation {
    sequence: u64,
    confirmed_unix_ms: u64, // informational, keep existing bookkeeping consumers
    read_started_mono_ms: u64,
    expires_mono_ms: u64,
}
```

Install it atomically under one mutex only after current-head verification and a successful swap, or an unchanged verified head. Age/readiness/header consumers obtain one coherent snapshot. Use qualified timer rate/resume policy for production guarantees; legacy tests can inject an explicit deterministic timer. Do not mix separate sequence/time atomic loads from different confirmations. A slow enrollment/follow/swap can immediately be stale; successful recovery does not grant a fresh S_reader from completion time.

During authority recovery, keep the **entire old confirmation**, not only old Unix time while refreshing its monotonic time. Preserve current epoch-stamping semantics. Unix regression no longer yields fresh age zero. Keep existing equality semantics for direct feed/archive age (`age <= bound`) unless deliberately versioning that behavior; projection and evidence deadlines remain strict (`now < deadline`). Round advertised age upward conservatively so the gateway cannot see an understated age.

`reader_staleness` readiness, read rejection, serve-status and `x-vlite-applied-age-ms` must consume that same age. An unknown/invalid age is stale when a bound is configured; it is not header value zero. Do not change file swapping, archive pin ownership, replay verification, writer routing or broader failover/fencing policy.

### Absolute credential/envelope time

For the new projection-qualified profile, expose `qualified_now_interval() -> Result<(lo, hi), ApiError>` from the proof. Backend principal expiration requires `hi < principal.expires_unix_ms()`; envelope expiration checks use the conservative upper bound. For not-yet-valid envelope checks, require `iat <= lo + permitted_skew`; keep the existing lifetime limit. Do not treat configured envelope skew as a measured clock uncertainty.

This may refuse a narrow uncertainty boundary that legacy scalar checks accepted, so gate it with the explicit v2 qualified profile and cover boundary tests. Gateway absolute credential expiry needs its own scoped proof and tests across API tokens, sessions, login/session refresh and envelope minting before a claim of complete qualified credential lifetime enforcement. That gateway-wide rollout is a separate owner after the proof/time-view contract lands, not an unadvertised first-slice expansion.

## 5. Provisioning and readiness consumption boundary

New tenant provisioning can outlast any individual clock grant. Acquire/renew short-lived evidence as needed, and perform a **new** authoritative source read and readiness observation near activation. Do not start S_ctl at operation creation, keep a proof alive by rereading an old object, or extend credential consumption TTLs by a guessed provisioning duration.

Relevant nonexcluded evidence:

- `control_state.rs:1382-1432`: activation atomically publishes the writer-only route and receipt; cancellation/route mismatch refuses.
- `tenant_provisioning.rs:1512-1578`: `prove` currently checks only proof presence before assembling the readiness digest. Presence must become `valid_at` for a role/source/operation-bound observation; no production qualification follows merely from passing `Some`.
- `tenant_provisioning.rs:2111-2140`: create activation requires proven readiness, acknowledged delivery, and a live published candidate; bookkeeping `now` is not the credential-observation clock. A committed receipt is deliberately recoverable without re-proving an already committed route.

The readiness input should become a bounded, authenticated observation receipt: operation ID, expected route digest, seeded lineage/epoch, backend audience/runtime binding, source A/digest, required and observed policy generation, manifest digest, local read intervals, and clock-evidence digest. A clock proof proves only the qualified timing/coverage premise; it does not prove ARM/backend readiness. Require a newly qualified observation at the pre-CAS validation point. Each CAS retry that recomputes activation must recheck evidence and credential validity; never reuse a stale readiness claim because an operation still exists.

Do not manufacture an `aca::Observed` from an external certificate or make the stale ACA snapshot the implementation authority. Detailed actual ACA response shape and active-revision observation must be acquired by the separately assigned ACA/readiness work. Locally we can freeze this typed observation contract and refusal tests without editing excluded ACA surfaces.

Public consumption begins only after the verified activation route/receipt is visible and the acknowledged credential is admissible. Before that, pending projection admission remains the operation-bound validator API credential with read-only operations (`projection.rs:161-184, 206-234`); candidate delivery/acknowledgment is not public routing activation. Evidence loss before route CAS prevents activation. After committed activation, receipt recovery must not be turned into an unsafe attempt to re-run activation or a requirement for a historical proof to remain live; current gateway/backend serving still independently requires fresh views.
