## Failing drafts, excluded from the passing diff

These are intentional contract assertions, not tests changed to accept the current behavior. Each ran by its exact selector and returned Cargo exit **101**, `0 passed; 1 failed`.

### F1: An empty output becomes visible before the publication rename

Evidence: `src\server\cloud_recovery.rs:532-544` creates `plan.output` before `rename`. The existing R6 test requires the resulting empty directory. This violates the strict output-complete-or-absent contract even though staged contents are not individually copied into the destination.

Place this test in the existing recovery test module:

```rust
#[test]
fn audit_claim_boundary_never_exposes_partial_output() {
    let env = setup();
    assert_eq!(env.restore_crashing("claimed").code, "test_crash");
    assert!(!env.request().output.exists(), "an empty output is partial output");
    assert_eq!(env.pins(), 0);
}
```

```text
cargo test --offline --locked --features server --lib server::cloud_recovery::tests::audit_claim_boundary_never_exposes_partial_output -- --exact --nocapture
thread 'server::cloud_recovery::tests::audit_claim_boundary_never_exposes_partial_output' panicked:
an empty output is partial output
test result: FAILED. 0 passed; 1 failed
```

Recommendation: either implement a same-volume, atomic **no-replace** directory publication primitive, or explicitly relax the complete-or-absent contract and document the observable empty claim. Do not remove destination protection by substituting an overwriting rename. The present operational documentation mentions interrupted empty claims (`DOCKER-OPERATIONS.md:459-461`), so the strict contract and implementation/documentation need an explicit reconciliation.

### F3: The free-space preflight is skipped when the probe returns no measurement

Evidence: fetch calls `check_restore_space(free_bytes(...), ...)` before payload access, but `src\server\compaction.rs:1155-1157` returns `None` on non-Unix platforms, and `cloud_backup.rs:72-83` accepts `None`. S1 explicitly asserts that `None` is accepted. Consequently the unconditional free-space requirement is not met here.

```rust
#[test]
fn audit_free_space_is_measured_before_restore() {
    let dir = tempfile::tempdir().unwrap();
    assert!(
        super::super::compaction::free_bytes(dir.path()).is_some(),
        "the free-space preflight must not silently skip this filesystem"
    );
}
```

```text
cargo test --offline --locked --features server --lib server::cloud_recovery::tests::audit_free_space_is_measured_before_restore -- --exact --nocapture
thread 'server::cloud_recovery::tests::audit_free_space_is_measured_before_restore' panicked:
the free-space preflight must not silently skip this filesystem
test result: FAILED. 0 passed; 1 failed
```

This executed **probe-only** test establishes unavailability, not low-space fetch ordering. Recommendation: implement a platform probe or explicitly refuse unsupported measurements if the contract is unconditional. Add a test-only injectable free-space result so `Some(needed - 1)` can be driven through fetch with an object-read observation hook, asserting `restore_insufficient_space`, zero payload reads, absent output and zero pins. Filling a filesystem is unnecessary and was not attempted. The current best-effort behavior is an intentional code policy that conflicts with the stronger requested contract, not an arithmetic defect.
