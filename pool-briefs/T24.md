## Scope

Today a claimed writer still publishes legacy sets and appends legacy
checkpoints, so the authority stays with no head, `failover report` never
reflects archive progress, and a former owner can keep appending legacy
checkpoints until its fence stops it. With a claimed writer authority, the
runtime backup loop must publish and archive only through the
authority-bound path.

1. `WriterFence`: add `pub(super)` read-only accessors for the authority
   store and claim (for example `authority() -> Option<(&AuthorityStore,
   &Claim)>`). Writer id and epoch come from the `Claim`; scope id and
   lineage come from the record returned by `verify_writer`. The disabled
   fence returns `None`. Do not change fence state rules.
2. `Handle`: carry a clone of `s.writer_fence`, set inside `Handle::new`
   so no call site changes. `authorized()` keeps its `closed()` refusal
   and, when the fence has an authority, also calls
   `fence.verify_before_commit()` (mapping the fence error to its existing
   `ApiError`). Every archive commit therefore re-verifies the epoch; a
   Fenced result fires the existing stop signal.
3. `publish` with an authority: build the same snapshot, verification,
   uploads and `Manifest`, wrap it in `HaManifest{schema, authority:
   HaIdentity{writer_id, epoch, scope_id, lineage}, manifest}` and call
   `sets.publish_ha(store, claim, &ha, &uploads, now, &authorize)`. Return
   the Published `Record` (for example via `resolve_ha_baseline` after the
   head advance, checking it names this set) so `run_job` keeps setting
   `status.last_set`. Map `HaPublicationError` with its existing
   conversion (`HeadMoved` → `writer_rebase_required`; the next cycle takes
   a new snapshot and rebases, never retries the stale observation).
4. `archive_once` with an authority: the baseline is the authority head
   from `resolve_ha_baseline`, never `status.last_set`. No head yet → the
   existing `pitr_baseline_missing` refusal. Then `open_archive_ha(store,
   claim)`, keep the policy-match check, `export_log(archive.next_base(),
   MAX_SEGMENT_BYTES)`, `recovery_bundle::bundle`, and
   `append_checkpoint_ha(...)`. Report the same `{set_id, checkpoint,
   checkpoints}` shape.
5. Consistency refusals, with an authority only (409, new codes; add them
   next to the existing cloud-backup codes and document them):
   - the configured cloud-backup target differs from the authority target
     in account, container, coordination container, prefix or endpoint →
     `writer_authority_target_mismatch`. Check at `PUT
     /v1/admin/cloud-backup` and again before each publish/archive. Carry
     only the authority target's non-secret fields (never a key) to where
     you compare them.
   - the cloud-backup `installation-id` differs from the authority record's
     `installation_id` → `writer_authority_installation_mismatch`, before
     any upload. Document in `docs/HA-ACA.md` that `authority init
     --installation-id` must be the `installation_id` shown by `GET
     /v1/admin/cloud-backup`.
6. Keep the startup refusal of an archived `base`
   (`writer_authority_base_unverified`). Restoring that base is ITEM-040
   (a later task). Do not touch drills or retention: drills and `collect`
   of HA sets are completed by a parallel task (ITEM-039) that owns
   `cloud_backup.rs` and `archive.rs`; tests here use `drill_every: 0`. If
   a drill or retention problem shows up, record it as a `FINDING:` line
   instead of working around it.

Existing deployments (no `--authority-target-file`) must be unchanged in
behaviour: no authority store access, legacy `publish`/`append_checkpoint`
byte-for-byte, the same status JSON and the same refusal codes.

## Tests (test-first)

- Lib unit tests in `backup_policy.rs` with the fake `Memory` store and a
  claimed fence (reuse the `setup_ha`/`prepare_ha` patterns or the
  `writer_authority.rs` test setup):
  - authority on: a run publishes an HA set and the authority head names it
    (`set_id`, `epoch`, `sequence`, manifest sha);
  - an archive cycle appends an HA checkpoint and advances the head
    sequence with an index digest;
  - after `prepare_transfer` (epoch bump) the old writer's publish and
    archive commit nothing, the fence becomes Fenced and the stop signal
    fires;
  - `HeadMoved` maps to `writer_rebase_required` and the next cycle
    rebases from a new snapshot;
  - target and installation mismatches refuse before any upload;
  - authority off: the legacy path performs no authority store operation
    and produces the same manifest bytes as before.

  writer stops; a new writer on the same target is refused
