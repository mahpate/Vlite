## Required behaviour

1. `pub const FAILOVER_USAGE: &str` (private is fine) =
   `"vlite-server failover report|execute --target-file <json> [--shared-key-file <path>] [--archive-status-file <json>] [--observed-sequence <n> --observed-unix-ms <ms>] [execute only, all required: --ack-report-id <id> --expected-epoch <n> --expected-revision <rev> --old-replicas <n>]"`.
2. `pub fn failover_command(args: &[OsString]) -> Result<serde_json::Value, String>`
   (blocking; called off the async runtime):
   1. First argument is the verb `report` or `execute`, else
      `invalid_arguments: the verb must be report or execute; usage: ...`.
   2. Parse with `gateway_mode::flags`; `report` allows `--target-file`,
      `--shared-key-file`, `--archive-status-file`, `--observed-sequence`,
      `--observed-unix-ms`; `execute` additionally allows `--ack-report-id`,
      `--expected-epoch`, `--expected-revision`, `--old-replicas`, all four
      required. `--target-file` is required for both.
   3. `--observed-sequence` and `--observed-unix-ms` are both given or both
      absent (else `invalid_arguments: --observed-sequence and --observed-unix-ms go together`);
      both parse as `u64`. `--expected-epoch` and `--old-replicas` parse as
      `u64`; `--ack-report-id` and `--expected-revision` are non-empty UTF-8
      of at most 256 bytes. A parse failure names the flag, never the value.
   4. `--archive-status-file`: read at most 64 KiB (larger →
      `invalid_arguments: --archive-status-file is larger than 64 KiB`),
      parse as `ArchiveStatus` (failure →
      `invalid_arguments: --archive-status-file is not archive status JSON`;
      never echo contents).
   5. All argument checks happen before any network access. Then
      `cloud_recovery::connect` (error → `"{code}: {message}"`),
      `sets.coordination()`, `AuthorityStore::new(meta, prefix)`, and an inner
      `fn run(store: &AuthorityStore, request: Request) -> Result<Value, FailoverError>`
      (your `Request` type) that tests drive on the fake store.
   6. `report` → `{"report": <LossReport JSON>, "text": report.render()}`.
      `execute` → rebuilds the report with `build_report` from the same
      inputs, then `execute(store, &report, &ack)`; output
      `{"report": ..., "text": ..., "result": {"record": <authority Record>, "etag": ...}}`.
      The rebuilt report's id must equal the ack (the library already checks
      this as `failover_ack_mismatch`; do not weaken it). A `FailoverError`
      becomes `"{code}: {short fixed description}"`.
   7. Event `failover_command` (`verb`, `outcome` = `ok` or the code); no
      values from arguments.
3. `vlite-server`: add `"failover"` beside `"gateway-keygen" | "control-state"`
   in the `main` match and in `gateway_tool`'s dispatch, so it shares the
   same `spawn_blocking`, pretty-JSON success output, `{"error": message}`
   stderr and failure exit. Add one USAGE line describing
   `vlite-server failover report|execute ...` and that `execute` requires the
   old writer at zero replicas and the exact report acknowledgement.
4. Remove `#[cfg_attr(not(test), allow(dead_code))]` from failover items that
   become used outside tests; keep it where they remain test-only.
