## Scope

Add two drills to `tests/ha_chaos_azurite.rs` using only the existing

1. **D7 `chaos_former_owner_head_cas_fails_and_new_writer_starts_from_verified_head`**
   (TEST-007 remainder, AC-007):
   - writer A claims epoch 1 with archive enabled (short
     `ARCHIVE_INTERVAL_SECS`), inserts a seeded random number of ids, and
     archives at least once so the authority head advances; record
     `head.sequence`;
   - insert more ids that are **not** archived yet (cut A's authority path
     with `Proxy` or stop before the next cycle, seeded choice);
   - run `failover report` then `failover execute --old-replicas 0` while A
     is paused / cut (as in D6), so the transfer sets `base` = A's last
     head;
   - restore A's path: A's next head CAS (archive cycle or publish) must
     fail — assert the authority head is unchanged (`head` absent, `base`
     still the transferred head, epoch 2, revision only advanced by the
     operator / new claim) and A never acknowledges a write after the
     transfer and self-stops within `AUTHORITY_RECHECK_MS + 5s`;
   - start writer B on a **stale or empty** database path: B restores the
     base, claims epoch 2, `/ready` 200, every id up to `head.sequence` is
     readable with identical vectors, ids written after the last archive are
     absent (the reported loss), and `writer_acknowledges(&b, 2)`;
   - if the restore leaves a superseded file (T24b), assert it exists for
     the stale-path case.
2. **D8 `chaos_failover_loss_report_matches_archived_position`** (TEST-008,
   AC-009):
   - writer A at epoch 1 with archive; seeded number of insert/archive
     rounds and a final burst of unarchived inserts; optionally kill A
     (`child.kill()`) or cut it mid-archive with a seeded delay
     (`delayed_fault`);
   - `failover report`: assert its reported archived position (sequence /
     set id / chain) equals what is actually durable — derive the truth by
     starting B after `failover execute` and reading B's restored sequence
     (`/v1/admin/...` status or `x-vlite-sequence`/position headers the
     server exposes) and the set of readable ids;
   - assert loss is never understated: every id the report counts as
     archived is readable on B, and every id written by A but missing on B
     is inside the report's loss window (report sequence < write sequence);
     the report's position is never ahead of B's restored position;
   - repeat for `VLITE_CHAOS_ITERATIONS` seeded rounds; print one
     `D8 seed=<n>: reported=<seq> restored=<seq> lost=<count>` line per
     round.
