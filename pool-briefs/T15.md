## Required behaviour

1. `pub struct ReaderApplyConfig` (`serde::Deserialize`, `deny_unknown_fields`):
   `target_file: PathBuf`, `shared_key_file: Option<PathBuf>`,
   `follower_dir: PathBuf`, `capacity_bytes: u64`, `staleness_bound_ms: u64`,
   `poll_interval_ms: u64`. All but `shared_key_file` required, none with a
   default. `ReaderApplyConfig::load(file: &Path, served: &Path) -> Result<Self, String>`
   reads at most 64 KiB (larger → refused) and validates:
   `follower_dir` absolute with no `.`/`..` components;
   `1 <= capacity_bytes <= MAX_DATABASE_BYTES`;
   `1 <= staleness_bound_ms <= 3_600_000`;
   `1 <= poll_interval_ms < staleness_bound_ms`;
   `served == follower_dir/reader-a/database.vlite` (lexical comparison).
   Every error is `reader_apply_invalid: <detail>` and never echoes file
   contents or values.
2. Slots: A = `follower_dir/reader-a/database.vlite`, B =
   `follower_dir/reader-b/database.vlite`. The reader owns exactly those two
   directories: at enrollment, if either exists it must be a real directory
   (`symlink_metadata`, a symlink or file → `reader_apply_invalid`) and is
   removed recursively; nothing else under `follower_dir` is touched. Both are
   then created with `create_private_subdir`.
3. Replica identity: `CONTAINER_APP_REPLICA_NAME`, else `HOSTNAME`, else
   `pid-<pid>`; characters outside `[A-Za-z0-9._-]` become `_`, truncated to
   120 chars. Pin reason = `reader-apply:<replica>`.
4. `pub struct ReaderApply` and
   `ReaderApply::enroll(config: ReaderApplyConfig) -> Result<ReaderApply, String>`
   (blocking): `cloud_recovery::connect` (a `RecoveryError` becomes
   `"{code}: {message}"`), then an inner
   `fn enroll_with(sets: Sets, config, replica: &str, now: u64) -> Result<ReaderApply, ApiError>`
   that tests drive on the fake store, in this order:
   1. `list()`; choose the first (newest) `Listed` whose `record` is
      `Some` with state `Published`; none → 409 `reader_apply_no_set`.
   2. Release this replica's stale pins: on every listed set with a record,
      `release` each pin whose reason equals this replica's reason (a crash of
      the same replica name left them). Pins of other readers are untouched.
   3. `pin(set, reason, PinKind::Operation, now)`.
   4. Prepare slots (item 2), `fetch_with(set, pin, slot A dir, capacity_bytes)`.
   5. `follow_archive` on slot A: `Applied`/`Current { sequence }` → served
      sequence; `Reseed(reason)` → 409 `reader_apply_reseed_required`.
   6. If slot A's file length exceeds `capacity_bytes` → 409
      `reader_capacity_exceeded`; then
      `check_restore_space(free_bytes(follower_dir), len + RESTORE_SPACE_MARGIN)`;
      then copy slot A to slot B with `create_private_file` and `sync_all`.
   7. `Progress`: `set_bound(staleness_bound_ms)`, `confirm(sequence, now)`.
   8. Event `reader_apply_enrolled` (set id, sequence, pin id; no paths of
      secrets, no target contents).
   Any failure after step 3 removes both slot directories and releases the pin
   (best effort; report the original error), so a failed enrollment leaves no
   pin and no partial file.
5. `ReaderApply::step(&self, service: &Service, now: u64) -> Step` (one poll,
   driven directly by tests; `Step` is a small enum you define, e.g.
   `Confirmed`, `Swapped`, `Retry`, `Failed`, `Stopped`). If the progress has
   already failed → `Stopped` without any store call. Otherwise:
   1. `list()`; if a newer Published set than the followed one exists →
      `fail("a newer published set needs a re-seed")`; if the followed set is
      missing or no longer Published → `fail(...)`.
   2. `follow_archive` on the standby slot.
      `Applied`/`Current { sequence: s }`:
      - `s > served`: standby length over `capacity_bytes` → fail; open the
        standby with `Database::open_read_only`, `swap_reader_generation`
        (refused → fail), flip served/standby, `confirm(s, now)`, event
        `reader_apply_applied` (set id, sequence, segments).
      - `s == served`: `confirm(served, now)`.
      - `s < served`: fail ("the archive head moved backwards").
      `Reseed(reason)` → fail(reason).
   3. `Err(error)` with status 503 (`cloud_store_unavailable`) or 507
      (`restore_insufficient_space`) → `Retry` (no confirm, so the staleness
      bound eventually fails readiness); any other error → fail with its code.
   Every fail path calls `Progress::fail` (it logs `reader_apply_failed`) and
   then releases the pin. At most one swap per step; the old served slot is
   caught up by the next step's `follow_archive`.
6. `Service::with_reader_apply(self, apply: &ReaderApply) -> Self` (pub): sets
   `reader = Some(apply's Progress)`. Remove the now-unneeded
   `#[cfg_attr(not(test), allow(dead_code))]` attributes in `reader_apply.rs`.
7. `ReaderApply::start(&mut self, service: Service)`: one named std thread that
   waits `poll_interval_ms` on a stop channel (`recv_timeout`) between steps
   and exits on `Stopped`. `ReaderApply::stop(self)` (blocking, idempotent):
   signals, joins, then releases the pin (event `reader_apply_pin_released`).
   A pin release failure is logged, never panics.
8. `vlite-server`:
   - `--reader-apply-file <json>` / no env var. Refused unless
     `--serve-mode reader` ("--reader-apply-file needs --serve-mode reader"),
     refused with an encryption key ("a reader that applies the archive

   - When set, before the database `open()` (599-662): `ReaderApplyConfig::load`
     with the positional path, then `ReaderApply::enroll` in

   - After the service builder (872-889): `.with_reader_apply(&apply)`.
     After the router starts: `apply.start(service.clone())`.
   - Failed start (905-912) and shutdown (before `service.close()` at
     1079-1082): `stop()` in `spawn_blocking` before closing the service.
   - USAGE (line 20): document `--reader-apply-file <json>` for reader mode
