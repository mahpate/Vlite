## Required tests

1. `reader_reserved_names_answer_like_missing`: in reader mode with
   bindings, each representative read of a reserved name (`notes_ev`,
   `notes_graph`) returns the same status and `error.code` as the same read
   of a truly missing name; list routes omit reserved names; ordinary names
   still served.
2. `writer_reserved_names_answer_like_missing`: same in writer mode.
3. `reader_mutations_on_reserved_names_are_reader_mode_not_leaks`: a
   mutation on a reserved name in reader mode returns the same answer as on
   a missing name (expected 403 `reader_mode`); no response text contains a
   reserved name.
4. `metrics_refused_with_bindings_does_not_affect_health_ready_or_status`
   for reader **and** writer modes: `/metrics` (admin) is 403
   `forbidden_scope`; `/health` 200; `/ready` 200; `/v1/admin/serve-status`
   200 with the correct `mode`, `sequence` null, and no reserved names in the
   body.
5. `without_bindings_metrics_and_sequence_are_unchanged` (control): the same
   reader/writer services without bindings answer `/metrics` 200 and a
   numeric `sequence`.
6. Binding-generation mismatch removing a reader from routing is already
   unit-covered in `src/server/gateway_mode.rs` (`eligible_reader` 555-565,
   test near 1317, header `x-vlite-binding-generation`). Only if the public
   API exposes a gateway router usable in-process, add
   `gateway_drops_reader_on_binding_generation_mismatch`; otherwise add a
   short comment in the file pointing to the unit test and state it in the
   commit message.
