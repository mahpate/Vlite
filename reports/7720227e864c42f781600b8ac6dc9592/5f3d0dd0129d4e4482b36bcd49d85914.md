# Dedicated tenant provisioning: evidence-backed unblock design

**Status: INCOMPLETE for live validation and qualification; design report delivered.**

This assignment performed repository inspection and one existing, fully mocked offline suite. It did not provision anything, contact Azure or any network endpoint, authorize execution, change a gate, or establish production readiness. Only this report is a deliverable. Existing-tenant migration (EPIC-006, ITEM-015..017) is excluded.

## 1. Main finding and evidence conventions

**CONFIRMED:** There is no current production path from a dashboard create submission to an activated dedicated tenant, nor from a reader submission to a provisioned, observed reader fleet. This is not just an unwired ARM adapter. The adapter now exists and is constructed only after preflight; production supplies empty proof options. Even hypothetical preflight success produces only `provisioned`, not an activated route. Private seed/readiness/credential composition and reader execution remain separate gaps.

**PROPOSED:** The minimum safe change is an evidence-producing and evidence-consuming composition of existing primitives, not an enablement switch. Reuse ACA app secrets for role-specific generation projections, private `VLITE_ADMIN_DIR` files for operator/control material, and the existing Blob coordination store for durable journals, evidence references, projections and receipts. No new external service or dependency is needed or proposed. An evidence document is not proof merely because it exists, is signed, or contains an approval field: the verifier must establish its provenance, scope, measurements, applicable unchanged acceptance criteria and currency.

In this report **CONFIRMED** means statically established in this checkout, except where explicitly labeled an executed check. Historical measurements are repository-recorded evidence, not measurements reproduced here. **PROPOSED** means future design/implementation, not an owner decision, permission or passing result.

Important source precedence:

- The current worker and `admin::run` supersede historical PRD statements that no adapter is constructed at runtime: `src/server/tenant_provisioning/worker.rs:48-64`, `src/server/tenant_provisioning/admin.rs:1144-1158`. The later implementation note records this correction: `docs/projects/feature-aca-ha/design-tenant-provisioning/design-tenant-provisioning.prd.md:1268-1272`.
- The isolated pin-object implementation supersedes a literal reading of older comments that all pins must rewrite set records. Those comments still correctly describe the legacy path and the absence of accepted production permission proof. Compare `src/server/tenant_provisioning.rs:436-464` with `src/server/reader_apply/follower.rs:246-265` and `docs/projects/feature-aca-ha/design-tenant-provisioning/design-tenant-provisioning.prd.md:818-830`.
- Local design OD-002 means **control actuator exclusion**; parent HA OD-002 means **writer stale-acknowledgment/zombie behavior**. Neither proves the other. Local OD-005 encompasses storage/pin isolation; the projection code also associates clock proof with OD-005. Parent HA OD-005 is the `S_ctl`/poll choice. Keep separate evidence records for these obligations.

## 2. What the current paths actually do

### Dedicated writer

**CONFIRMED runtime order:** select an operation; read control state and journal; require an uncancelled held reservation and nonclosed journal; refuse a foreign claim; resolve the retained create profile; require qualification, quota and budget; build the ARM adapter; claim once; provision once. No gate before the claim dispatches ARM. Automatic selection considers only unclaimed creates, not reader intents. An unreadable record stops selection. A failed or unknown attempt retains its claim; another invocation gets a fresh attempt ID and cannot take it over.

Evidence: `src/server/tenant_provisioning/worker.rs:112-247`, especially `:151-177` and `:182-239`; `src/server/tenant_provisioning/admin.rs:1144-1158`.

**CONFIRMED distinction:** The first claim does not require `ActuatorStopped`; replacing a different claim does. The standalone driver contract can accept a prior stop proof, but this worker explicitly rejects another holder and passes `None` into `Driver::new`. A future stop-proof constructor alone would therefore not wire recovery into `work`.

Evidence: `src/server/tenant_provisioning.rs:748-773`; `src/server/tenant_provisioning/worker.rs:197-223`.

**CONFIRMED after ARM:** `Outcome::Provisioned` means only resources were created/verified and journaled. It does not record a seed, establish authority, obtain readiness, deliver credentials or activate. Those library primitives are separate, and the administrative acknowledgement/replacement actions still return `transition_unavailable`.

Evidence: `src/server/tenant_provisioning/worker.rs:74-86`, `:225-247`; `src/server/tenant_provisioning.rs:1322-1518`, `:1720-1808`; `src/server/tenant_provisioning/admin.rs:570-575`.

### Readers

**CONFIRMED:** Reader submissions are durable intent, not execution. A present-fleet resume is denied for missing pin proof. The worker does not select reader operations; explicit non-create selection fails profile resolution. Library reader actuation requires a plan bound to the latest sealed route receipt, pin proof, preflighted reader profile and fleet observation. It intentionally permits only `writer_only` routing. Thus creating reader replicas and routing user reads to them are different milestones.

Evidence: `src/server/tenant_provisioning/admin.rs:529-540`; `src/server/tenant_provisioning/worker.rs:151-177`; `src/server/tenant_provisioning/aca.rs:229-237`, `:1581-1663`, `:1688-1804`. Current item status explicitly records absent reader REST/CLI/worker composition and unenforced writer-mount exclusion: `docs/projects/feature-aca-ha/design-tenant-provisioning/design-tenant-provisioning.prd.md:534-540`.

## 7. Fail-closed evidence contract and trade-offs

**PROPOSED common verification rules:** Bind evidence to tenant/operation where relevant, build/profile digest, target/region/resource IDs, actual principal/client ID/audience, source artifact hashes, acceptance policy version, observation interval and approved expiry/invalidation events. Validate integrity and accountable issuer using the existing trust boundary. Retain raw secret-free supporting artifacts/references in Blob; keep credentials and private signing material in private admin files/ACA app secrets, never journals, CLI literal arguments, logs or this report.

Validation must distinguish:

- **Unknown/missing/corrupt/untrusted source:** no proof, no claim or new dispatch; return the specific blocker and keep the operation observable. Do not silently use last-known-good after its validity ends.
- **Stale evidence or relevant configuration/identity change:** remeasure/revalidate; cached acceptance cannot cross builds, targets, grants, revocation or clock validity. Recheck on dispatch/publication boundaries. Existing committed exact CAS receipts remain the durable recovery fact; do not strand a completed route because a later observation expires.
- **Uncertain cloud result:** keep uncertain journal entry and retained claim; poll/reconcile recorded handles and exact resource identity; never call a failed timeout “not created,” adopt a collision, delete an uncertain writer, or issue compensating mutations while the prior actuator may act.
- **Projection publisher stall, expired clock proof or wall regression:** refuse startup/admission/readiness/publication as appropriate; unchanged ETags never renew upstream validity. A process-local zero age is not a cross-host freshness proof.
- **Partial fleet or stop evidence:** no eligible endpoint publication/reader serving, no stop claim, no abandoned-pin release. Keep writer-only service and retained pins/compute debt visible. Missing ARM counts are unknown, not zero.
- **Quota/budget proof expiry:** no additional allocation/dispatch based on it; preserve already-running data and follow the approved policy for existing resources, not an invented destructive shutdown.

Trade-offs: conservative evidence expiry and no takeover improve safety at the cost of availability/manual recovery and idle cost; that is the intended refusal, not a defect to mask. Single reader app/private replicas minimize schema and service changes but require complete observation and cautious untargetable scale-in. Tenant ABAC prefixes reuse existing storage but depend on correct effective grants and complete nonnested prefix inventory; they do not isolate mutually hostile readers within the same tenant. The Job's admin EmptyDir makes its audit log ephemeral; the durable Blob journal must remain authoritative and any additional audit persistence must reuse existing storage (`deploy/azure-container-apps/ha/templates.ps1:717-728`, `:824-845`). No new dependency is proposed.
