## Required behaviour

1. **Strip inbound** `x-vlite-epoch` in `request_headers` (only that name; do not
   blanket-strip `x-vlite-*`). A caller can never forge a stamp toward a backend.
2. **Check before exposing anything.** In `forward`, after the loop has chosen
   `upstream` and **before** `tokio::spawn(pump(..))` or building the response:
   - Compute the outgoing headers with `response_headers` first, and read the
     stamp from those **effective** headers, so `Connection: x-vlite-epoch`
     nomination removes the stamp and the response is then refused as missing.
   - Only when `target.epoch` is `Some`: require exactly one `x-vlite-epoch`
     value that is a canonical decimal u64 >= 1: ASCII digits only, 1-20 chars,
     no sign, whitespace, comma/list, or leading zero, no overflow. Duplicates or
     malformed values count as missing (`EpochRefusal::Missing`).
   - Freshest directory: re-read `self.feed.current()` and the tenant's record.
     If the record disappeared, changed `lineage`, or control state is unusable,
     fail closed (`EpochRefusal::Stale` semantics). Otherwise
     `expected = max(target.epoch, current record epoch)`.
   - Call `gateway::check_epoch(Some(expected), stamped)`. Newer stamps are
     accepted (directory lag). On refusal drop the upstream response (no body is
     streamed), log a `gateway_upstream_failed`-style event with code
     `backend_epoch_stale` (never the header value of an unauthenticated
     source beyond the parsed integer), and return `refusal.error(target.operation)`:
     read => 503 `backend_epoch_stale`; write => the existing ambiguous-write 502
     (`write_outcome_unknown`). **Never retry or fall back** after an epoch refusal.
   - When `target.epoch` is `None` (shared-pool), behaviour must be byte-identical
     to today: no parsing, no extra feed read, no header changes.
3. Keep the backend's `x-vlite-epoch` in the client response (it already passes
   `response_headers`).
4. Remove the `dead_code` allowances that become unnecessary.
