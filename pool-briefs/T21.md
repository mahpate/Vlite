## Scope

One new integration test file with `#![cfg(feature = "server")]`
(auto-discovered; no `Cargo.toml` change). Drills use only the shipped
binary, the REST API, Azurite and an in-test TCP fault proxy.

1. A small std-only TCP fault proxy (`std::net`, threads, no new crate):
   listens on `127.0.0.1:0`, forwards to the Azurite host:port, and exposes
   `cut()` (refuse new connections and shut down open ones) and `restore()`.
   SharedKey signatures do not cover the host, so a proxied path-style
   endpoint `http://127.0.0.1:<proxy>/devstoreaccount1` works.
2. Repeatability: `VLITE_CHAOS_ITERATIONS` (default 1, max 20) repeats each
   drill; `VLITE_CHAOS_SEED` (default: time-derived) chooses kill/cut delays
   with a tiny std-only xorshift. Print the seed at the start of every
   drill and in every assertion message.

## Required behaviour (one `#[test]` + `#[ignore]` per drill)

- D1 `chaos_reader_killed_mid_apply_restarts_from_verified_position`
  (TEST-015/TEST-006): writer + archive, reader ready; record the applied
  sequence S. Insert more vectors, and while the next archive is applied,
  kill the reader (`Child::kill`) after a seeded delay. Restart it on the
  same follower dir: it becomes ready, its applied sequence is >= S, and
  every vector it serves exists on the writer with equal values. It never
  returns 2xx data with `x-vlite-applied-age-ms` above the staleness bound.
- D2 `chaos_blob_outage_fails_reader_closed_and_recovers` (TEST-009,
  fail-closed): the reader's target goes through the proxy. `cut()`; within
  staleness bound + 2 poll intervals + 5 s every data read is 503
  `reader_stale` or `reader_apply_failed`, never stale 2xx. `restore()`;
  the reader is ready again and its sequence advances after the next
  archive.
- D3 `chaos_writer_killed_during_archive_never_publishes_a_gap` (TEST-009,
  partial uploads at process level): the writer's target goes through the
  proxy. Insert vectors, then during an archive window either kill the
  writer or `cut()` the proxy (seeded choice). Restart the writer on the
  same database and admin dir (restore the proxy), insert more, and wait
  for the next archive. A reader started afterwards and an existing reader
  see monotonic applied sequences, eventually reach the writer's latest
  data, and never serve a vector set that skips an acknowledged write that
  is older than one that they do serve.
- D4 `chaos_failover_report_refuses_without_authority` (TEST-008 refusal
  path): on the drill target, `vlite-server failover report --target-file
  <t> --shared-key-file <k>` exits non-zero with error code
  `failover_authority_missing`. Read the exact stdout/stderr contract from
  `tests/server_failover_cli.rs` and `src/server/failover.rs`.

Blocked, do NOT add placeholder tests: TEST-007 (double writer), TEST-014
(paused writer after promotion) and the TEST-008 loss-report match need a
runtime path that creates/claims `<prefix>authority.json`. That path is not
wired (writer startup claim is outside ITEM-024 serving wiring). List them

Rules: no fixed sleeps for correctness (use `eventually` with bounded
timeouts), unique containers per run deleted on drop, every child process
killed on drop. If a drill exposes a product bug, do not change `src/`:
keep the failing assertion and describe it under `FINDING:` in the commit
