## Owner constraints (binding)

- HA is strictly **opt-in**: `-EnableHa` switch required; without it
  `deploy.ps1` refuses before any Azure call. The current single-ACA deployment
  (parent scripts, app `vlite-app`, env `vlite-env`, share `vlite-data`, its
  `admin-token` secret) must be untouchable: refuse any HA name equal to or
  adopting a parent singleton app/environment/share, and refuse resources not
  tagged `vliteHaDeployment=<id>` (ownership check before update).
- **Secrets use native ACA app secrets the same way the singleton already does
  for `admin-token`** (owner: "currently ACA also have the credentials for admin
  token etc. we should use in same way"). Generation-suffixed immutable names
  (e.g. `gw-seed-g7`), projected as files under `/run/vlite` via a
  `storageType: Secret` volume with explicit `secretRef`/`path` items (never
  mount-all). No secret values in argv, logs, tags, or the repo. The gateway
  never receives the admin token.
- No default image: `-Image` required and must be a digest reference
  (`...@sha256:<64 hex>`).

## Required behaviour

`templates.ps1` — pure functions returning hashtables (no I/O):
`New-VLiteHaGatewayTemplate`, `New-VLiteHaWriterTemplate`,
`New-VLiteHaReaderTemplate`, `New-VLiteHaGatewayConfig` (JSON-able hashtable
with exactly the `gateway_mode.rs` `GatewayFile` fields: `bind`,
`allow_remote`, `control_state`, `s_ctl_ms`, `poll_interval_ms`,
`max_replicas`, `envelope_lifetime_ms`, `public_key_bundle_file`,
`signing_key_file`, `active_kid`, `readiness_propagation_ms`,
`drain_timeout_ms`, `max_request_bytes`, `max_in_flight`,
`upstream_timeout_ms`, `max_buckets` — verify against the source, no extra
keys), `New-VLiteHaTrustConfig` (exactly `gateway_trust.rs` `TrustFile`:
`audience`, `public_key_bundle_file`, `control_state`, `s_ctl_ms`,
`poll_interval_ms`, `skew_ms`, `max_lifetime_ms`, `readiness_propagation_ms`),
`New-VLiteHaReaderApplyConfig` (`target_file`, optional `shared_key_file`,
`follower_dir`, `capacity_bytes`, `staleness_bound_ms`, `poll_interval_ms`),
and `Test-VLiteHaParameters` (validation, throws with a clear message).

- Gateway: `vlite-server gateway --config /run/vlite/gateway.json`; external
  ingress, `allowInsecure:false`, `transport: http`, target port 8080,
  `activeRevisionsMode: Single`, no sticky sessions, min replicas >= 2,
  **mandatory** max (no default, >= min, <= 1000) equal to config
  `max_replicas`, HTTP concurrency scale rule, no data volume, projected
  files: signing key, public bundle, gateway config, control target.
- Writer: `vlite-server /data/vectors.vlite --serve-mode writer --bind
  0.0.0.0:8080 --allow-remote --gateway-trust-file /run/vlite/trust.json
  --durability full`; internal ingress; min=max=1; **never**
  `--create-if-missing` (a separate explicit `-InitializeTenant` path may add
  `--create-if-missing <dims> --create-format <n>` only for a brand-new
  tenant, and the test proves restart manifests never carry it); no
  `VLITE_ADMIN_DIR`. Writer storage is an Azure Files share; refuse unless
  `-AllowUnqualifiedWriterStorage` is given and mark such deployments
  non-production in tags/output (Azure Files is not power-loss qualified).
- Reader: `vlite-server /data/served/database.vlite --serve-mode reader --bind
  0.0.0.0:8080 --allow-remote --gateway-trust-file /run/vlite/trust.json
  --reader-apply-file /run/vlite/reader.json`; internal ingress; EmptyDir
  volume at `/data` (never the writer share); min >= 1, mandatory max; no
  create/durability/group-commit/admin-dir/grpc flags. Readers are deployed only
  with `-EnableReaders`; default routing stays writer-only.
- Probes on all apps per t4 §6 (startup/readiness `/ready`, liveness
  `/health`), explicit `terminationGracePeriodSeconds`; enforce
  `grace_ms > readiness_propagation_ms + drain_timeout_ms + SafetyMarginMs`.
- Poll interval > 0 and < `s_ctl_ms`; all timing inputs required (no guessed
  production defaults; `parameters.example.json` uses obvious placeholders).
- Tags: `vliteHaDeployment=<id>`, `vliteHaRole=gateway|writer|reader`.

`deploy.ps1` — parameters per t4 §4 table; refuse without `-EnableHa`; check
`az account show` subscription equals `-SubscriptionId` and never switches it;
ownership checks; generation-suffixed secret names from `-SecretGeneration`;
local state under `$HOME/.vlite/azure-ha/<subscription>/<rg>/<deployment>`
created with a private-directory helper (missing original material on rerun is
a hard refusal); apply order: writer → readers (if enabled) → gateway last;
writer update first deactivates **all** active revisions and waits until every
revision has zero replicas (timeout → throw, no automatic rollback, never
reactivate an old revision); each manifest written to a private temp file and
removed in `finally`; `containerapp create|update --yaml <file>` chosen by
existing owned state. Secret rotation (t4 §5 order) may be implemented as a
`-Rotate` stage machine or documented as manual steps in README if it does not
fit — never blindly PUT the authority object and never delete old secrets while
a revision still references them.

min=max=1, no `--create-if-missing` on restart, init path only with

`README.md` — opt-in boundary, prerequisites (zone-redundant
