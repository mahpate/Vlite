## What to run (native Windows, no Docker, no WSL)

1. Start Azurite's Blob service natively with Node, data OUTSIDE the
   checkout:
   ```powershell
   $data = Join-Path $env:TEMP "azurite-t20-$(Get-Random)"
   New-Item -ItemType Directory $data | Out-Null
   $az = Start-Process -PassThru -WindowStyle Hidden npx -ArgumentList @(
     '--yes','azurite-blob','--blobHost','127.0.0.1','--blobPort','10010',
     '--location',$data,'--skipApiVersionCheck','--disableTelemetry','--loose')
   ```
   Wait until `Test-NetConnection 127.0.0.1 -Port 10010` succeeds (allow up
   to 120 s for the first npx download). Record the Azurite version
   (`npx --yes azurite-blob --version`). If port 10010 is taken, use any free
   port and adjust the endpoint below.
2. `$env:VLITE_AZURITE_BLOB_ENDPOINT = 'http://127.0.0.1:10010/devstoreaccount1'`
3. Build once: `cargo build --features server --tests --bins` (record time).
4. Run each ignored test separately, with `--nocapture`, and record pass or
   fail and wall time for each:
   ```
   cargo test --features server --test reader_apply_azurite -- --ignored --nocapture
   cargo test --features server --test gateway_azurite -- --ignored --nocapture
   cargo test --features server --test cloud_backup_azurite -- --ignored --nocapture
   ```
5. Run `reader_apply_azurite` two more times (three runs in total) to show
   whether it is stable. Record each result and wall time.
6. Offline regression controls (no Azurite needed):
   ```
   cargo test -q --features server --test server_reader_apply_cli
   cargo test -q --features server --test server_failover_cli
   cargo test -q --features server --test server_serve_mode
   ```
7. Stop Azurite (`Stop-Process -Id $az.Id`, plus any child `node` process
   whose command line contains `azurite-blob` and `10010`; stop by process
   id only) and delete `$data`.

## If a test fails

Do not edit product code or tests. Capture the failing assertion, the last
200 lines of its output (never print the shared key or bearer tokens; the
tests do not print them, so do not add printing), and your diagnosis with
file and line references: product defect, test defect, or environment.
If `reader_apply_azurite` fails only on timing, say which wait expired and
by how much.

## Report contents

- Machine, OS, Rust (`rustc -V`), Node and Azurite versions; checkout SHA.
- A table: test, run number, result, wall time.
- For each failure: assertion, excerpt, diagnosis.
- A one-line verdict: "TEST-006 live: PASS (3/3)" or the precise failure.
- Confirmation that `git status --short` shows no changes in the checkout
  and that Azurite was stopped and its data deleted.
