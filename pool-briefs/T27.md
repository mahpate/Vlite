## Background

ITEM-030 was reopened by T24b: under `--gateway-trust-file` the HA writer
refuses `VLITE_ADMIN_DIR`, so it has no managed admin directory and no way
to configure cloud backup / archive (the REST configure route needs the
admin dir). Without an archive the authority head never advances and
readers cannot follow. The owner-approved decision is ITEM-041 option (a):
a writer-only startup flag that reads a cloud backup policy JSON file and
configures the existing cloud backup runtime in a private directory, with
no new dependency, no new REST route and no new environment variable. ACA
app secrets mounted under `/run/vlite/` carry the file, the same way the
admin token and trust files are carried today.

## Existing API to reuse (do not reimplement)

- `backup_policy::read_limited` + `Policy` (`deny_unknown_fields`) +
  `Policy::validate()` for parsing; `refusal_for_policy` via `configure`.
- `backup_policy::Runtime::open`, `Runtime::configure(policy,
  &Handle::new(&service), now)`, `Runtime::run_now`, `check_authority`.
- `AdminControl.cloud.set` + the existing `configure_cloud` branch and
  `service.ops.cloud_changed()` for scheduling.
- `WriterAuthority` (`writer_fence.authority()` -> `(store, claim)`,
  `store.verify_writer(claim)` -> `.record.installation_id`), or
  `check_authority(&target, None)` returning the observed installation.
- `logs::stderr` for startup messages (`Handle::audit` no-ops without an
  admin dir).

## Scope

1. New flag `--archive-policy-file <json>` on `vlite-server` (no
   environment variable). Valid only with `--serve-mode writer` and
   `--authority-target-file`: add it to the authority-options condition so
   the existing "authority options require ..." errors fire, and add it to
   the `authority_options` list. Document it in USAGE. Refuse it together
   with `VLITE_ADMIN_DIR` / a managed admin dir ("invalid_arguments:
   --archive-policy-file is for writers without VLITE_ADMIN_DIR; use PUT
   /v1/admin/cloud-backup") so there is exactly one configuration source.
2. Parse at startup (before binding) with `read_limited` (64 KiB cap),
   `Policy` and `validate()`. Bad JSON, unknown fields, out-of-range values,
   `enabled:false`, or `archive.enabled:false` fail startup with a clear
   `invalid_arguments:`/`archive_policy_invalid` message and a non-zero
   exit before listening. (An archive policy that archives nothing is a
   misconfiguration for an HA writer.)
3. The policy `target` must equal the writer's authority target on
   `account`, `container`, `coordination_container`, `prefix` and
   `endpoint` (the same fields `check_authority` compares; `client_id` and
   `auth` are not compared there). Mismatch fails startup with
   `writer_authority_target_mismatch`. The authority target file is the
   same `cloud_backup::Target` JSON the deploy writes as
   `archive-target.json`.
4. Runtime directory: a private sibling of the database,
   `<database path>.cloud-backup/` (create with owner-only permissions on
   Unix using the existing private-dir helper if one exists). Carry it as a
   `#[doc(hidden)]` `ServerOptions` field (for example
   `archive_runtime: Option<(PathBuf, Policy)>` or separate fields) so the
   public API is unchanged; `api_reference.py` skips `#[doc(hidden)]`.
   In `configured_with_control`, when there is no admin dir and the field
   is set, `Runtime::open(dir)`, `control.cloud.set(...)` so the existing
   branch calls `configure_cloud`.
5. Installation seeding: add `pub(super) fn seed_installation(&self, id)`
   to `Runtime`, writing `INSTALLATION` through `write_atomic` after
   `valid_installation`; it is a no-op when the same id exists and refuses
   a different existing id (`writer_authority_installation_mismatch`).
   Seed from the authority record's `installation_id` before calling
   `configure`, otherwise `configure` generates a random id and
   `check_authority` fails. Then `configure(policy, &Handle::new(&service),
   now)` and `service.ops.cloud_changed()`.
6. First-base gap (required): `archive_cycle` archives the latest
   published set, and `next_run` is due at `max(last_attempt,
   policy_updated) + interval_secs*1000`, so a fresh configure with a long
   `interval_secs` publishes no base for days. When the runtime has no
   published set at startup, run one initial backup (`run_now`) on a
   blocking task after the router is built and before/while serving,
   logging success or failure to stderr; a failure must not crash the
   server (the regular schedule retries) but must be visible in
   `GET /v1/admin/cloud-backup`-equivalent status and stderr. Do not run it
   when a published set already exists (restart case).
7. Every startup error after the service is built follows the existing
   cleanup order (`stop_apply`, `service.close().await`, `stop_trust`).
8. Templates: in `New-VLiteHaAppTemplate`'s writer branch add
   `$files['archive-target']='archive-target.json'` and
   `$files['archive-policy']='archive-policy.json'` and args
   `--authority-target-file /run/vlite/archive-target.json
   --archive-policy-file /run/vlite/archive-policy.json`. Add a new builder
   `New-VLiteHaWriterArchivePolicy -Config` that projects the policy
   (target = the writer archive target including `client_id`, `enabled`
   true, `interval_secs`, retention fields, `drill_every`,
   `archive{enabled:true, interval_secs}`) from config keys with defaults
   matching `backup_policy.rs` (interval 3600, keep_sets 3, keep_days 30,
   orphan_grace_hours 24, drill_every 24, archive interval 300), validated
   in the `Assert-VLiteHaInteger` style with the Rust ranges
   (`interval_secs` 300-604800, `keep_sets` 3-1000, `keep_days` 30-3650,
   `orphan_grace_hours` 1-720, `drill_every` 0-100, archive interval
   60-86400). Add a writer assertion in the template that the mounted
   policy equals that projection.
9. `ha/deploy.ps1`: add `"writer-archive-policy-$g"` to `$files`; in the
   writer `$roleSecrets` case add `archive-target-$g =
   $secrets["writer-archive-target-$g"]` and `archive-policy-$g =
   $secrets["writer-archive-policy-$g"]`. The replacement writer inherits
   them. `Assert-VLiteHaQualification` MUST keep throwing (live HA stays
   gated); only update the tail of its message so it no longer claims a
   missing CLI flag (e.g. "...the writer archive policy is mounted from
   app secrets; live qualification is still pending."). Do not change the
   single-app deploy at `deploy/azure-container-apps/deploy.ps1`.
10. Docs: `docs/HA-ACA.md` — for gateway-trust writers, document
    `--archive-policy-file`, its validation, the private runtime dir, the
    seeded installation id, the initial base, and that `authority init`
    still comes first using the installation id the operator chooses (state
    the exact order). Keep the REST path for admin-dir writers.
    `ha/README.md` — the new secret and mount.
