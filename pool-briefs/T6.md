## Required behaviour (types/names are yours; keep them small)

1. **Selection.** Tenant `T` is the existing immutable 32-hex tenant ID; select by
   exact tenant field (users, credentials, bindings) — never by display name or
   substring. Refuse a deleted tenant; carry a suspended tenant's suspension.
2. **Sanitized inventory** `TenantState` built by filtering **before**
   serialization (never build a full bundle and filter afterwards):
   tenant record (limits), tenant-bound users (normalized name, role, disabled,
   graph scopes — no account ID, version, hash, session), tenant-bound
   credentials (principal ID, ops, graph/collection scopes **with source
   collection IDs** via a new typed accessor, limits, rate, absolute expiry,
   revoked/expired state — no hash, no lineage secret material), configured
   bindings with `binding.tenant == T` (order, identity, scopes, read scopes,
   raw access, retirement, per-binding generation unchanged), and selected
   orphan records reported separately. Strict serde (`deny_unknown_fields`).
   Canonical digest: SHA-256 over length-prefixed fields (not `Debug`, not
   unordered maps).
3. **Migration-only rekey** `rekey_for_migration(state, target_lineage, now)`:
   for each credential **still active at `now`**, keep the nonsecret principal
   ID, mint a fresh random secret and hash (reuse the existing hashing/secret
   helpers in `credentials.rs`), preserve ops, scopes, limits, rate and absolute
   expiry. Produce two views per fresh credential (source lineage `L_s` and
   target lineage `L_d`) with the same hash/ID/limits. Expired/revoked entries
   never mint. Return the plaintext tokens once in a separate value that is
   never `Debug`/`Serialize` (redacting `Debug`), so they can be written to a
   private file later.
4. **Stale-grant refusal.** Given the target's collection `(stored name, id)`
   table, an explicit grant whose source collection ID differs from the target
   ID for the same stored name is refused (typed error naming the principal ID
   and stored name, no secrets). Wildcards stay wildcards within T only.
5. **Users import.** Reuse `users::rekey_import` semantics: imported tenant users
   get fresh account IDs, unusable password hashes, disabled; the fresh admin name
   must not collide with an imported username (refuse/choose per existing rules).
6. **Bindings.** Build the target reservations with
   `Bindings::new(selected_set).with_orphans(selected_orphans)` (see
   `src/server/reserved.rs` and `src/memory/binding*.rs`), compute the routing
   fingerprint B exactly as existing code does, and also a full SHA-256 of the
   reservation-name set for evidence (orphan-only B = 0 must still yield a
   non-empty reservation digest). Never bump per-binding generation; never adopt
   an orphan or invent a grant.
7. **Refusals:** unknown sidecar entries / unknown schema fields, a selected open
   import job (if visible from the state you are given), deleted tenant,
   cross-tenant binding, corrupt orphan record. Webhooks are never selected.
