## Required behaviour

1. `WriterObservation { sequence: u64, observed_unix_ms: u64 }` — optional,
   operator-supplied last observed position of the old writer.
2. `LossReport` (Serialize, deterministic): scope id, lineage, current epoch,
   revision, phase, short writer-id prefix (8 chars max, never the full id),
   the archived position taken **only** from the authority (`head`, else
   `base`, else none), optional `ArchiveStatus` cross-check fields
   (last checkpoint sequence/time, failures, last error code), the optional
   observation, and `loss`: `Known { commits }` only when an observation is
   supplied and `observation.sequence >= archived`; otherwise `Unknown`.
   Never infer progress from a configured interval (Q-4); never understate
   (AC-009). If `ArchiveStatus.last_checkpoint_sequence` exceeds the authority
   head, report it as unpublished (lost), not as archived. `report_id` = lower
   hex SHA-256 of the canonical serialized report without `report_id`.
3. `build_report(&AuthorityStore, Option<&ArchiveStatus>, Option<WriterObservation>)
   -> Result<LossReport, FailoverError>`: one fresh `read`; validate the record.
4. `LossReport::render() -> String`: stable human text stating the archived
   sequence/time, the observed position or "unknown", the loss, and that all
   commits after the archived sequence are lost. No tokens or data.
5. `FailoverAck { report_id, expected_epoch, expected_revision,
   old_replicas: u64 }` (infrastructure fence: replicas of the old writer app
   after the operator stopped it).
6. `execute(&AuthorityStore, &LossReport, &FailoverAck)
   -> Result<Observed, FailoverError>`, checks in this order, each refusing
   without any PUT: `old_replicas != 0` → `FenceUnconfirmed`; `report_id`
   mismatch → `AckMismatch`; ack E/revision differ from the report →
   `AckMismatch`; then one fresh `read`; if the authority epoch/revision moved
   since the report → `ReportStale` (fresh report required). Then exactly one
   `prepare_transfer`. Map `Lost`/`HeadMoved` → `Conflict` (fresh report
   required), `Unresolved` → `Indeterminate`, `Unavailable` → `Unavailable`,
   `Missing` → `Missing`, `Invalid` → `Invalid`. Never retry or loop.
7. `FailoverError::code()` stable strings: `failover_fence_unconfirmed`,
   `failover_ack_mismatch`, `failover_report_stale`, `failover_conflict`,
   `failover_indeterminate`, `failover_authority_unavailable`,
   `failover_authority_missing`, `failover_authority_invalid`.
8. Events: `failover_prepared` (old E, new E, report id) and
   `failover_refused` (code). No secrets.

## Tests (test-first, `#[cfg(test)] mod tests` in `failover.rs`)

Fake `Memory`, deterministic, no sleeps. At least:
`failover_report_uses_authority_head_not_interval`,
`failover_report_loss_known_only_with_observation`,
`failover_report_unpublished_checkpoint_is_lost`,
`failover_report_id_is_deterministic`,
`failover_refuses_without_zero_replicas` (no PUT: compare `raw` bytes),
`failover_refuses_ack_mismatch`,
`failover_report_stale_after_head_advance` (old writer advances head after the
report → `ReportStale`, no PUT),
`failover_conflict_on_concurrent_transfer` (hook a competing
`prepare_transfer` before our PUT → `Conflict`, exactly one PUT attempted),
`failover_unknown_applied_succeeds_by_readback` (`Fault::After`),
`failover_unknown_unreadable_is_indeterminate` (`Fault::After` PUT plus a
refused GET),
`failover_prepares_recovering_epoch_plus_one` (new record: E+1, base = old
head, writer none, phase recovering; a new `claim` then succeeds and the old
claim's `advance_head` fails).
