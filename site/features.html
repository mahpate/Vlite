Storage and records

Hybrid retrievalDense + BM25 or dense + sparse fusion using weighted reciprocal rank fusion.
Grouped resultsGroup nearest matches by a metadata field with a per-group hit cap.

Geographic searchGeoPoint metadata, Haversine-radius filtering and ranking by vector or geographic distance.

Indexes and concurrency

Search acceleration and concurrent access
FeatureSupport and requirements
Rebuildable HNSWDeterministic construction, configurable graph/search budgets and bounded mutation buffering.
Scalar-u8 quantizationCompressed traversal codes with full-precision candidate reranking. Original vectors remain resident.
Metadata indexesEquality and range indexes with full-filter rechecks; rebuilt on reopen/settings changes.
ANN restart snapshotsOptional validated graph cache tied to database state. Not available for encrypted databases.
Disk ANNOptional graph/vector sidecar with a bounded node cache. Builds still need in-memory HNSW capacity; no metadata/expiry filtering.
Index quality and memorySampled recall against exact results, index identity/readiness and component-level memory diagnostics.
Parallel exact scansNative Rayon scans above workload thresholds; not on WebAssembly.
Concurrent server readsShared read access and exclusive writes; bounded committed snapshots for eligible exact queries.
Shared embedded readersMultiple read-only processes under shared file locks, excluding a writer. Reopen to see later commits.
Committed read snapshotsRust handles for bounded exact search, get and browse outside the owner lock.
Background rebuildsExplicit start, poll, cancel and maintenance controls; optional server scheduling and retry backoff.
Durable group commitOptional shared sync for bounded concurrent record writes while retaining separate atomic frames.
Read-lock policy--lock-held-reads trades snapshot copying for holding the owner read lock during exact scans.

Command-line tools and agents

  • Interactive/scripted shell: query records and collections; use --read-only to disable writes. The shell still takes an exclusive file lock.
  • Offline maintenance: inspect, verify, backup, restore, compact, upgrade and re-encrypt.
  • Import: CSV, JSONL, pgvector text and supported FAISS input; optional Parquet/Arrow IPC with import-formats.
  • Search quality: exact-oracle recall, configuration/database comparison and bounded index evaluation.
  • Index tuning: workload-based configuration advisor with memory/recall trade-offs.
  • Benchmark harnesses: seeded or external vectors, mixed mutations and raw timing/memory reports.
  • MCP server: stdio tools, shared-lock read-only access by default and explicit writable mode.
  • Agent skills: RAG, MCP, operations and index tuning workflows.

Requirements and boundaries

  • The live dataset must fit in RAM. Disk ANN bounds its node cache, not the database's overall memory footprint.
  • One exclusive writer or multiple shared read-only owners per file; no simultaneous embedded writer/readers across processes.
  • File creation defaults to V3; collections/checkpoints need V4+, and expiry/extended vectors need V5. Upgrades are explicit.
  • No cross-collection transactions, distributed consensus, automatic network replication or inner-product ANN.
  • Plaintext ANN sidecars are unavailable with encrypted databases. TLS and access controls are separate from file encryption.
  • Embeddings come from your application/provider. VLite does not bundle a semantic model runtime.
  • Recovery checks do not certify physical power-loss behavior; filesystem and hardware guarantees still apply.
Experimental source capabilities

Property-graph storage, bounded graph reads and graph-aware maintenance require the non-default graph build feature. They are not included in distributed release artifacts and are not part of the supported catalogue above. See graph-file requirements and limits.
