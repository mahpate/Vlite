## Background

The owner approved measurements on separate temporary apps that are cleaned
up afterwards. MEAS-002 so far has only a local, Blob-free number. A sibling
task (T30b) extends the temporary-ACA harness and will run your binary inside
one ACA job container. That container has a user-assigned managed identity
with Storage Blob Data Contributor on a temporary storage account whose two
containers already exist. This task builds the driver only. Never run it
against Azure; use only a local Azurite endpoint if one exists.

## Shared contract (T30b depends on it exactly)

- Cargo: `[[example]] name = "ha-meas002"`, `path =
  "benchmarks/ha_meas002.rs"`, `required-features = ["server"]`. Add no new
  dependency (`reqwest` blocking+json, `serde_json`, `base64`, `tokio` are
  already enabled by `server`; dev-dependencies such as `tempfile` are
  available to examples). `Cargo.lock` must not change.
- Command line (all `--name value`; unknown or repeated flags fail):
  - `--server <path>` (else env `VLITE_MEAS002_SERVER`; required).
  - `--target-file <path>`: target JSON with `account`, `container`,
    `coordination_container`, `prefix`, `auth`, plus `client_id` (managed
    identity) or `endpoint` (emulator). Else env `VLITE_MEAS002_TARGET`
    holding the JSON text itself. Exactly one source; neither is an error.
  - `--shared-key-file <path>`: required with `emulator_shared_key`, refused
    with `managed_identity`.
  - `--duration-secs` (60..=3600, default 360), `--rate` commits per second
    (1..=200, default 20), `--archive-interval-secs` (60..=86400, default
    60), `--staleness-bound-ms` (1000..=3600000, default 300000),
    `--reader-poll-ms` (100..=60000, default 1000, must be below the bound),
    `--observe-ms` (50..=5000, default 100).
  - `--work-dir <abs path>` (default: a fresh temp dir removed at exit).
- The driver appends a random 16-hex run id plus `/` to the target `prefix`
  (`prefix` may be empty; keep the result valid for `validate`), so
  repeated runs never share Blob state.
- Exit 0 and print exactly one compact JSON object on stdout on success;
  diagnostics go to stderr; any failure exits non-zero with no stdout.

## Scope

`benchmarks/ha_meas002.rs`, a single program:
1. Create the v4 database (2 dimensions); write target and policy JSON
   (`{"target":..,"enabled":true,"interval_secs":604800,"drill_every":0,
   "archive":{"enabled":true,"interval_secs":<archive-interval>}}`).
   Preflight (role assignments on a fresh account can take minutes to
   propagate): run `authority show` every 15 s for at most 600 s until it
   exits non-zero with stderr JSON `{"error":"writer_authority_missing: .."}`
   (store reachable and authorized, no head yet). A successful `show` means
   the prefix is not fresh: fail. Any other outcome at the deadline: fail,
   naming only the error code. Record `preflight_attempts` and
   `preflight_ms` in the output. Then run `authority init` (random
   installation id, scope id `meas002`) once; never retry `init`.
2. Start the writer as the HA template does plus `--insecure-local --bind
   127.0.0.1:0` (emulator only: `--authority-shared-key-file` and env
   `VLITE_CLOUD_BACKUP_SHARED_KEY_FILE`). Strip inherited `VLITE_*` vars.
3. Start one reader with a random 32+ character `VLITE_AUTH_TOKEN`; wait for
   `/ready` 200 (deadline: 2 x archive interval + 120 s).
4. Writer thread: open-loop schedule at `--rate`; `PUT /v1/vectors/{i}` with
   `{"vector":[i,1]}` for i = 1..; record send/ack instants and failures and
   schedule lateness.
5. Observer thread: every `--observe-ms`, `GET /v1/database` on the reader;
   commit i is visible at the first observation with `records >= i`
   (single sequential writer, prefix-consistent apply; verify that claim by
   also requiring `x-vlite-applied-sequence` to be non-decreasing and
   record any regression). Count statuses keyed `"<status>"` or
   `"<status>:<error code>"`; record the applied-age header.
6. Head thread: every 1000 ms run `authority show`; record when
   `head.sequence` advances (publish instants, 1 s resolution).
7. After the write phase, keep observing until every acked commit is
   visible or 2 x archive interval + 120 s pass; then stop children (kill on
   drop, including panic and error paths) and print the JSON.

Output `"schema":"vlite-meas002/1"` with: `platform`
(`azure_container_apps_job` when `CONTAINER_APP_JOB_NAME` and
`CONTAINER_APP_JOB_EXECUTION_NAME` are both set, else `local`), `source`
(`{revision, dirty_paths}` from `VLITE_RESOURCE_SOURCE_REVISION` and
`VLITE_RESOURCE_SOURCE_DIRTY_PATHS` if both set, else `null`; never run
git), `config` (every effective option and the `auth` kind; no secrets,
key, token, account key or client id), `host` (`available_parallelism`,
OS), `commits` (`attempted`, `acked`, `failed`, `visible`,
`not_visible_by_deadline`), summaries `ack_latency_ms`, `ack_to_visible_ms`,
`publish_to_visible_ms` (per head advance: first observation covering it),
`applied_age_ms` (each `{count,min,p50,p90,p95,p99,max,mean}`,
nearest-rank, `null` when empty), `reader_status_counts`,
`applied_sequence_regressions`, `schedule_lateness_ms_max`, `head_advances`
(at most 240 entries `{at_ms, sequence}`), `elapsed_ms`. No unbounded
arrays. Report only what was observed.
