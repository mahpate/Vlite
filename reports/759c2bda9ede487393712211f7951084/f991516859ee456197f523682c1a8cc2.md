## 2. Top 15 findings, ranked

Effort: S = under one day, M = several days, L = larger redesign. Risk describes regressions from the recommendation.

1. **Suspension understates consequences.** `admin-tools.js:502` says "Every API key ... is refused immediately" but omits user sign-outs documented in `docs/CONSOLE-ADMIN.md:69-72`. Add: "Users are signed out and cannot sign in until you resume this tenant. Data is kept." **S; low risk.**

2. **First-account guidance misses the essential role.** `app.js:209-210`: "No user accounts yet ... add people"; `index.html:654` defaults to "Viewer: read and search", whereas `docs/CONSOLE.md:19-20` requires a super admin. Replace setup guidance with "Use the admin token, then create your first Super admin account in Administration > Users & access." **S; low risk.**

3. **Account editing requires transcription.** `index.html:652`: "User ID ... copy it from the list"; `admin-tools.js:419`: "Enter a user's ID above". This makes ordinary account maintenance an API exercise. Render selectable user rows with "Edit user" and a separate "Add user" form. **M; medium risk: preserve graph/tenant grants.**

4. **Confirmation lacks an accessible name.** `index.html:859-862` has `<dialog id="confirmation">`, "Confirm operation", and generic "Confirm", without labeling relationships. Associate heading/body with `aria-labelledby`/`aria-describedby`; use action-specific buttons such as "Delete user". **S; medium risk: preserve cancel return values.**

5. **Recovery controls contradict the stated sequence.** `index.html:757` says "verify or drill it, then stage"; "Verify selected backup" appears after staging/restart selection at 766. Users must mentally reorder controls. Group "1. Choose backup", "2. Verify or test restore", "3. Prepare restored copy", "4. Use copy after restart". **M; medium risk: retain non-live restore semantics.**

6. **Routine settings require JSON.** `index.html:775` exposes "Backup schedule changes (JSON...)" and 804 "Automatic maintenance changes (JSON...)". Replace defaults with enabled/interval/retention fields; put raw JSON under "Advanced configuration". Label saves "Apply until server restart". **M; high risk: preserve merge/omission semantics.**

7. **API-key permissions expose wire names.** `index.html:679-685`: "search_build", "index", "collections", "diagnostics". These obscure authority. Use "Search and build missing indexes", "Build or rebuild indexes", "Create and manage collections", "Read query diagnostics"; retain wire values internally. **S; medium risk: avoid implying narrower grants.**

8. **Access/webhook setup overloads users with syntax.** `index.html:671-695` exposes wildcard scopes and "Optional tenant and usage limits"; 818 lists event identifiers inline. Use collection/graph/event checklists, a tenant picker, and collapsed "Usage limits". Label wildcard choices "All collections" / "All graphs". **M; high risk: faithfully preserve scope distinctions.**

9. **Historical recovery requires epoch arithmetic.** `index.html:784-785`: "Unix timestamp (milliseconds)" and "Target value (nonnegative safe integer)"; 787: "Create PITR copy". Offer date/time with explicit timezone, keep sequence under advanced options, and use "Prepare restored copy at this time". **M; high risk: exact timestamp conversion.**

10. **Change-feed paging starts with implementation jargon.** `index.html:626`: "Opaque cursor (blank starts retained history)"; 625 explains compaction/resync inline. Hide cursor behind "Resume from a saved position"; default action "Show retained changes". Keep resync warnings at the actual error. **M; medium risk: preserve whole-commit paging.**

11. **Metric labels require statistical knowledge.** `index.html:586-589`: "Request p50", "Request p95", "Search QPS", "Search p95 / mean". `observability.js:170` silently chooses percentile or mean. Use "Median request duration", "95th-percentile request duration", "Searches per second", and distinguish "Search duration: 95th percentile" from "average". **S; low risk.**

12. **Navigation hides purpose behind categories.** `navigation.js:18-35`: "Observability" and "Replication" under recovery; `index.html:105`: "Quick tour" inside account preferences. Use "Monitoring", "Export replication log", and a visible "Help & tour" action. Desktop: monitor/health/console require one selection; users/backups two; API keys/TLS/replication three. Mobile adds "Menu" (`index.html:64`). **S; medium risk: preserve deep links.**

13. **Generic/raw results obscure completion and emptiness.** `style.css:207,219`: "No response yet", "Nothing to show yet"; health/audit/backups use `<pre>` (`index.html:640,752,768`). Provide "Health checks passed", "No audit entries", and named backup rows; disclose "Technical response (JSON)". **M; medium risk: distinguish unavailable/loading/error/empty.**

14. **Quick tour assumes expert input too early.** `console-tools.js:942-947` routes "Add records" to bulk JSON and tells users "Paste JSON documents". Start with "Add one example record" and highlight "Fill example" (`index.html:184`); offer bulk import afterward. **S; low risk: tour must remain write-free.**

15. **Developer Console mixes passive inspection and active requests.** `index.html:838` says "Latest request only"; 840 "REST playground" exposes DELETE beside GET (841). Keep inspector primary; collapse "Send a custom API request" and "Read-only test scenarios". Use "Send DELETE request" when selected. **S; medium risk: retain mutation confirmations.**
