## Required behaviour (what the test must assert)

Test name: `reader_applies_archive_reports_position_and_fails_closed_when_stale`.

1. Skip cleanly (return early with an `eprintln!`) when
   `VLITE_AZURITE_BLOB_ENDPOINT` is unset, as the other Azurite tests do.
2. Writer: start `vlite-server` standalone (or `--serve-mode writer`) with
   `VLITE_ADMIN_DIR`, create the two containers, `PUT /v1/admin/cloud-backup`
   with the target and a policy whose archive is enabled at the minimum
   allowed interval (60 s; find in `backup_policy.rs` whether a shorter
   test-only trigger already exists and use it if so — do not add one), insert
   records, then `POST /v1/admin/cloud-backup/run` → 201 and wait until a
   `Published` set exists.
3. Reader: write a `ReaderApplyConfig` file (`target_file`,
   `shared_key_file`, absolute `follower_dir` with no dot components,
   `capacity_bytes` in 1..=1073741824, `staleness_bound_ms`, and
   `poll_interval_ms` > 0 and < the bound) and start
   `vlite-server --serve-mode reader --reader-apply-file <cfg>` serving
   `<follower_dir>/reader-a/database.vlite`, without `VLITE_ADMIN_DIR`.
4. Wait for `/ready` 200. Assert the records written before the set are
   served, and that read responses carry `x-vlite-lineage`,
   `x-vlite-binding-generation`, `x-vlite-applied-age-ms` and
   `x-vlite-applied-sequence` with numeric values.
5. Write more records on the writer; with `eventually` (bounded by
   archive interval + staleness bound + margin) assert they become visible
   on the reader and `x-vlite-applied-sequence` increases.
6. A mutation on the reader is refused with 403 `reader_mode`.
7. Staleness: stop the writer's archive (stop the writer process, or make
   the data container unreachable by deleting it) and assert that once the
   bound has passed, `/ready` and a data read answer 503 `reader_stale` (or
   `reader_apply_failed` if the apply loop reports a failure first; accept
   exactly these two codes and say which one in a comment).
8. Clean up both containers in a drop guard. Never print the shared key or
   admin token.
