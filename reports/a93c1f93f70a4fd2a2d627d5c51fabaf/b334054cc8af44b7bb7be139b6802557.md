## Static inspection and source evidence

This section is source reasoning, not additional executed validation. All line references are at HEAD `14804b9b512d95e91f4f9fa88d394215b558dec3`.

- [`Coordinator::view`, compaction lines 466-483](https://github.com/mahpate/Vlite/blob/14804b9b512d95e91f4f9fa88d394215b558dec3/src/server/compaction.rs#L466-L483) holds the state mutex while reading the fence and, when needed, recovery code. [`status`, lines 1999-2060](https://github.com/mahpate/Vlite/blob/14804b9b512d95e91f4f9fa88d394215b558dec3/src/server/compaction.rs#L1999-L2060) uses those captured values for reasons and response fields. The guarantee is specifically against an older journal paired with a newer fence; filesystem metadata and selection-file reads remain separately sampled.
- The [deterministic status test, lines 2321-2390](https://github.com/mahpate/Vlite/blob/14804b9b512d95e91f4f9fa88d394215b558dec3/src/server/compaction.rs#L2321-L2390) invokes `STATUS_AFTER_VIEW` after capture, changes the job, then establishes recovery. It checks the first response remains maintenance/non-recovery with the old job, and the next response reflects recovery and the updated job.
- [`Runtime::enabled`, lines 784-790](https://github.com/mahpate/Vlite/blob/14804b9b512d95e91f4f9fa88d394215b558dec3/src/server/backup_policy.rs#L784-L790) keeps uncertainty schedulable. [`claim_due_at`, lines 1003-1026](https://github.com/mahpate/Vlite/blob/14804b9b512d95e91f4f9fa88d394215b558dec3/src/server/backup_policy.rs#L1003-L1026) attempts settlement before clock reconciliation, due selection, or claiming the busy flag.
- The [configure route, lines 1732-1742](https://github.com/mahpate/Vlite/blob/14804b9b512d95e91f4f9fa88d394215b558dec3/src/server/backup_policy.rs#L1732-L1742) calls `cloud_changed()` before propagating `view?`. Moving error propagation before notification would reintroduce the tested failure.
- The assignment's hook description needs a minor factual distinction: the [runtime-only test, lines 2527-2559](https://github.com/mahpate/Vlite/blob/14804b9b512d95e91f4f9fa88d394215b558dec3/src/server/backup_policy.rs#L2527-L2559) uses thread-local `WRITE_FAULT` / `READ_FAULT`; the [asynchronous route test, lines 3312-3362](https://github.com/mahpate/Vlite/blob/14804b9b512d95e91f4f9fa88d394215b558dec3/src/server/backup_policy.rs#L3312-L3362) uses directory-keyed `DIR_FAULTS`, visible across its blocking worker and scheduler threads. This is appropriate to their different execution models, not a confirmed defect.
- [`Ops::ensure_thread` and `run_loop`](https://github.com/mahpate/Vlite/blob/14804b9b512d95e91f4f9fa88d394215b558dec3/src/server/ops.rs#L258-L346) explain the notification test: an initially disabled policy has no maintenance thread; uncertainty must make it eligible to start, and the worker retries claims with waits bounded at 500 ms. The test reads in-memory uncertainty while waiting, rather than issuing another request that could settle the policy itself.

## Findings, recommendations, and limits

**Product findings: none confirmed.** All reported regression variants were killed by assertions in the expected tests. There is therefore no unresolved product finding with a severity, reproduction, or suggested source fix.

Recommendations and trade-offs:

- Retain the deterministic post-view hook alongside end-to-end stress: it reliably kills the old response-ordering regression without depending on a scheduler race.
- Keep uncertainty in scheduler enablement and settlement in due claiming; these serve different purposes, and the mutants demonstrate why both are needed. Keep route notification before error propagation.
- Give future mutation experiments isolated target directories, or explicitly invalidate package artifacts before returning to clean-source testing. The artifact-reuse issue was detected and corrected here; fresh outputs cost additional compilation time but make provenance unambiguous.
- Run the same stress on the qualified Linux/local-ext4 profile before treating these Windows results as release-platform qualification. Do not infer universal flake freedom from zero observed failures.

**Required checks not run: none.** Formatting, clippy, both modules, the three named tests, reportable mutation checks, and all requested stress counts completed. No fixture-only substitute was used for the integration stress; it launched the real locally built server.

Additional scope not executed: Linux/ext4 validation, a full unfiltered crate test suite, release builds, and Azure/emulator backup integration. These were not required for this assignment; real Azure was explicitly forbidden. Native Linux execution was unavailable: `wsl --list --quiet` reported that Windows Subsystem for Linux was not installed, and no Docker executable was found. Installed cross-compilation targets do not establish a runnable Linux environment.

The task-specific temporary sources, binaries, caches, fixtures, and logs were removed after extracting the evidence above. Only this report was left in the checkout.
