## Background

The owner approved running measurements and SLO work "on separate apps"
that are "cleaned up after measurements". MEAS-007 measures the ephemeral
storage and resource evidence of the reader-apply probe per ACA vCPU tier.
Today the probe only runs locally. This task builds a one-command harness
that runs it as Manual ACA jobs in a brand-new temporary resource group,
collects the JSON through console logs, and always deletes the group.

The probe (`cargo run --release --features json --example ha-reader-apply
-- --resource-evidence`) is Linux-only, prints one pretty JSON document to
stdout and calls `rustc --version` and `df -kP` at runtime, so the image
must be a single-stage `rust:1.89-bookworm` image that keeps the toolchain.
It detects platform `azure_container_apps_job` from
`CONTAINER_APP_JOB_NAME` and `CONTAINER_APP_JOB_EXECUTION_NAME`. It reads
optional `VLITE_RESOURCE_RECORDS` (default 110000, <=2,000,000),
`VLITE_RESOURCE_DELTA` (300, <=100,000), `VLITE_RESOURCE_DIMENSIONS` (64,
<=1024; records x dimensions <=32,000,000), each a plain decimal >=1, and
`VLITE_RESOURCE_HOST_NOTE`. Provenance comes from
`VLITE_RESOURCE_SOURCE_REVISION` (40 lowercase hex) and
`VLITE_RESOURCE_SOURCE_DIRTY_PATHS`, which must be both set or both absent
(absent falls back to `git`, which the image does not have). Check the exact
encoding the probe expects for the dirty-path list and for "clean" before
choosing the wrapper's value; do not change the probe.

## Scope

1. `deploy/azure-container-apps/ha/measure.Dockerfile`: single stage
   `FROM rust:1.89-bookworm`, copying exactly the inputs of the `Dockerfile`
   `source` stage (lines 3-19), then
   `cargo build --locked --release --features json --example ha-reader-apply`.
   `ARG`/`ENV` `VLITE_RESOURCE_SOURCE_REVISION` and
   `VLITE_RESOURCE_SOURCE_DIRTY_PATHS` (refuse an empty or non-40-hex
   revision with a `RUN` check). Run as a non-root user. The entrypoint is a
   small `/usr/local/bin/vlite-meas` shell wrapper (written with `printf` or
   a heredoc in the Dockerfile) that runs the built binary
   `target/release/examples/ha-reader-apply --resource-evidence`, captures
   stdout to a temp file, and on success prints:
   `VLITE-MEAS BEGIN <sha256-of-gzip-bytes> <byte-count>`, then the
   gzip+base64 payload as numbered lines `VLITE-MEAS <seq> <chunk>`
   (76-character chunks, seq from 1), then `VLITE-MEAS END <line-count>`.
   On probe failure print `VLITE-MEAS FAILED <exit-code>` plus the last 50
   stderr lines prefixed `VLITE-MEAS-ERR ` and exit non-zero.
2. `deploy/azure-container-apps/ha/measure.ps1` (`#Requires -Version 7.2`,
   `$ErrorActionPreference = 'Stop'`, dot-sourceable: the main runs only
   when `$MyInvocation.InvocationName -ne '.'`). Parameters:
   `-SubscriptionId` (required unless `-Plan`), `-Location` (default
   `westus2`), `-Id` (lowercase alphanumeric 3-12, default random),
   `-Measurements` (only `MEAS-007` is accepted; anything else is refused
   as `not implemented`, never silently skipped), `-Tiers` (default
   `0.5,1,2`; allowed ACA consumption values 0.25..2 in 0.25 steps; memory
   is always `cpu*2Gi`), optional `-Records`/`-Delta`/`-Dimensions`
   validated against the probe limits above, `-OutDir` (required; must be
   outside the repository root and must not exist or be empty),
   `-Image` (skip the build and use this image), `-SourceRevision`
   (default `git rev-parse HEAD`), `-AllowDirty`, `-KeepOnFailure`, `-Plan`.
   - `-Plan` is fully offline: it prints the ordered list of `az` argument
     arrays it would run (with the subscription replaced by
     `<subscription>`) and returns them as objects; no Azure or git calls
     when `-SourceRevision` is given.
   - Resource names: RG `vlite-ha-meas-<id>`, env `vlite-meas-<id>-env`, ACR
     `vlitemeas<id>` (alphanumeric), identity `vlite-meas-<id>-id`, jobs
     `vlite-meas-<id>-c<tier without dot>` (for example `c05`, `c1`, `c2`).
     Refuse any name or RG that matches `asendme*`, `vlite-app`,
     `vlite-env` or `vlite-data`, and refuse if the RG already exists.
   - Tag the RG `vliteMeasurement=<id>`, `vliteMeasurementOwner=ha-harness`,
     `vliteMeasurementExpires=<UTC now + 1 day, ISO-8601>`.
   - Flow: create RG; create ACR (Basic, admin user disabled);
     `az acr build --platform linux/amd64 --timeout 7200` with build args
     for the two provenance values from the repository root context (or use
     `-Image`); create a user-assigned identity and grant it `AcrPull` on the
     ACR, retrying the first job start for role propagation; create the
     environment (Consumption); create one Manual job per tier
     (`--replica-timeout 3600 --replica-retry-limit 0 --parallelism 1
     --replica-completion-count 1`, the identity as registry identity, the
     resource env vars); start each job, poll its execution to a terminal
     state with a bounded timeout, read the console logs
     (`az containerapp job logs show --container <name> --tail 300`
     first, falling back to a Log Analytics query on
     `ContainerAppConsoleLogs_CL` for the execution), reassemble, verify
     the sha256 and byte count, gunzip, check it is a JSON object, and
     write `<OutDir>/MEAS-007-c<tier>.json` plus `<OutDir>/summary.json`
     (tier, cpu, memory, execution name, status, sha256, file name, the
     source revision, dirty flag; never the subscription ID).
   - The az CLI `.cmd` wrapper on Windows mangles JMESPath filters that
     contain `[?...]`; fetch JSON and filter in PowerShell instead.
   - `finally`: unless `-KeepOnFailure` was given and a step failed, run
     `az group delete --yes` and then poll `az group exists` until false
     (bounded); report a cleanup failure loudly and exit non-zero.
   - Never print secrets or the subscription ID; redact it in messages.
   - Provenance: `VLITE_RESOURCE_SOURCE_REVISION` = `-SourceRevision`;
     `VLITE_RESOURCE_SOURCE_DIRTY_PATHS` from `git status --porcelain`
     paths in the encoding the probe expects. Refuse a dirty tree unless
     `-AllowDirty` is passed.
3. Pure, testable functions (exported by dot-sourcing): at least
   `Test-VLiteMeasParameters`, `New-VLiteMeasPlan`,
   `ConvertFrom-VLiteMeasLog` (lines in, bytes out, throws on missing
   BEGIN/END, gaps, duplicates, sha256 or length mismatch, or a FAILED
   marker), and `Assert-VLiteMeasName`.
4. `deploy/azure-container-apps/ha/MEASURE.md`: purpose (owner-approved
   temporary measurement apps, always deleted), prerequisites (`az` login,
   containerapp extension), the exact command, the outputs, cost and
   cleanup behaviour, the tag-based manual cleanup command, and the
   statement that MEAS-001..006 are not implemented yet.

## Tests (test-first)

`deploy/azure-container-apps/ha/measure.test.ps1`, in the `ha/test.ps1`
style, fully offline, covering at least:
- `-Plan` with `-SourceRevision` produces the expected ordered steps,
  names, tags, tiers (cpu and `cpu*2Gi`), env vars and a final group
  delete, without touching Azure or git (stub `Invoke-VLiteMeasAz` and
  `git` to throw if called).
- Refusals: protected names (`asendme-rg`, `vlite-app`, `vlite-env`,
  `vlite-data`), bad `-Id`, unsupported tiers, `MEAS-001`, out-of-range
  records/delta/dimensions and their product, `-OutDir` inside the repo or
  non-empty, a missing subscription without `-Plan`.
- Log reassembly: a round trip of a sample JSON through the same
  gzip+base64+sha256 format the wrapper prints (generate it in the test,
  interleaved with unrelated log lines and timestamps), and refusals for a
  missing END, a gap, a duplicate, a sha256 mismatch and a FAILED marker.
- The Dockerfile copies every input of the `Dockerfile` `source` stage and
  builds the `ha-reader-apply` example with `--features json`.
- With a stubbed `Invoke-VLiteMeasAz` that fails mid-run, the `finally`
  still issues `group delete` (and does not when `-KeepOnFailure`).
