## Required behaviour

1. `State` enum: `Disabled`, `Starting`, `Claiming`, `Recovering`, `Serving`,
   `AuthorityUnavailable`, `Fenced`, `Draining`, `Stopped`. Allowed
   transitions exactly as in the design's state machine; any other
   transition is refused (returns an error, state unchanged). `Fenced`,
   `Draining`, `Stopped` are latched: nothing returns to `Serving`.
2. `WriterFence` (cheaply cloneable, `Arc` inside, `Send + Sync`) holding the
   `AuthorityStore`, the `Claim`, the latched state, a stop signal (e.g. a
   `tokio::sync::watch` or `std::sync` condvar/flag observable by the binary),
   and MEAS-006 counters.
3. `Disabled` fence (HA off): every gate is a no-op `Ok`, never reads the
   store, readiness unaffected. This is the single-ACA default and must cost
   nothing.
4. `admit_mutation() -> Result<(), ApiError>`: pre-enqueue local gate. Refuse
   with 503 `writer_authority_unavailable` (no mutation) unless `Serving`.
5. `verify_before_commit()`: fresh, **uncached** `verify_writer` (OD-002).
   Failure → 503 `writer_authority_unavailable`, no mutation; a `Fenced`
   result also latches.
6. `verify_before_ack()`: fresh uncached `verify_writer` after a local
   commit. Success → `Ok`. Any failure → 502 `write_outcome_unknown` via
   `gateway::ambiguous_write()`, never a success; `Fenced` latches,
   `Unavailable` moves to `AuthorityUnavailable` and marks an uncertain
   commit so the fence can no longer return to `Serving` (drain and stop
   instead).
7. Latching `Fenced` atomically: closes mutation admission, makes every later
   `verify_before_ack` fail, makes `ready()` false, and signals stop. Also
   latch on authority regression (lower epoch), disappearance (`Missing`) or
   `Invalid` — terminal.
8. Transient `Unavailable` while `Serving` with no uncertain commit →
   `AuthorityUnavailable`: acks and readiness blocked immediately; a later
   successful verify with the same E/ID returns to `Serving`.
9. `ready() -> bool` and `state()`; `begin_drain()`, `stopped()` for the
   terminal path; `exit_code()` → `Some(1)` once fenced/stopped by authority
   (the binary's failure convention), `None` otherwise.
10. Events (no tokens, data or raw bodies; sanitize writer id to a short
    prefix): `writer_fenced` (local E, observed E, reason),
    `writer_drain_timeout`, `writer_stopped`.
11. MEAS-006: count authority GETs issued by the fence and record
    `verify_writer` latency into a bounded in-memory sample; expose
    `measurements() -> {count, p50, p95, max}` (durations). No sleeps.

## Tests (test-first, `#[cfg(test)] mod tests` in `writer_fence.rs`)

Use the fake `Memory` store and fault hooks; deterministic barriers
(`std::sync::Barrier`/channels), never sleeps. At least:
`writer_fence_disabled_is_free` (no store reads, always ready),
`writer_fenced_after_local_commit_is_ambiguous` (bump E between
`verify_before_commit` and `verify_before_ack` → 502 `write_outcome_unknown`),
`writer_fenced_latch_stops_queue_and_readiness` (after latch:
`admit_mutation` 503, `ready()` false, stop signalled, state never returns
to `Serving`), `writer_fenced_on_different_writer_id`,
`writer_fence_regression_or_missing_is_terminal`,
`writer_fence_transient_unavailable_recovers_without_uncertain_commit`,
`writer_fence_uncertain_commit_cannot_resume`,
`writer_fence_precommit_failure_is_503_without_mutation`,
`writer_fence_exit_code_is_one_when_fenced`,
`writer_fence_counts_gets_and_latency` (count equals verify calls; p50 <=
p95 <= max), `writer_fence_refuses_illegal_transitions`.
