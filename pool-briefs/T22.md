## Scope

Today nothing creates or claims `<prefix>authority.json` at runtime, so the
T17 serving fence can never be enabled. Add the smallest operator-explicit
path. No automatic election, no automatic re-claim, no new crate.

1. `vlite-server authority init|show --target-file <json>
   [--shared-key-file <path>]`; `init` also requires `--installation-id <id>
   --scope-id <id> --lineage <16 lowercase hex>` (ids follow
   `Record::validate`; the lineage is the one in serve-status). `init` calls
   `create` (exists → `writer_authority_exists`); `show` is read-only. Both
   print JSON on stdout: schema, ids, lineage, epoch, revision, phase,
   `writer_present` (bool, never the full writer id), base/head. Wire it like
   `failover`: a blocking `pub fn authority_command(args: &[OsString]) ->
   Result<Value, String>` re-exported from `server.rs` next to
   `failover_command` (`#[doc(hidden)]` is acceptable if `failover_command`
   has no `site/api.html` row; check `python tests/api_reference.py`), a
   usage constant, `gateway_tool` dispatch, and add `authority` to the
   "./ prefix" note in `USAGE`.
2. Writer startup: `--authority-target-file <json>` with optional
   `--authority-shared-key-file <path>` (no environment variables). Before
   the listener binds: connect exactly like `failover`, `read()`, then:
   - Missing/Unavailable/Invalid/Unresolved → fail closed with the
     `ApiError` code of that error (e.g. `writer_authority_missing`).
   - record lineage ≠ the database's v4 lineage, or the database has no
     lineage → `writer_authority_lineage_mismatch`.
   - `writer_id` already set → `writer_authority_claimed` (the operator runs
     `failover report|execute`, which bumps the epoch and clears the writer;
     a restart is an operator failover in v1).
   - `base` is `Some` → `writer_authority_base_unverified` (checking the
     local database against an archived head needs the HA archive binding,
     which is out of scope; fail closed rather than serve stale state).
   - else `claim(now)`; CAS conflict → `writer_authority_conflict`. Build
     `WriterFence::new(store, claim)`, transition Claiming → Recovering →
     Serving, call `with_writer_fence` right after `with_serve_mode`. Log one
     `writer_authority_claimed` event (epoch, 8-char writer prefix; never a
     key). Do the blocking I/O off the async runtime.
3. Periodic recheck (PRD F1 "short periodic recheck"):
   `--authority-recheck-ms <500..60000>` (default 5000, only with
   `--authority-target-file`). A task calls `verify_before_commit` through
   `spawn_blocking` every interval while not Fenced/Draining/Stopped, so an
   idle fenced writer self-stops (existing stop signal → drain → exit code 1)
   and an AuthorityUnavailable writer recovers without a write.
4. Option validation: the authority options need `--serve-mode writer`;
   refuse them with `--grpc-bind` (no response barrier) and with
   `--durability none`. `--gateway-trust-file` stays allowed.

Existing deployments (no authority options) must be unchanged in behaviour:
fence stays Disabled, no store access, no new task.
