## Required behaviour

1. **Versioned HA variants.** HA manifest / index / checkpoint entries are
   explicitly distinguishable (schema or version marker) and carry `writer_id`,
   `epoch`, authority scope and lineage; each HA Index records the prior head's
   digest. **Legacy (authority-off) serialization is byte-identical** to today —
   do not add optional keys to legacy objects. An old binary must refuse an HA
   object (existing `deny_unknown_fields` gives this; keep it).
2. **HA chain.** A domain-separated HA `chain` encoding over epoch, writer ID,
   base sequence, end sequence and segment hash. Keep `check_bundle` and its
   policy/memory checks unchanged for both variants. `Index::check` (and
   `read_index`/`open_archive` parsing) validates HA entries: chain, entry
   epoch/writer consistent with the manifest, epoch never decreasing across
   entries. Legacy validation unchanged.
3. **`append_checkpoint_ha`:** (a) `verify_writer(claim)` and require
   `phase == serving` and the authority head equal to this archive's current
   head (set, sequence, chain); (b) prepare segment, recovery bundle and next HA
   Index with the same epoch/writer; upload all create-only with exact
   hash/length readback (reuse `upload`), keep `authorize()` shutdown checks;
   (c) `advance_head(claim, &observed, HeadRef{..index_sha256: Some(..)})` — this
   is the commit point; do **not** update the legacy `archive.json` pointer as
   the commit in HA mode; (d) map results: `Fenced` → typed fenced error,
   archive progress not advanced, no retry under the successor's ETag;
   `HeadMoved` with same writer/epoch → typed "rebase required" error carrying
   the observed head (no overwrite); `advance_head`'s Unknown handling already
   reads back — accept only exact readback; anything else is unresolved and
   does not advance progress.
4. **`publish_ha` (first baseline / new baseline):** existing set
   publish/finish prepares a Published set; it becomes HA-authoritative only
   through `advance_head` (phase `recovering` → `serving` for the first baseline,
   `serving` for later baselines by the same writer/epoch). In HA mode never
   select a set by "newest Published" alone: provide a helper that resolves the
   authoritative set from the authority head, and make sure an orphan Published
   set (published but head CAS lost/fenced) is not returned.
5. Errors use existing `ApiError` conventions; reuse T1's `AuthorityError` →
   `ApiError` mapping (503/409/502 codes) rather than inventing new codes,
   except a new `writer_rebase_required` (409) if you need it — document it in
   the commit message.
