# Task T3 — HA EPIC-007: tenant export/import/migration design (report)

Repository: mahpate/Vlite (Rust). You work in a fresh clone at the plan base.
This is a **design/investigation task. Do not change any source, test or doc
file.** Your only output is the report file named below.

## Goal

Produce an implementation-ready design for EPIC-007 of
`docs/projects/feature-aca-ha/feature-aca-ha.prd.md` (section "EPIC-007:
Per-tenant deployment mapping and migration", ~lines 858-865): move one tenant
from the shared database (a namespace `t<id>__*` inside one VLite database) to
its own dedicated writer deployment, and roll back by flipping the tenant
directory record until the source is released.

Requirements to satisfy (read them in the PRD): G-5 (line ~32), FR-015 (~314:
opt-in, reversible until source release, credentials re-issued rekey-only),
TEST-013 (~396), AC-013 (~429), GATE-006 (~467), OD-011 (~505: support both
`shared-pool` and `dedicated`; shared-pool stays the default).

Tasks to design: ITEM-027 (tenant export via existing log/restore primitives),
ITEM-028 (carry grants, memory bindings with reserved prefixes/orphans, users;
re-issue credentials), ITEM-029 (verification, directory flip, rollback, TEST-013).

## Report must contain

1. Inventory: exactly which on-disk/in-database state belongs to a tenant
   (collections, graph data if namespaced, memory records/evidence, bindings,
   reserved prefixes and orphan reservations, users, grants, credentials,
   webhooks, imports, quotas) with file:line evidence, and which is global and
   must NOT move.
2. Export format and command surface (reuse existing primitives; no new crates),
   including how namespace prefixes are stripped/rewritten for the dedicated
   target and how integrity is verified (hashes/counts).
3. Import into a fresh dedicated database; credential re-issue (rekey-only:
   new secrets, same grants/scopes), user and binding carry-over, orphan handling.
4. Cut-over sequence with the gateway directory flip (`shared-pool` → `dedicated`),
   write freeze/drain on the source, `lineage`/`epoch`/`binding_generation`
   values for the new record, and how in-flight requests behave.
5. Rollback until "source release", and the definition/command of source release.
6. Test plan mapping to TEST-013/AC-013 (unit + integration file names, what
   each asserts), and the HA-off/no-regression argument for single-ACA users.
7. Risks/open decisions with a recommended default for each (the owner has
   delegated approvals to best judgement; no new dependencies such as Key Vault).
8. A proposed split into parallel-safe implementation tasks with exclusive
   file ownership and test-first order.

Cite file:line for every claim about current code. Keep it under ~900 lines.
