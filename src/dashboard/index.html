    05 / PERFORMANCE
Index maintenance

    
Index readiness not checked

    
    
Builds HNSW for the active collection from its committed records, with the metric, HNSW settings and (when supported) quantization selected in the Search playground. Blocks the single owner; schedule outside latency-sensitive traffic. Reopen/overflow loses readiness.

    
    

    
HNSW configuration and background maintenance

      
m trades graph connectivity for memory; ef_construction trades build effort for quality. Use the same configuration for building and ready-only search. A seed makes builds reproducible for fixed data. Snapshot limits do not cap total process memory.

      
      
      
      
      
      
      
      
      
      

      
      
Connect to see which collection maintenance applies to.

      
      
      
      
Policy is process-local and resets on restart. A tick explicitly polls/publishes or starts a matching job for the active collection; the optional automatic scheduler (Operations) is off by default. Observe does not publish. Cancellation is cooperative.

      

    

    
Index memory and measured quality (active collection)

      
Memory shows the byte counts of the listed index components only, not total process memory. Quality samples live records, compares the ready index against exact search for those queries and reports recall@k; it does not build or change the index.

    DATA WORKFLOWS
Import, export and guided demo

    
Imports are limited to 100 records / 4 MiB, committed in atomic batches of 20. An entire import is not atomic. Existing IDs are replaced only after confirmation. No automatic retries.

    
  1. Connect to a test database.
  2. Preview a demo or import file.
  3. Confirm the writes, browse the records, then search.

    
    
    
Each record: id (string), vector (JSON array), optional payload_base64 and metadata (typed object). CSV headers: id,vector,payload_base64,metadata; quote JSON cells.

    
    

    
    
    
Page exports include full records (up to 100), fetched individually; not a point-in-time database backup. Use Operations for consistent backups.

  

  

    LARGE IMPORTS
Resumable import

    
Splits a JSON array, NDJSON/JSONL or CSV file into numbered chunks for the active collection. Each chunk commits atomically and exactly once; the whole import is not atomic. Committed chunks are kept if you stop, abort or close the page. Nothing is retried automatically: after an unknown outcome, Resume reads the durable job status first and replays only the last committed chunk to prove it is the same file.

    SERVER OPERATIONS
Health and administration

    
    
    

    

      
Connect to discover server administration features. These operations require an admin credential.

      
Credentials and audit

      
      
      
      
Change configured secret files offline first. Reload validates both before swapping. Admin token rotation requires reconnecting with the new token. Environment tokens require restart. Revocation is in-memory; empty its configured file to persist it.

      

      
      
Last 256 process-local requests only; not a durable compliance log. No credentials or record contents.

      

      
Backup and staged restore

      
      
      
      
      
      
      
Copies can block the owner and consume disk. Restore never replaces the live file. Selection takes effect only after an operator restarts the API with the same admin directory. Original data remains untouched; the selection persists. Do not remove the selected copy.

      
      
      
Verify checks the backup file's integrity (CRC) and records the result in its manifest. A drill restores it to a scratch file, opens and validates it, compares collections/counts with the manifest, runs a self-match query, then deletes the scratch file; the active database and restart selection are never touched.

      

      
Scheduled backups

      
Off by default. Runtime changes are memory-only: the server's environment configuration applies again after restart. Retention is a separate opt-in: when enabled it deletes generated backups ranked beyond retain_last (and, if retain_days is set, older than it), but never the newest verified backup, restored copies, drill scratch files or the next-startup selection.

      
      
      
      
      

      
Automatic index maintenance

      
Off by default and memory-only (resets to the environment configuration on restart). When enabled, each tick takes at most one action for one collection (round-robin), starts at most one background rebuild, skips and counts busy ticks, and never runs a synchronous build. Thresholds are the global maintenance policy above plus the stale ratio and optional low-recall trigger here.

    ACCESS CONTROL
Scoped credentials

    
Bootstrap admin only. A scoped credential is limited to named collections (bound to those collections' identities; a dropped and recreated collection or another database fails closed) and selected operations, and always expires. The secret is returned once: it is shown masked here, kept only in this page's memory, never placed in the request inspector, history, exports or browser storage, and cleared on Disconnect.
