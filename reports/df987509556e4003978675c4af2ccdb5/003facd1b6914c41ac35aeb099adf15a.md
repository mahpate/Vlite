## Failure analysis

### F1: OpenAPI baseline contract regressed in the HA change interval

**Failing test:** `graph_surface_parity::reg008_served_openapi_matches_baseline_except_approved_additions`.

Trimmed original failure:

```text
thread 'reg008_served_openapi_matches_baseline_except_approved_additions'
panicked at tests\graph_surface_parity.rs:926:35:
served /openapi.json differs from the baseline capture beyond the approved additions
(first difference at line 68 after removing them)
test result: FAILED. 6 passed; 1 failed; 0 ignored
error: test failed, to rerun pass `-p vlite --test graph_surface_parity`
```

The single-test rerun returned the same panic and exit 101:

```text
test result: FAILED. 0 passed; 1 failed; 0 ignored; 6 filtered out
```

At baseline `d9c3d64da1dd54a8f2036f473b98143bd7b98690`, the same named test passed:

```text
test reg008_served_openapi_matches_baseline_except_approved_additions ... ok
test result: ok. 1 passed; 0 failed; 0 ignored; 6 filtered out
```

**Attribution:** caused by the reviewed HA branch interval, not pre-existing at the requested baseline and not explained by a Windows-only startup failure. Both executions successfully obtained HTTP 200 from `/openapi.json`; the assertion rejects document drift afterward.

Static inspection supplies the likely exact cause:

1. `git log d9c3d64d..e995c536 -- src\openapi.json` identifies commit **`bfaf5a2`**, `EPIC-002: serve modes (standalone/writer/reader), reader admission, drain and serve-status`.
2. `git diff d9c3d64d e995c536 -- src\openapi.json` contains exactly one added document line: the `/v1/admin/serve-status` operation, between metrics summary and slow-query diagnostics. See [head OpenAPI, line 94](https://github.com/mahpate/Vlite/blob/e995c536573d11388f676f2c3724118992472753/src/openapi.json#L94).
3. The parity test's [approved-additions policy](https://github.com/mahpate/Vlite/blob/e995c536573d11388f676f2c3724118992472753/tests/graph_surface_parity.rs#L141-L157) intentionally accepts only reviewed byte-exact additions; its list contains no `serve-status` entry.
4. The [failing comparison](https://github.com/mahpate/Vlite/blob/e995c536573d11388f676f2c3724118992472753/tests/graph_surface_parity.rs#L917-L927) filters graph-specific paths, then compares the remaining served document against the edited baseline and allowlist. It does not filter this new admin operation.
5. `tests\graph_surface_parity.rs` is unchanged between the two tested revisions.

This is specifically an **HA serve-mode/OpenAPI contract-maintenance regression** within the supplied gateway-head range. The evidence does not implicate the later per-phase gateway timeout or streaming implementation, and does not demonstrate incorrect runtime behavior of `/v1/admin/serve-status`.

**Recommendation:** review the intentional admin operation and add its exact expected line to the narrowly scoped approved-additions contract. Prefer that to dropping the parity assertion or broadly excluding admin paths, which would weaken unrelated schema-drift protection. No such change was made in this report-only task.
