Quick start

Open a file in your process. No server is needed.

from vlite_embedded import NativeLibrary

meta = {"category": {"type": "string", "value": "docs"}}
native = NativeLibrary()
with native.create("docs.vlite", dimensions=3) as db:
    db.put("1", [1.0, 0.0, 0.0], metadata=meta)
    db.batch([{"op": "put", "id": "2", "vector": [0.0, 1.0, 0.0]}])
    print(db.search([0.9, 0.1, 0.0], k=5,
                    filter=[{"op": "eq", "field": "category", "value": meta["category"]}]))
import { NativeLibrary } from "@vlite/embedded";

const native = new NativeLibrary();
const db = await native.create("docs.vlite", 3);
await db.put("1", [1, 0, 0]);
console.log(await db.search([0.9, 0.1, 0], 5));
await db.close();
await native.close();
use vlite::Database;

let mut db = Database::create("docs.vlite", 3)?;
db.put(1, &[1.0, 0.0, 0.0], b"hello")?;
for hit in db.search(&[0.9, 0.1, 0.0], 5)? {
    println!("{} {}", hit.id, hit.distance);
}
db.close()?;

Conventions

  • Record IDs are unsigned 64-bit integers. SDKs and JSON pass them as decimal strings.
  • Lower distance means nearer, for every metric.
  • A write survives a process crash when the call returns; by default it is synced within 60 s, or before returning with full durability. Batches are all-or-nothing.
  • Metadata values are typed. A filter is an AND of up to 64 conditions.
  • Errors carry a stable, machine-readable code.
MetricDistanceHNSW
squared_l2 (default)Σ (a − b)²Yes

Shared types

The SDKs, the C ABI, REST and MCP use these JSON shapes. gRPC uses the same values in protobuf messages.

Metadata values

Metadata is a map of up to 64 fields, at most 64 KiB in total. Every value is tagged with its type, and filters only match values of the same type.

TypeJSON form
string{"type": "string", "value": "docs"}
integer{"type": "integer", "value": "42"}, a decimal string so 64-bit values survive JSON
float{"type": "float", "value": 0.5}
boolean{"type": "boolean", "value": true}
geopoint{"type": "geopoint", "value": {"latitude": 47.6, "longitude": -122.3}}; needs format 5

Filters

A filter is a list of up to 64 conditions. A record matches only when every condition matches.

ConditionMatches
{"op": "eq", "field": "category", "value": {...}}The field equals the typed value.
{"op": "range", "field": "year", "min": {...}, "max": {...}}The field lies within the inclusive bounds. Bounds are integers or floats of the field's type; give at least one.
{"op": "georadius", "field": "place", "latitude": 47.6, "longitude": -122.3, "radius_meters": 5000}The geopoint lies within the radius.

Revisions

Every write gives the record a new revision, returned as a decimal string. To make a write conditional, pass the revision you expect, or "absent" to require that the record does not exist. A mismatch fails and writes nothing. Revisions survive reopening, but change when a file is compacted, upgraded or restored.

File formats

FormatAdds
3 (default)Records with typed metadata, exact search and in-memory HNSW indexes
4Named collections, resumable imports and the change feed
5Record expiry, metadata-only updates, geopoints, named and sparse vectors, encryption, commit timestamps and graph-enabled files

Each format includes everything before it. The format is chosen when the file is created, and opening a file never upgrades it. Asking for encryption, commit timestamps or a graph creates a format 5 file. An older reader rejects a newer format rather than guessing.

C ABI

The C library (vlite_ffi, header bindings/c/vlite.h) is the layer the Python and Node.js SDKs load. Release archives include it, built with graph support. Most work goes through one function, vlite_execute: send a JSON request with an op field and read back a JSON response.

{"op":"create","path":"documents.vlite","dimensions":3}
{"ok":true,"result":{"handle":"1"}}
{"ok":false,"error":{"code":"invalid_handle","message":"Unknown or closed handle"}}

Check that vlite_abi_version() returns 1. Pass handle 0 to create and open, then use the returned handle, a decimal string, for later calls. Handles belong to the loaded library and process. Free every response exactly once with vlite_response_free. Requests are UTF-8 JSON of at most 8 MiB, and unknown fields are errors. IDs, revisions and integer metadata values are decimal strings. Calls are synchronous and run one at a time.

REST

Run vlite-server or the Docker image. Send an API key as a bearer token.

curl -s -X POST localhost:8080/v1/search \
  -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"vector":[0.9,0.1,0],"k":5}'

Routes are grouped by area. The Access column shows who can call each route:

  • Public needs no credentials.
  • Any key accepts any valid credential or signed-in account.
  • A scope name, such as search, means a scoped vlk_ credential needs that scope for the collection or graph. “on *” means the credential must be bound to every collection. Credentials bound to a tenant cannot call those routes, except to create collections.
  • Admin needs the admin token or an admin account.

The admin token can call every route. The read-only token can call any GET route outside /v1/admin/, plus the search and graph-read routes. Signed-in dashboard accounts get the access of their role. Routes without a collection name use the default collection, so a scoped credential must cover default to call them. Errors are JSON: {"error": {"code": "...", "message": "..."}}.

gRPC

The gRPC service vlite.v1.VLite serves the same database as REST, with the same credentials, scopes and limits. It is off until you start vlite-server with --grpc-bind ADDR. Release binaries and the Docker image include it; source builds need the grpc Cargo feature. Add --grpc-tls-cert and --grpc-tls-key for TLS, and --grpc-tls-client-ca to require client certificates. The contract is proto/vlite/v1/vlite.proto. See the gRPC guide.

Send the credential as authorization: Bearer <token> metadata. Errors carry the REST error message, and the vlite-error-code trailer carries the REST error code. An empty collection field means the default collection. Requests are capped at 8 MiB and responses at 16 MiB. Graphs, automatic search planning, HNSW index builds and maintenance, backups, credentials, tenants, accounts and diagnostics are REST-only.

MCP

vlite-mcp lets AI assistants use a VLite file through the Model Context Protocol. The assistant's host starts it over stdio: vlite-mcp --db documents.vlite. It is read-only by default; --writable adds the write tools. For an encrypted file, pass --encryption-key-file PATH or set VLITE_ENCRYPTION_KEY or VLITE_ENCRYPTION_KEY_HEX. To work through a running server instead, use vlite-mcp --server URL --token-env VAR. Graph tools appear only for graph-enabled files. Release archives include vlite-mcp. See the MCP guide.
