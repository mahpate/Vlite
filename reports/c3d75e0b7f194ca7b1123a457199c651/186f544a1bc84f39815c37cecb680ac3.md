## 1. Decision and authoritative contract

**Do not enable takeover.** At 19dfffe, `ActuatorStopped` has only a private attempt string and a `#[cfg(test)]` constructor. There is no production producer, host-exclusion verifier, or recovery integration accepting such a proof. A Blob CAS winner cannot stop a process that already received permission to dispatch.

The PRD requires two distinct facts before superseding or destructive work: completion/reconciliation of prior cloud actions **and** exclusion of the former actuator. It explicitly rejects a wall-clock lease as proof (`docs\projects\feature-aca-ha\design-tenant-provisioning\design-tenant-provisioning.prd.md:150-158`, section 3.3). OD-002 chooses a separate privileged VLite worker using existing Blob/admin state, not another coordination service. It identifies missing terminal execution evidence, role/token propagation bounds, and in-flight ARM completion bounds (`...prd.md:1166-1169`). Those are requirements and recorded gaps, not demonstrated platform guarantees.

The earlier PRD narrative saying there is no production ARM adapter (`...prd.md:1174`) is superseded by the later implementation note (`...prd.md:1288-1289`) and actual source: `ArmClient` exists and is wired behind gates. This does not resolve OD-002. The production worker still lacks qualification/quota/budget proofs and refuses before claiming or building the adapter (`worker.rs:35-62,178-227`; `admin.rs:1146-1159`).

**Scope distinction:** Stopping a tenant container app, stopping the ACA **Job execution that runs the privileged worker**, excluding its credentials/host, and finishing an ARM resource operation are different propositions. None implies the others. This investigation is about the worker actuator, not a writer-fence, stopped reader, or reader-pin proof.

## 2. Exact identity that evidence must bind

The following is the existing identity, not an invented execution identifier:

| Component | Fact at 19dfffe and evidence |
|---|---|
| Operation namespace | `Operations` uses a configured store/prefix; operation files are under that prefix and operation ID. The operation ID is the first 32 hex characters of SHA-256 over `SCHEMA`, NUL, principal, NUL, idempotency key. Schema is `vlite.tenant-operation/1`. It is not an ACA execution ID (`src\server\tenant_provisioning.rs:39,486-499,531-532`). |
| Immutable operation | `Intent` stores operation ID, principal, key digest, payload/request digest, tenant ID, retained content digests, and creation time. Acceptance validates exact retained content and preserves the accepted request on an identical retry (`tenant_provisioning.rs:230-245,537-635`). No raw idempotency key is needed in an exclusion report. |
| Worker invocation | The CLI generates `worker-` plus 32 random hex characters from 16 random bytes on each invocation. It does not accept an ACA execution ID as this attempt identity (`worker.rs:66-71`; `admin.rs:1223-1231`). Fresh random generation reduces collision risk; it is not a verified host/replica binding. |
| Claim | `Journal` stores operation ID, generation, current `attempt`, steps, and `closed`. A conditional store write changes the claim. Same-attempt claims are idempotent; a different holder requires the proof's attempt to equal the current holder (`tenant_provisioning.rs:303-313,719-773`). |
| Side effect | A step identifies sequence, dispatching attempt, resource, action name, request digest, destructive flag, uncertain/settled outcome, and optional persisted ARM handle (`tenant_provisioning.rs:270-299,775-858`). Driver action digests include the tenant owner, exact resource, action, and action detail (`aca.rs:859-875`). |
| Resource ownership | ARM call owner is `vlite-tenant:<tenant_id>`, not operation ID, attempt ID, or Job execution identity (`aca.rs:47-48,859-861`). An owner tag is therefore not a worker-exclusion token. |
| ARM handle | The versioned envelope stores API version, operation/fallback, owner, start time, and absolute observation deadline; it does **not** carry ACA Job execution, replica, or worker attempt (`arm.rs:634-646,771-803`). The journal provides the step-to-attempt association. |

**Minimum recommended proof binding, not an existing schema:** full pinned binary/image identity; control store/object namespace and journal prefix; immutable intent bytes/digest and operation/tenant IDs; prior attempt; observed claim generation and journal ETag/version; relevant action sequences/digests/handles; ACA Job resource identity plus immutable execution and replica/container/process incarnations; worker managed-identity resource/client/principal identifiers and effective permission scope; and durable stop/exclusion evidence with its provenance and validity conditions.

The generation/ETag binding is necessary to detect a stale evidence snapshot; it must not substitute for actuator fencing. The current `claim` accepts no expected generation or operation-bound stop certificate. A future verifier must re-read the holder and revalidate evidence during CAS contention. If another claimant wins, evidence for the former holder cannot authorize replacing the new one.

**Existing linkage gap:** the worker audit contains operation ID, attempt, outcome, and optional error code, but no ACA execution/replica identity (`admin.rs:1035-1080`). The Job selects an operation at runtime by default; its command carries neither a fixed operation nor a pre-bound attempt (`templates.ps1:835-840`). The local audit is in EmptyDir and lasts one execution; the Blob journal is durable (`templates.ps1:731-734`). Consequently, a vanished execution or missing local log can make historical attempt-to-host attribution impossible. Do not infer it from approximate start time, image, Job name, or tenant tag.

## 3. Complete exclusion evidence required

These are necessary evidence classes for a candidate protocol, **not evidence collected here and not an assertion that ACA can supply them**.

1. **Complete actor attribution and inventory.** Identify every execution/replica/process capable of acting as the prior attempt, including overlapping manual Job starts, replica/container restarts, descendants, and copied/reused attempt strings. Include every host holding the worker identity, not merely configured serving apps. Establish the actual deployed image/template, identity assignments, retry behavior, execution history, pagination completeness, and freshness/provenance of observations. A Job name or a single observed replica is insufficient.
2. **A durable, nonreactivatable exclusion boundary.** Establish that those old incarnations are terminal, cannot resume a paused post-journal dispatch, cannot spawn or be restarted, and cannot reacquire the worker identity. Prevent concurrent start, update, identity attachment, recreation, and other reactivation paths across the proof-to-takeover interval and thereafter for the old authority. Define who owns this exclusion and how its observation is serialized with recovery using existing state. An accepted stop request or one terminal-status sample is not that boundary.
3. **Credential and effective-permission closure.** Inventory existing role assignments/inherited permissions and all credential-acquisition paths for the excluded hosts. Supply authoritative bounds/evidence for revocation, platform/token caches, token acceptance, and reacquisition prevention. Do not invent an expiry/revocation delay. The Rust five-minute refresh threshold is a client cache policy, not an Azure revocation bound (`cloud_backup\azure.rs:294-345`). Exclude old access even if a successor's identity or grants are enabled.
4. **Closure of already-issued requests and provider work.** Account for requests that crossed the transport boundary before exclusion, including requests whose responses or handle persistence were lost. Bind known handles to exact steps; obtain terminal operation evidence and exact resource/configuration/inventory reconciliation. A killed client, expired observation budget, or revoked identity does not retract accepted server-side work. Include multi-revision Stop requests and all request classes, including reads/polls, when claiming the literal property that the old actuator cannot still issue ARM requests.
5. **Durable provenance and consumption.** Retain nonsecret evidence references/digests, exact subject identities, source API/schema, observation boundaries, demonstrated bounds, unknowns, and the recovery decision in existing durable history. Evidence must survive worker and recovery-owner crashes. Revalidate at claim CAS; never synthesize success from stale local output or a missing record. Preserve prior uncertain steps: a stop proof permits ownership transfer only, not automatic settlement or terminal release.

For the literal “cannot still issue ARM requests” claim, authorization denial alone is insufficient: a live process can still send a denied request and may retain permitted read access. A weaker “cannot perform an accepted mutation” claim requires its own accepted gate definition and enforcement evidence; it must **not** be silently substituted for the requested exclusion property.

### Concurrency, ambiguous stop, and reactivation

- **Parallelism is not global serialization.** The template sets manual trigger, parallelism 1, one completion, and retry limit 0 (`templates.ps1:820-823`). Static/template checks show rendered configuration only. They do not demonstrate mutual exclusion across independent Job executions or platform restart behavior. The admin-directory lock is local to each EmptyDir; it is not cross-execution exclusion (`admin.rs:1163-1166`; `templates.ps1:832,839`).
- **Paused-after-record is the critical counterexample.** `Driver::dispatch` obtains `Decision::Dispatch` from the Blob journal and then calls `arm.begin` without a second claim check (`aca.rs:915-928`). A fabricated proof lets B change the journal while A is paused at that boundary; A can then issue ARM requests. A second cooperative check alone would still leave a check/send race. The adapter receives a resource/owner/verb, not an attempt-fencing authority (`aca.rs:96-102,148-160`).
- **Restarts get fresh attempts in the ordinary CLI.** A restarted invocation cannot claim over the recorded predecessor without proof. This fails safely but does not prove the predecessor stopped. Same-attempt reuse is accepted at the claim layer; it is not authenticated host identity (`worker.rs:66-71`; `tenant_provisioning.rs:761-766`). Existing same-attempt overlap fixtures exercise step reconciliation, not complete host exclusion.
- **Ambiguous stopping stays unknown.** Timeout, lost stop response, 404 on the wrong object, incomplete execution/replica enumeration, unavailable identity history, or stale terminal observation cannot produce proof. A requested stop is not confirmed exclusion. Resource recreation under the same name or attachment of the same identity creates a new incarnation requiring separate attribution.
- **A shared worker identity makes revocation broad.** One dedicated worker identity can be held by multiple executions even though configured serving roles differ. Revoking it may stop unrelated work; reenabling it for B may revive A's effective access unless A's host/incarnation is irreversibly excluded. Template checks compare configured role identity IDs and distinguish client IDs, but do not verify the actual client-ID-to-resource binding or effective cloud RBAC (`templates.ps1:757-799`; `docs\HA-ACA.md:994-995`).
- **Target-app inactivity is not actuator inactivity.** `Verb::Stop` deactivates tenant app revisions; it does not stop ACA Job executions or revoke their credentials (`aca.rs:80-94`; `arm.rs:354-382`). Complete inactive target revisions can later change if another actuator can still act. The historical `arm19a` app probe explicitly did not run the worker/Job identity and did not prove OD-002 (`...prd.md:1128,1155`).

## 5. Concrete safe refusal conditions

Use existing refusal gates and retain claims/reservations; additional scenarios below describe required verifier behavior, not implemented new error codes.

| Condition | Safe decision |
|---|---|
| Recorded holder differs; stop proof missing, wrong subject, fabricated, stale, operation-unbound, or not production-verifiable | `actuator_fence_unproven`; no claim replacement or ARM dispatch. Check again after any claim race. |
| Execution/replica/process identity missing; actor enumeration incomplete; unknown restart or concurrent Job; unverified actual identity binding | No `ActuatorStopped`. Refuse exclusion even if one execution reports terminal. |
| Stop acknowledgement without terminal host exclusion, unknown stop result, host can resume/restart, or start/update/recreation/reactivation remains possible | No proof. Keep the prior claim and recovery blocker; do not release on silence or elapsed time. |
| Revocation/token propagation bound absent; tokens may still be used or reacquired; enabling successor grants can restore old access | No proof. No arbitrary waiting interval or identity-rotation assumption. |
| Outstanding accepted request, lost response/handle, running/unknown/expired operation, or response crossing original deadline | Retain uncertain step; `cloud_outcome_unknown` where the driver exposes it. No new conflicting/destructive call. A recovered handle must be independently authentic and exactly correlated. |
| Different requested action while any prior action is uncertain | `prior_action_unknown`; reconcile the exact recorded action instead (`tenant_provisioning.rs:795-806`). |
| Target owner/configuration differs, reused name, revision overlap, or incomplete/malformed revision inventory | Ownership/readback refusal or unresolved outcome, including `revision_inventory_incomplete`/`revision_overlap` where applicable; never call that an actuator proof (`aca.rs:1042-1078`). |
| Reservation lost/cancelled/sealed, unsupported profile, missing retained inputs, or missing qualification/quota/budget | Preserve `operation_not_provisionable`, `profile_unsupported`, input-validation refusals, `qualification_missing`, `quota_unproven`, `quota_exceeded`, `budget_unapproved`. An exclusion proof cannot waive them (`worker.rs:188-227`; `...prd.md:1171,1289`). |

6. **Stop at the platform evidence boundary in this assignment.** Actual ACA stop/restart/concurrent-execution semantics, identity binding, revocation/token-cache behavior, and provider completion bounds require separately authorized isolated platform evidence. No such actions are permitted here; do not deploy or collect them. An eventual campaign must include concurrent starts, platform restarts, ambiguous stop, delayed requests, and attempted reactivation with a successor present, and retain all unknowns. Negative samples alone cannot establish an undocumented universal bound.
7. **Accept proof only after both obligations close.** A future reviewer must verify authoritative host/credential exclusion and independently complete exact prior-action reconciliation, then verify proof binding/CAS-race behavior and crash recovery. Keep all existing qualification, quota, budget, profile, pin, routing, and HA gates unchanged. If the evidence remains ambiguous, the only acceptable outcome is blocked takeover.

**Design trade-off:** retaining one dedicated worker identity and the existing Blob journal is the smallest owner-aligned shape, but exclusion can have a broad availability cost across executions. Per-attempt credentials would complicate identity lifecycle, permission propagation, and old-token exclusion and are not proven or recommended as an automatic workaround. Cooperative locks, more Blob checks, or short leases improve coordination but cannot establish the post-check transport guarantee. Prefer a verified irreversible execution/authority boundary; if unavailable, refuse rather than add services, dependencies, or fabricated timing assumptions.

## 8. Uncertainties and recommendation

Unknown at 19dfffe and unverified here: whether ACA provides sufficient immutable execution/replica identities and authoritative termination semantics; whether enumeration can be complete under concurrent starts; whether a terminated execution can reactivate or retain descendant activity; actual worker identity attachment and role scopes; cached-token/revocation/renewal behavior; upper bounds or terminal correlation for accepted/lost ARM requests; and an enforceable proof-to-takeover boundary under recovery-owner crashes.

The static absence of a production proof path is established; platform feasibility is not. Preserve `ActuatorStopped` as test-only, keep `actuator_fence_unproven` refusal, and retain unknown operations until exact reconciliation. Do not fabricate execution identifiers, terminal evidence, propagation numbers, or provider guarantees. Add no dependencies and relax no gates. The next legitimate deliverable is an owner-reviewed, implementable evidence/exclusion contract using the existing state, not a production takeover enablement.
