## Recommendations, trade-offs and limits

1. **Nonblocking terminology correction:** API `:448-449`, OpenAPI `:104`, its exact parity addition (`tests\graph_surface_parity.rs:606`), and PRD `:274` say the scoped limiter runs "before authentication." In fact `observe` resolves authentication first (`src\server.rs:1371-1380`) and then calls `rate_limit(...).and_then(authorize)` (`:1414-1423`). Change this to **"before route authorization"** while retaining the documented generic 503 exception; update the verbatim parity addition together with OpenAPI. This does not invalidate the substance of the P2-3 fix: administrators bypass the scoped limiter, and denied scoped callers can encounter it before the handler.
2. Keep the two-layer dashboard test design: control wiring plus transport behavior. The interaction test by itself does not execute the real preflight click handler, so it must not be cited alone as killing removal of that handler's option.
3. Keep the isolated observer executable separate: shared-buffer live-grants sweeps demonstrably miss the tested helper-log regression. Its runtime allowlist covers the structured server log buffer and audit surfaces, not arbitrary future raw stderr output or an external logger sink.
4. Preflight remains advisory and a potentially long shared reader; it does not reserve a reload, prevent intervening edits, or remove writer contention. Status is deliberately lock-free with respect to the database/reload and can report a snapshot around concurrent reload. The code, tests and operator instructions preserve these trade-offs.
